# 课文同步

把教师已经编辑并归档的课文安全地同步到 Chronovita 学生端，同时保留旧发布的回滚能力，并明确记录尚未适配的练、问、创、人物和视频。

## 1. 先读前导配置

开始任何网络访问或文件修改前，完整读取项目根目录的 `doc/04-课程同步台账.md`。

该台账是以下信息的唯一事实源：

- 应用仓库与教师内容仓库地址；
- 当前开发分支、内容目录和发布边界；
- 课程、课时、来源 PR 与当前学生标题；
- `课文 / 练 / 问 / 创 / 人物 / 视频` 的同步状态。

台账缺失，或“前导配置”没有明确两个仓库时，先依据用户确认和本地 Git 事实补齐台账，再读取 PR。不要把仓库地址、课程总表或状态流水复制进本 Skill。

## 2. 确定同步对象

1. 使用台账配置的教师内容仓库读取用户指定 PR；没有指定编号时，只选择仍开放且归档校验通过的最新课程 PR。
2. 记录 PR 编号、标题、head commit、归档 release、`course_id`、`lesson_id`、源内容 checksum 与检查结论。
3. “最新”按已校验的不可变归档版本判断，不按网页更新时间猜测。
4. `course_id + lesson_id` 与现有课程一致时，标题变化属于同号课文更新，允许新课文替换学生端当前标题与正文。
5. PR 身份跨课程、归档损坏、checksum 不符或必需检查失败时停止；不得猜测目标课时。

## 3. 教师端预览

1. 从 PR 的封存课程源导入本地草稿，不直接编辑旧封存文件。
2. 在草稿教师备注中保存 PR、commit 与源 checksum。
3. 对正文、标题、摘要、关键词、地图点、人物、来源和问答做逐字段比对。
4. 运行课程契约校验，并在教师端预览中检查段落、标注、知识笺和中文显示。
5. 预览或字段比对失败时保留 PR 开放，不进入学生发布。

## 4. 学生端内容优先发布

课文可以先于其他模块同步，但必须遵守以下边界：

- 新内容生成新的封存版本和新的当前发布；禁止改写既有 Release、sealed 文件或 checksum。
- 先运行 `scripts/sync_teacher_lesson.py`；它先把教师导入稿原样封存，再生成单独的学生兼容封存件，不把兼容字段倒写成教师来源事实。
- 学生课文同步范围包括标题、摘要、正文、关键词、课时元数据和地图点。
- 若新稿尚未适配旧模块，学生兼容封存件暂时保留上一发布的事实、人物、来源、问答提示、学习目标、情景材料和画板种子；必须在台账中把练、问、创、人物和视频标为“待同步”。
- V5 课文 checksum 变化时，必须在同一次发布中生成只更新课程绑定的下一版人物包；这只是技术兼容重签，不等于人物语义已经同步。
- 不得通过关闭完整性校验、伪造 checksum 或把旧式发布清单直接降级为当前发布来完成覆盖。
- 新课文与旧模块明显冲突时，以课文展示正确为先，不宣称旧模块已同步。

发布后同时验证：

1. 当前发布编号递增，父发布指向先前 Release；
2. 旧 Release 文件和 checksum 未变化；
3. 学生端课程路线和课文页显示新标题、摘要与正文；
4. 当前发布仍可解析，未同步模块的状态与台账一致。

## 5. 更新台账

每次同步只更新目标课时一行：

- 写入当前学生标题、来源 PR、commit、源 checksum 和当前 Release；
- 同号改题时把“PR 覆盖”改为“是”；
- 课文成功发布后标为“已同步”；
- 用户未要求同步的模块写“未要求”；已经要求但尚未适配的模块写“待同步”；验证完成后才写“已同步”；
- 不维护额外的过程流水，历史由 Git 提交、Release 和 PR 评论追溯。

## 6. 关闭来源 PR

只有以下条件全部成立才能关闭 PR：

- 教师端预览通过；
- 学生端当前课文已切换并通过页面检查；
- 台账已经更新；
- 本地测试和文档检查通过。

关闭前在 PR 留言写明学生 Release、发布 checksum、源 commit，以及仍为“待同步”的模块。关闭失败时报告原始错误，不删除本地成果；发布失败时保持 PR 开放。

## 7. 最小验证

- 课程内容、工作流与发布契约测试；
- 项目文档检查和 `git diff --check`；
- 学生端登录、课程路线、课文页的真实浏览器检查；
- 浏览器控制台无新增错误；
- Git 工作区只包含本任务文件，不覆盖用户已有改动。
