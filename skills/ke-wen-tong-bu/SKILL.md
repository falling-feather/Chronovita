# 课文同步

## 范围

只做：提取新课文 → 统一必要格式 → 覆盖课程目录与文本 → 登记配套不一致 → 核对展示 → 关闭已承接 PR。

新旧课号、排序、标题和内容大幅改变是正常更新。以教师最新快照为准，不为保持旧模块兼容而扩大任务。除非用户另行明确要求，禁止重建人物包、RAG/向量库、数据库、视频和练问创，禁止扩展发布契约、重签制品、改造互动入口或自动迁移旧学习记录。

## 执行

1. **确认来源**：先读项目根目录的 `doc/04-课程同步台账.md`，确认应用仓库、教师内容仓库及实际工作树。缺失配置先补齐；Skill 不复制仓库地址、课时总表或当前状态。统计实际开放 PR，不把最大编号当成待处理数量。
2. **按课程归并**：获取来源 PR 的准确 head commit，并让本地来源仓库取得相应提交。按 `course_id` 分组，以最新完整课程快照为本次目标；旧 PR 只核对承接关系，不逐个重放。修订稿采用最终版本。发现旧稿中的课时在最新快照消失时，确认是明确删课还是遗漏，不擅自并回目录或丢弃未承接内容。
3. **提取并去噪**：校验 PR 检查结果、来源身份、归档完整性及课文源 checksum。只同步课程名、课时编号和顺序、标题、摘要、正文、关键词及解释、时长和必要展示元数据。重复的 Markdown、格式层、运行包和预览 HTML 不单独维护；换行与首尾空白统一处理，加粗、颜色和关键词标注保留，不改写教师文字。来源 checksum 用于追溯；文本指纹排除导出时间、版本及 PR 元数据，避免将导出变化当成课文变化。
4. **覆盖同步**：复用下面的现有入口，写入 `content/textbooks/<course_id>.json` 和教师草稿文本。该课程的当前目录完整采用新快照；同号改题直接覆盖，不按旧标题或序号猜测映射。明确删除的课时退出当前目录，旧学习记录保留原身份。
5. **登记不一致**：在唯一课程同步台账记录来源 PR、commit、文本指纹及逐课状态。人物、史料、数据库、视频和练问创未配套时写“尚未同步／与新课文不一致”；这是可接受的本次交付边界，不是启动相关开发的理由。
6. **集中验收并收口**：检查本批目录数量和顺序、教师/学生正文一致及教学标注可用，执行相关定向验证和构建。检查通过即完成；不反复全量回归，也不修理历史模块与新课文不同引起的范围外问题。向每个已承接 PR 留言说明最终快照、文本指纹和配套边界，按编号关闭并复核开放清单。未承接或课文校验失败的 PR 保持开放并说明具体原因。

## 现有入口

在台账指向的应用工作树中，用项目 Python 环境执行：

```text
python -X utf8 scripts/sync_teacher_course_snapshot.py --repository <台账中的教师仓库> --checkout <本地来源仓库> --prs <PR 编号列表> --apply
```

参数与实现以脚本为准。只有该入口实际阻断课文提取、覆盖或展示时才作最小修复；不得为本次同步另造一套发布流程。完成后清理本次无用途的临时检查文件，保留用户已有改动。

交付只报告：处理的 PR、采用的最终快照、覆盖课时、实际验证结果和配套不一致台账。课文同步完成不等于配套模块完成，也不等于 PR 已合并。
