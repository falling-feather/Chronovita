# 学习成果提交与教师反馈

> 适用版本：V0.10.27—V0.10.28。本文记录 BE-009A 的不可变契约和 FE-011 的学生提交、版本回看、教师批阅与失败回退。

## 1. 核心边界

```text
本机私人草稿（IndexedDB）
  └─ 学生明确点击提交
       ├─ 服务端从登录会话绑定 student_id
       ├─ 服务端读取该学生、该课时的后端画板
       └─ 写入 learning-submission/v1 不可变版本
              └─ 教师读取已提交版本
                    └─ 追加 learning-feedback/v1
```

- Cookie 只用于确认身份，不保存书案正文。
- 新提交与反馈要求真实 accounts 用户；`legacy-local` 合成身份不创建无法迁移的成果所有者。
- 没有明确提交就没有教师可见成果；读取 IndexedDB 不等于同步。
- 客户端不传 `owner_id`、教师身份、版本号或画板正文。
- 提交失败不删除、不锁定本机草稿，学生可以继续编辑并重试。
- 教师反馈是新记录，不能修改学生版本或覆盖旧反馈。

## 2. 提交契约

`POST /api/v1/learning/submissions` 接收 `learning-submission-request/v1`：

- `client_submission_id`：一次明确提交的稳定幂等 ID。
- `course_id`、`lesson_id`：服务端检查真实课时归属。
- 书案标题与 Markdown 正文。
- 最多 24 张便签、600 段笔迹、20,000 个归一化点。
- 最多 240 条前三阶段学习事件。
- 本机草稿更新时间。

服务端补入学生 ID、提交时间、同课时递增版本和画板快照，再生成 `source_payload_checksum` 与最终 `checksum`。相同账号和 `client_submission_id` 的同内容重试返回原版本；同一 ID 携带不同内容返回 409，不能覆盖。

画板快照兼容旧无 envelope 记录和当前 `canvas/v1`。服务端只读取认证账号的键；没有画板时保存明确的空快照，损坏或超出容量时停止提交，不把损坏数据静默丢弃。

## 3. 教师反馈契约

教师队列和详情使用：

- `GET /api/v1/learning/review/submissions`
- `GET /api/v1/learning/review/submissions/{submission_id}`

反馈使用 `POST /api/v1/learning/review/submissions/{submission_id}/feedback`，接收 `learning-feedback-request/v1`：

- `client_feedback_id`：反馈重试幂等 ID。
- `completion_status`：`in_review`、`changes_requested` 或 `completed`。
- `comment`：1—4,000 字符。

反馈保存教师 ID、当时显示名、序号、时间和双 checksum。相同教师与客户端 ID 的同内容重试返回原记录，不同内容返回 409。学生在自己的提交详情中可读取完整反馈历史。

## 4. 数据库与权限

数据库 schema v4 新增：

| 表 | 作用 | 不可变约束 |
| --- | --- | --- |
| `learning_submissions` | 学生明确提交版本 | `student + course + lesson + version` 唯一；`student + client_submission_id` 唯一 |
| `learning_feedback` | 教师反馈历史 | `submission + sequence` 唯一；`teacher + client_feedback_id` 唯一 |

角色矩阵：

| 动作 | 学生 | 教师 | 审校者 | 管理员 |
| --- | --- | --- | --- | --- |
| 提交、查看自己的成果 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 查看已提交成果队列 | 拒绝 | `student.summary` | 拒绝 | `student.summary` |
| 追加反馈 | 拒绝 | `student.feedback` | 拒绝 | `student.feedback` |

跨学生读取自己的详情接口返回 404，避免确认其他学生的成果 ID。教师读取、队列访问和反馈写入均进入身份审计链。

## 5. 完整性与容量

- 提交 JSON 上限 4 MiB，反馈上限 256 KiB；API 仍受全局请求体上限保护。
- 存储读取重新执行 Pydantic 严格校验和 checksum 复验；未知字段、非有限数字或正文篡改均失败关闭。
- 正文只保存 Markdown，不接收客户端 HTML，教师端必须使用项目受限 Markdown 渲染器，不能直接注入 DOM。
- 表由统一迁移管理器登记，`validate` 模式不会自行建表；备份清单记录 schema v4。

## 6. 页面状态与重试

- `LessonCreate.tsx` 分开显示“本机已保存”和“教师可见 · 第 N 版”，不把自动保存冒充提交。
- 第一次提交前先保存书案并同步当前画板；书案或画板未能安全保存时停止提交，不冻结半成品。
- 请求发送前把完整 `learning-submission-request/v1` 写入当前账号/课程/课时的本机重试槽。超时或断网后按钮改为“重试上次提交”，只发送完全相同的正文、事件和幂等 ID；后续编辑可在确认旧请求后另交新版本。
- 学生在书案“版本记录”和 `/learning` 中查看不可变历史、教师反馈和完整书案快照。
- `/teacher/learning` 只展示已提交版本，教师可查看 Markdown 正文、便签、笔迹、只读导图和学习轨迹，并追加 `in_review`、`changes_requested` 或 `completed` 反馈。
- `LearningSubmissionViewer.tsx` 使用项目受限 Markdown 转换，不渲染客户端 HTML；教师页面为重型只读导图按路由异步加载。
