# Chronovita — 本地学习书案与事件账本

> 该文档隶属于[开发者文档](../01-开发者文档.md#14-当前开发情况与关联文档)，解释已有模块。文中旧版本验收只证明当时结果；新课表适配以[同步台账](../04-课程同步台账.md)为准。

> 适用版本：V0.10.26。本文记录 FE-010 的本地数据契约、前三阶段留痕、第四阶段编辑工具、隐私边界、降级方式和验收结果。

## 1. 目标与结果

第四阶段不再把整页等同于一张 React Flow 导图，而是学生自己的历史学习书案。学生可以把前三阶段形成的线索继续整理为正文、便签、手写笔迹、自由绘图和知识导图；后端已经生成的史官卷宗仍是权威推演结果，但在页面中下移为可展开档案，不再压住创作区。

V0.10.26 完成“本地私人草稿”，V0.10.27 冻结明确提交与教师反馈后端契约，V0.10.28 已接通学生提交、版本回看和教师批阅页面。断网编辑与恢复仍不自动上传正文；只有学生主动确认的快照进入教师可见版本。

## 2. 数据流

```text
踏勘关键词 ─┐
历史抉择 ───┤
RAG 问答 ───┼→ learning-ledger/v1（IndexedDB，localStorage 回退）
临时笔记 ───┘                    │
                                 ├→ 学习轨迹
史官卷宗 ────────────────────────┤
                                 └→ learning-desk-draft/v1
                                      ├─ 所见即所得 / Markdown 正文
                                      ├─ 便签
                                      ├─ 归一化笔迹与绘图
                                      └─ React Flow 导图（沿用后端 CAS）
```

`LessonPage.tsx` 是事件写入边界。子阶段只发送包含 `course_id`、`lesson_id`、事件类型、标题和摘要的请求；页面壳以当前认证主体重新建立 `owner_id`，拒绝跨课时请求后再写入。事件写入失败只关闭增强层，不能阻断课文、推演、RAG 或卷宗。

## 3. 本地契约与隔离

`learningLedger.ts` 定义两种客户端契约：

- `learning-ledger/v1`：稳定事件 ID、作用域键、账号、课程、课时、事件类型、标题、摘要、有限元数据和发生时间。
- `learning-desk-draft/v1`：标题、富文本 HTML、Markdown、便签、笔迹、创建时间和更新时间。

两者均使用 `owner_id + course_id + lesson_id` 形成编码后的作用域键。读取 IndexedDB 或回退记录时会再次核对三个原始字段，不因键名相同就信任正文。账号 token 不进入任何本地记录；账户模式仍只使用 HttpOnly Cookie。

当前事件类型为：

| 类型 | 触发点 | 保存内容 |
| --- | --- | --- |
| `stage_entered` | 进入四阶段之一 | 阶段名称与目的；同一标签页 30 分钟内去重 |
| `keyword_opened` | 点击正文关键词 | 正式词条与释义 |
| `decision_completed` | 固定行动或自由陈策成功推进 | 回合、行动来源和权威反馈 |
| `question_answered` | RAG 返回结构化回答 | 原问题、回答正文、人物模式和引用数量 |
| `temporary_note_saved` | 助教临时笔记完成自动保存 | 笔记摘要与字符数 |

事件最多保留 240 条 `localStorage` 回退记录。正文 HTML 上限 80,000 字符，Markdown 上限 60,000 字符，便签最多 24 张、每张 1,000 字符；笔迹最多 600 段、合计 20,000 个点。所有坐标压到 `0—1`，宽度限制为 `1—24`，非法颜色回退为固定墨色。

## 4. 编辑与安全边界

`LearningDeskEditor.tsx` 提供两种同步视图：

- 所见即所得支持标题、加粗、斜体、引证、有序和无序列表。
- Markdown 使用项目自己的小型受限方言，支持标题、强调、重点、引证和列表。

富文本只保留 `p/br/strong/em/u/mark/h2/h3/ul/ol/li/blockquote`。本地草稿即使被手工篡改，重新载入时也会删除脚本、图片、事件属性和未知标签；粘贴只接收纯文本。这里不是通用 HTML 编辑器，不允许运行任意嵌入内容。

`LearningDeskDrawing.tsx` 使用 Pointer Events，同时支持鼠标、触控笔和手指。每次落笔保存为模式、颜色、宽度和归一化点列；擦除也是可回放的线条操作。画布不保存截图或二进制 Blob，因此可在不同分辨率下重绘，并能受统一容量上限约束。

React Flow 的读取、自动保存、冲突检测、AI 扩充和卷宗节点导入保持原接口不变。它现在只在“知识导图”工具中挂载；未显示时不会创建零尺寸播放器，切换回来后通过 `ResizeObserver` 重新确认画布尺寸。

## 5. 页面结构与离线行为

```text
学习书案题头 + 本机保存状态
  ├─ 材料匣：临时笔记 / 推演卷宗 / 导图状态
  └─ 工具区
       ├─ 正文与便签
       ├─ 手写与绘图
       ├─ 知识导图
       └─ 学习轨迹

可展开史官卷宗档案
```

首次打开没有草稿时，以课程题目、写作提示和临时笔记建立本机初稿；已有草稿时绝不覆盖。临时笔记或史官卷宗只能通过学生点击“收入正文/整理进正文”追加，避免后台更新悄悄改写学生文章。正文、便签和笔迹在 520ms 无新修改后写入 IndexedDB；学生也可在错误状态点击重试。IndexedDB 不可用时使用 `localStorage`，两者都不可用时显示失败，但导图后端保存和其他课堂阶段仍可继续。

网络中断不会影响本地草稿与事件账本。导图沿用后端接口，断网时保留当前页面内改动并显示保存失败；这与本地正文已保存是两个独立状态，界面分别说明，不能把本地保存冒充后端提交。

## 7. 后续接口边界

V0.10.27—V0.10.28 已实现这条边界：学生本机编辑 → 学生明确提交 → 后端生成不可变成果版本 → 教师读取已提交版本并追加反馈。服务端自行绑定提交者并冻结同课时画板快照，不信任客户端 `owner_id`；提交失败不会删除或锁死本机草稿。前端会保留原样冻结的请求用于幂等重试，避免网络中断后重复生成版本。接口、页面与权限见[学习成果提交与教师反馈](#8-学习成果提交与教师反馈)，剩余验收任务见[当前项目规划](../02-项目规划.md)。

## 8. 学习成果提交与教师反馈

> 适用版本：V0.10.27—V0.10.28。本文记录 BE-009A 的不可变契约和 FE-011 的学生提交、版本回看、教师批阅与失败回退。

### 8.1 核心边界

```text
本机私人草稿（IndexedDB）
  └─ 学生明确点击提交
       ├─ 服务端从登录会话绑定 student_id
       ├─ 服务端读取该学生、该课时的后端画板
       └─ 写入 learning-submission/v1 不可变版本
              └─ 教师读取已提交版本
                    └─ 追加 learning-feedback/v1
```

- Cookie 只用于确认身份，不保存书案正文。
- 新提交与反馈要求真实 accounts 用户；`legacy-local` 合成身份不创建无法迁移的成果所有者。
- 没有明确提交就没有教师可见成果；读取 IndexedDB 不等于同步。
- 客户端不传 `owner_id`、教师身份、版本号或画板正文。
- 提交失败不删除、不锁定本机草稿，学生可以继续编辑并重试。
- 教师反馈是新记录，不能修改学生版本或覆盖旧反馈。

### 8.2 提交契约

`POST /api/v1/learning/submissions` 接收 `learning-submission-request/v1`：

- `client_submission_id`：一次明确提交的稳定幂等 ID。
- `course_id`、`lesson_id`：服务端检查真实课时归属。
- 书案标题与 Markdown 正文。
- 最多 24 张便签、600 段笔迹、20,000 个归一化点。
- 最多 240 条前三阶段学习事件。
- 本机草稿更新时间。

服务端补入学生 ID、提交时间、同课时递增版本和画板快照，再生成 `source_payload_checksum` 与最终 `checksum`。相同账号和 `client_submission_id` 的同内容重试返回原版本；同一 ID 携带不同内容返回 409，不能覆盖。

画板快照兼容旧无 envelope 记录和当前 `canvas/v1`。服务端只读取认证账号的键；没有画板时保存明确的空快照，损坏或超出容量时停止提交，不把损坏数据静默丢弃。

### 8.3 教师反馈契约

教师队列和详情使用：

- `GET /api/v1/learning/review/submissions`
- `GET /api/v1/learning/review/submissions/{submission_id}`

反馈使用 `POST /api/v1/learning/review/submissions/{submission_id}/feedback`，接收 `learning-feedback-request/v1`：

- `client_feedback_id`：反馈重试幂等 ID。
- `completion_status`：`in_review`、`changes_requested` 或 `completed`。
- `comment`：1—4,000 字符。

反馈保存教师 ID、当时显示名、序号、时间和双 checksum。相同教师与客户端 ID 的同内容重试返回原记录，不同内容返回 409。学生在自己的提交详情中可读取完整反馈历史。

### 8.4 数据库与权限

数据库 schema v4 新增：

| 表 | 作用 | 不可变约束 |
| --- | --- | --- |
| `learning_submissions` | 学生明确提交版本 | `student + course + lesson + version` 唯一；`student + client_submission_id` 唯一 |
| `learning_feedback` | 教师反馈历史 | `submission + sequence` 唯一；`teacher + client_feedback_id` 唯一 |

角色矩阵：

| 动作 | 学生 | 教师 | 审校者 | 管理员 |
| --- | --- | --- | --- | --- |
| 提交、查看自己的成果 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 查看已提交成果队列 | 拒绝 | `student.summary` | 拒绝 | `student.summary` |
| 追加反馈 | 拒绝 | `student.feedback` | 拒绝 | `student.feedback` |

跨学生读取自己的详情接口返回 404，避免确认其他学生的成果 ID。教师读取、队列访问和反馈写入均进入身份审计链。

### 8.5 完整性与容量

- 提交 JSON 上限 4 MiB，反馈上限 256 KiB；API 仍受全局请求体上限保护。
- 存储读取重新执行 Pydantic 严格校验和 checksum 复验；未知字段、非有限数字或正文篡改均失败关闭。
- 正文只保存 Markdown，不接收客户端 HTML，教师端必须使用项目受限 Markdown 渲染器，不能直接注入 DOM。
- 表由统一迁移管理器登记，`validate` 模式不会自行建表；备份清单记录 schema v4。

### 8.6 页面状态与重试

- `LessonCreate.tsx` 分开显示“本机已保存”和“教师可见 · 第 N 版”，不把自动保存冒充提交。
- 第一次提交前先保存书案并同步当前画板；书案或画板未能安全保存时停止提交，不冻结半成品。
- 请求发送前把完整 `learning-submission-request/v1` 写入当前账号/课程/课时的本机重试槽。超时或断网后按钮改为“重试上次提交”，只发送完全相同的正文、事件和幂等 ID；后续编辑可在确认旧请求后另交新版本。
- 学生在书案“版本记录”和 `/learning` 中查看不可变历史、教师反馈和完整书案快照。
- `/teacher/learning` 只展示已提交版本，教师可查看 Markdown 正文、便签、笔迹、只读导图和学习轨迹，并追加 `in_review`、`changes_requested` 或 `completed` 反馈。
- `LearningSubmissionViewer.tsx` 使用项目受限 Markdown 转换，不渲染客户端 HTML；教师页面为重型只读导图按路由异步加载。
