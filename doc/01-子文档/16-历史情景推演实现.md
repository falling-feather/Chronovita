# 历史情景推演实现

> 适用版本：V0.10.23。本文记录 GAME-002 的实现边界、场景资产、数据流和验收结果；未来任务见[项目规划](../02-项目规划.md)，已完成提交见[开发历史](../03-开发历史.md)。

## 1. 完成结果

L101“大禹治水”和 L103“商鞅变法”的抉择阶段已经从表格式关卡改为连续历史情景推演：学生先读情境和身份目标，再在六回合中选择审校后的行动或自行陈策；每次推进都会显示叙事反馈、局势变量、人物信任和事件，历史回合可随时回看。达到发布关卡规定的回合或结局条件后，页面按平衡、代价或失败呈现结果，并读取后端生成的史官卷宗。

这次重构只改变表达层，不把历史规则搬到浏览器。场景图片、回合标签和结局色调是前端投影；行动白名单、状态变化、完成条件、发布身份和卷宗仍由服务端权威决定。

## 2. 核心数据流

```text
当前 V3 发布与 ScenarioTemplateV1
  → POST /practice/game/sessions（幂等开始或恢复）
  → 固定行动：POST /turns → 确定性规则结算
  → 自由陈策：POST /free-input → 当前轮行动白名单内分类
  → GameSession revision、history、变量、NPC、事件
  → 达到终局后读取 DossierV1
```

- `GamePractice.tsx` 负责会话恢复、提交状态、回合回看和可访问反馈。
- `gamePresentation.ts` 负责场景映射、叙事按回合分组、中文选择序号和结局语气映射，不计算游戏状态。
- 每次写入继续携带 `revision` 和唯一 `client_action_id`，重复请求不会重复消耗回合。
- 自由陈策只有在服务端高置信映射到本轮允许行动时才推进；模型未配置、超时、越界或需要澄清时，页面显示原因和最多四个安全回退行动，当前回合保持不变。
- 预设行动无需在线模型，断网课堂在 API 可用时仍能完成完整六回合、卷宗和后续画板流程。

## 3. 页面结构

| 区域 | 表达 | 数据来源 |
| --- | --- | --- |
| 情景舞台 | 时代、地点、环境图、当前回合 | 课时 ID 与展示映射；回合来自会话 |
| 身份与目标 | 学生本轮扮演身份、课程目标 | 发布关卡摘要 |
| 回合史卷 | 序章、已完成回合、当前回合、历史回看 | `session.history` |
| 行动区 | 若干预设行动卡与常显自由输入 | `available_actions` 与自由输入接口 |
| 局势案板 | 当前变量、最近变化和事件 | `state`、最后一轮 delta |
| 人物议事席 | 时代人物立绘、信任值与变化 | 发布 NPC 元数据与权威会话 |
| 结局卷页 | 正向、成果与代价并存、需要复盘 | 会话状态、结局 ID、`DossierV1` |

历史回看只切换阅读焦点，不修改会话。点击“回到当前”即可继续行动。移动端把回合轨道收为内部横向滚动区，页面本身不产生横向滚动；滚动条隐藏但键盘与触控仍可使用。`prefers-reduced-motion` 下关闭卷页入场、选择揭示和人物变化动画。

## 5. 结局表达规则

结局事实仍来自发布规则。前端只把稳定结局 ID 映射为三种教学语气：

- ID 包含 `balanced`、`water-controlled`、`durable` 或 `credible`：`positive`，显示“平衡路径 · 阶段成功”。
- 会话为 `failed` / `abandoned`，或 ID 包含 `failure`、`breakdown`、`collapse`、`uncontrolled`、`lost`：`negative`，显示“推演结局 · 需要复盘”。
- 其余已完成结果：`mixed`，显示“推演结局 · 成果与代价并存”。

因此“完成六回合”不等于成功，页面不会再把妥协、失控或高代价路径统一涂成绿色。卷宗标题、历史解释和主要代价直接读取 `DossierV1`，客户端不能改写。

## 7. 已知边界

- 在线自由陈策依赖已配置模型；未配置时不会伪装智能回答，而是退回本轮审校行动。
- 场景图是教学气氛插画，不是历史现场复原，不作为史实证据或 RAG 引用。
- 当前只有 L101/L103 使用专属情景图；其他课时自动使用通用低干扰背景，待正式课程内容和关卡发布后再配置。
- V0.10.23 不改动冻结课程契约、规则引擎、卷宗结构或教师审校工作流。
