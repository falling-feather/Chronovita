## 2. 大版本与中版本汇总

- **实际完成**：两课课程/关卡/证据/展示以同一 V3 release 精确绑定；四角色账户、学生四阶段课堂、教师证据/展示工作台、FTS/BGE RAG、离线抽取式回退、两段 45 秒视频、确定性课堂 ZIP 和双分辨率 E2E 均形成代码与验证结果。
- **质量结果**：PR #4 的 `python311-quality`、`postgres16-service`、`gitleaks-history`、`teacher-editor-launcher` 和 `student-classroom-e2e` 全部成功。
- **尚未形成的结果**：用户内容验收、合入 `main` 和公开 V0.10 prerelease；因此本阶段称为技术候选基线，不称正式发布完成。
- **包含版本**：`V0.10.0`—`V0.10.14`。

### 2.2 V1.0.0 内容智能体阶段基线

- **原定目标**：保留 V0.10.32 已成熟的课堂架构，以独立大版本开始证据库、AI 助教和 NPC 对话内容完善。
- **实际完成**：统一应用与前端版本为 V1.0.0，建立 `codex/v1-agent-routing` 活动分支；规划首选“本地状态机拟合 + 受证据约束 API”，将轻量生成模型列为可插拔次优路线，并纠正未执行且冲突的旧发行任务编号。
- **当前边界**：本提交只形成开发基线，没有改变 RAG、模型、NPC 或游戏运行逻辑，也没有创建公开发行、标签或新课堂包。
- **包含版本**：`V1.0.0`。

### 2.3 V1.0.1 双课本地回答与受约束 API

- **日期**：2026-08-31。
- **原定目标**：为 L101 大禹治水与 L103 商鞅变法建立本地优先、复杂问题才调用 API 的确定性路由底座。
- **实际完成**：新增与当前证据 checksum 绑定的双课回答状态、`local_template / external_api / clarify / refuse` 四路决策、原问题答案槽与审校关系守卫和外部模型封闭证据选择；在线模型租约只在命中批准关系且证据充分的复杂综合题真正路由到 API 时获取。模型不能提交正文，只能从覆盖全部问题 facet 的强匹配候选中选择片段和批准的综合模式；服务端从发布摘要确定性组装答案并执行不确定性下限，限流、超时、无效引用、facet 漏失和模式越界都回退本地证据答案。
- **安全边界**：查询改写不能自行制造可回答性；面积、价格、颜色、形状、未知工匠等未发布答案槽，以及离题、注入、时代错置和证据不足问题均不调用 API、不生成引用。
- **包含版本**：`V1.0.1`。

### 2.4 V1.0.2 双课证据原子库与 V4 发布

- **日期**：2026-08-31。
- **实际完成**：L101/L103 各建成 48 个稳定片段的 `EvidenceCorpusV2`，将答案槽、史实边界、来源定位、人物范围和 API 允许位置写入证据 checksum；检索、本地回复、模型输入与引用校验统一受当前槽位的片段白名单约束。
- **发布结果**：两课通过 `course-release/v4` 原子切换到发布 #6（`rel-28b5624648-0006`），重复执行幂等；V1 证据和 V1—V3 release 仍可读，旧发布 #5 未被改写。
- **验证结果**：契约、checksum、损坏语料、双课原子发布、受槽位约束路由和 V1 兼容均通过；两课纯 FTS 基准各 60/60，后端 540 项（3 项条件跳过）、前端 61 项、TypeScript 与两种前端构建通过。
- **包含版本**：`V1.0.2`。

### 2.5 V1.0.3 双课人物包与可审计会话

- **日期**：2026-08-31。
- **实际完成**：L101 发布 5 个、L103 发布 6 个审校人物档案；`PersonaPackV1` 固定角色口吻、渠道、可答槽位、知识边界、允许证据用途和场景说话绑定。人物回答从当前包解析范围，边界专用材料不得交给外部模型，后世材料必须明确标为史家补充。
- **发布结果**：两课通过 `course-release/v5` 原子切换到发布 #7（`rel-28b5624648-0007`）；L101 人物包 checksum 为 `217c4c58e522b4cad6f54ffaa9c1a0da47a9c0de0b3f51e57ec4c595787e885e`，L103 为 `7aee38bd070e056088d0df9c782b6439140e0bb3e6d7208388595ac678a60702`，发布 #6 未被改写。
- **会话结果**：新增创建、读取和发送消息三类人物会话接口；owner、release、人物包、证据库、人物和渠道由服务端锁定，写入使用 revision 与消息 ID 幂等，每段会话最多 24 轮并只使用最近 6 轮做连续性，不把旧答案或旧引用提升为新证据。数据库迁移升至 schema v5。
- **任务收束**：原规划 `BE-010` 的服务编排、持久化和 API 范围并入 `CONTENT-003` 同一交付，不另建重复提交。
- **包含版本**：`V1.0.3`。

### 2.6 V1.0.4 双课本地陈策与规则后人物对话

- **日期**：2026-08-31。
- **行动结果**：L101/L103 的自由陈策先在本机当前可用行动内拟合；精确别名和高置信匹配零 API 推进，离题、提示注入和不可用行动失败关闭，只有含糊且具备当前发布已审校事实上下文的输入才可升级外部分类。
- **对话结果**：规则先结算状态、事件和结局，每个新 V5 回合随后生成 `ScenarioNpcDialogueV1`。人物、发布、证据、行动和规则结果由服务端固定；外部模型只能润色底稿并选择允许 passage，失败或越界时回退本地表达。
- **存储与页面结果**：数据库迁移升至 schema v6，以 `game_npc_dialogues` 和同一回合 CAS 原子保存人物对话；新增按 owner 恢复对话列表的 API。学生端分层显示陈策、规则旁白和具名人物回应，刷新时按回合幂等恢复，旧会话无人物投影时保留旁白降级。
- **包含版本**：`V1.0.4`。
