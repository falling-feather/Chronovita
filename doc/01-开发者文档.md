## 1. 项目与系统定位

Chronovita 把一门历史课组织为“踏勘—抉择—召见—卷宗”四阶段课堂：

| 课堂阶段 | 学生活动 | 主要数据对象 | 主要实现 |
| --- | --- | --- | --- |
| 踏勘 | 阅读正文、材料、地图并观看短片 | `CoursePackageV1`、`LessonPresentationV1` | `LessonWatch.tsx`、课程与展示 API |
| 抉择 | 在六回合中选择固定行动或输入自由行动 | `ScenarioTemplateV1`、`GameSessionV1`、`TurnV1` | `GamePractice.tsx`、`services/game_runtime/` |
| 召见 | 向课程专家或人物追问依据 | `EvidenceCorpusV1`、`RagAnswerV1`、`PersonV1` | `LessonAsk.tsx`、`services/rag/` |
| 卷宗 | 复盘选择、代价、解释和来源并导入画板 | final `DossierV1`、Canvas、Progress | `LessonCreate.tsx`、持久化服务 |

核心术语：

- **草稿**：允许作者继续修改的数据库或工作流状态，不是学生可见事实。
- **封存件**：通过校验和审校、带精确版本与 checksum 的不可变制品。
- **release**：将课程、关卡、证据库和展示资源绑定为一个活动快照；V0.10 正式课程使用 `course-release/v3`。
- **开发目录**：可用于教师编辑和测试的内容源，不得冒充已发布课程。
- **published 目录**：只从当前活动 release 读取的学生运行目录。
- **抽取式回退**：在线模型不可用时，直接根据召回证据摘要组织答案，不使用模型常识。

## 2. 总体架构

```text
浏览器
├─ React 学生端：课程、四阶段课堂、进度、画板
├─ React 教师端：课程/关卡/证据/展示草稿与发布
└─ React 管理端：账号、角色、密码、禁用与会话撤销
          │  /api/v1/* + HttpOnly Cookie
          ▼
FastAPI（apps/api/main.py）
├─ 中间件：请求体限制、Host/CORS、请求 ID、脱敏访问日志、登录限流
├─ routers：auth、courses、learning、practice、game、admin_content
└─ 同源静态服务：课堂包中提供 SPA、视频和 API
          │
          ▼
services 业务层
├─ auth / persistence / operations
├─ content / content_history / contracts
├─ game_runtime / saga / sandbox
├─ rag / llm / ai
└─ courses
          │
          ├─ SQLite 或 PostgreSQL：账号、会话、审计、学生资产和工作流状态
          ├─ content/：草稿、封存件、运行制品、release manifest 和活动指针
          ├─ distribution/：模型、课堂发行源和许可
          └─ media/：HyperFrames 工程；正式媒体另封存到 content/media/
```

浏览器只通过 API 使用业务状态。`services/` 不依赖 React；路由层负责身份、HTTP 状态和稳定错误信封，服务层负责契约、并发、持久化和失败关闭。

## 5. 入口与运行流程

### 5.1 开发模式

1. `apps/api/main.py` 导入 `Settings`，校验运行档、数据库、Host、CORS、认证和模型端点。
2. lifespan 建立数据库 Engine，执行 `apply-safe` 迁移或 `validate` 复核，再初始化认证、内容、游戏和学生资产服务。
3. FastAPI 注册 `/api/v1` 路由；开发时 Vite 把 API 请求代理到回环 API。
4. React 启动 `AuthProvider`，读取 `/api/v1/auth/config` 和 `/me`；未认证访问受保护页面时跳到 `/login` 并保存兼容的原目标。
5. 页面只从 API 取得课程、发布、会话和学生资产；刷新后重新读取服务端权威状态。
6. 停止时关闭 API 和前端进程；不得直接删除正在使用的数据库或运行目录。

### 5.2 正式双端口验收

开发工作树使用 `scripts/classroom-review.ps1` 同时启动 accounts API 与 Vite。脚本从 `-WebPort` 生成唯一可信 Origin，从 `-ApiPort` 生成 Vite 代理目标；默认端口为 `5174 / 8010`，因此不依赖机器上可能被其他项目占用的 `5173 / 8000`。默认先用 `prepare_rag_model.py --verify-only` 复验发行 BGE 资源，损坏即停止；只有显式 `-LexicalOnly` 才进入词法回退。`RagAnswerV1.retrieval_mode` 返回本次回答实际使用的 `hybrid / lexical`，学生端以小标签显示“混合检索 / 词法回退”。

启动、停止：

```powershell
.\scripts\classroom-review.ps1
.\scripts\stop-classroom-review.ps1
```

启动器写入 `.chronovita-review/runtime.json` 并只回收记录 PID 与两个监听端口，不触碰 `5173 / 8000` 或其他项目进程。

### 5.3 单端口课堂包

1. `scripts/build_classroom_release.py` 预构建前端并把源码、wheelhouse、模型、内容、视频、启动脚本、许可和 manifest 打入确定性 ZIP。
2. 解压后由 `scripts/classroom.ps1` 初始化账号数据库；空库首次启动必须安全输入管理员密码。
3. FastAPI 设置 `CHRONO_SERVE_WEB_APP=true`，同一端口提供 SPA、视频 Range 请求和 `/api/v1/*`。
4. 默认只绑定 `127.0.0.1`；`-Lan` 才绑定 `0.0.0.0` 并显示学生访问地址。
5. `scripts/stop-classroom.ps1` 读取自身运行状态并回收进程，不扫描或终止无关进程。

### 5.4 请求与状态生命周期

```text
Cookie/请求 → 身份与权限 → 当前 release 解析 → 契约校验
            → 服务层事务/CAS → 数据库或不可变制品
            → 响应 DTO → React 页面
```

任何校验、权限、checksum、CAS 或审计失败都必须在写入前失败，或由同一事务回滚；错误响应不得泄露数据库 URL、Cookie、口令、API key、提示词或学生私有文本。

### 6.2 认证、授权与学生资产

`services/auth/` 和 `apps/api/routers/auth.py` 管理四类角色：

| 角色 | 主要权限 | 默认工作区 |
| --- | --- | --- |
| `student` | 自己的课程、会话、进度、卷宗和画板 | `/` |
| `teacher` | 读取和创作内容、读取学生摘要 | `/admin/content` |
| `reviewer` | 独立审校和审计复核，不创作、不发布 | `/admin/content` |
| `admin` | 发布、账户与会话管理以及内容管理 | `/admin/accounts` |

`accounts` 模式把登录状态保存在 HttpOnly Cookie；服务端保存会话哈希、空闲与绝对到期时间、撤销状态和审计。最后一个启用管理员不能被禁用或移除管理员角色。Canvas、Progress、GameSession 和 Dossier 均绑定认证 `user_id`；客户端不能选择所有者。

### 6.3 课程、内容、证据与 V3 发布

| 层 | 位置 | 权威输入 | 输出 |
| --- | --- | --- | --- |
| 作者源 | `services/content/flagships/dayu_l101.py`、`shangyang_l103.py` | 正文、人物、事实、来源、证据片段、关卡和展示描述 | 可重复构建的课程初稿 |
| 工作流 | `services/content/workflow.py`、`evidence_workflow.py`、`scenario_authoring.py` | 草稿、作者、审校者和 CAS revision | 校验、批准、封存记录 |
| 契约 | `services/contracts/` | 严格字段、稳定排序和 checksum 规则 | `CoursePackageV1`、`EvidenceCorpusV1`、`LessonPresentationV1` 等 |
| 运行制品 | `content/runtime/v1/` | 封存件 | 内容寻址 JSON 与媒体引用 |
| 发布 | `content/releases/manifests/`、`active/` | 精确课程/关卡/证据/展示版本与 checksum | `course-release/v3` 活动快照 |

教师不能审校自己的内容，审校者不能发布，管理员发布时只能选择已封存且身份一致的制品。重复发布相同集合必须幂等；任何文件漂移、路径越界、checksum 不一致或跨课程引用都在移动活动指针前失败。

### 6.4 游戏、卷宗、画板与进度

`services/game_runtime/` 从当前发布的 `ScenarioTemplateV1` 启动会话。固定行动直接进入规则引擎；自由输入先被严格分类到当前行动白名单，低置信、越界或模型不可用不会推进回合。

回合写入使用 `revision` 与 `client_request_id` 保证并发单写和重试幂等。规则引擎应用变量/NPC 效果、事件和结局；最终卷宗只从封存规则、真实回合和发布身份确定性派生。画板使用版本化 envelope 与 CAS，卷宗节点按稳定 ID 和来源 checksum 幂等合并。学习进度按阶段 touch，在竞争写入时重读并合并已完成层级。

V0.10.23 的 `GamePractice.tsx` 不复制规则，而是把同一权威会话呈现为历史情景舞台：发布情境开场、已完成回合和当前轮次组成可回看史卷；预设行动继续走确定性 `/turns`，自由陈策继续走 `/free-input`。模型未配置、置信不足或问题越界时只显示原因与服务端允许的回退行动，不消耗回合。终局颜色由已发布结局 ID 的教学含义映射，不把所有完成会话伪装成成功；卷宗仍由后端生成。双旗舰场景图只负责表达，资产损坏时降级为同结构底色，不参与结局或规则判断。

### 6.5 RAG 与模型边界

`services/rag/query.py` 先为当前发布构造不超过四路的可审计查询计划，`services/rag/retrieval.py` 再为当前课程、课时、release checksum 和 evidence checksum 建立并读取可重建 SQLite 索引：

1. 查询规划识别人物身份、课程概览、证据边界、因果、比较和细节意图；人物模式可消解“你/我”的指代，L101/L103 可把口语别名扩展为当前发布中已经存在的规范词。
2. 提示覆盖、伪造引用和明显时代错置被标记为阻断查询，不执行别名扩展，也不会因人物名称命中而变成可回答问题。
3. 原问、人物消解和规范词改写分别进入 FTS/BGE；每路内部先做词法—向量 RRF，多路结果再做一次 RRF。只要存在通过支持阈值的改写，未通过阈值的噪声路不再影响最终排序。
4. 中文词和二元组进入 FTS5；本地模型可用时生成 512 维 BGE 向量。人物模式始终按证据的 `person_ids` 收窄。
5. 每次回答把实际参与最终排序的路径写入 `RagAnswerV1.retrieval_mode`；向量真实参与时为 `hybrid`，否则为 `lexical`，前端不得把词法回退冒充完整混合检索。
6. 词法信号覆盖至少 40% 且存在实际命中，或前五结果向量相似度至少 0.82，才视为证据充分。人物身份意图可用当前不可变发布中的人物档案组织自我介绍，但仍必须附人物范围内召回片段。
7. 不充分时直接返回 `insufficient_evidence`，不调用模型，不生成引用；充分且在线模型可用时，模型只能从本次召回片段选择 1—4 个引用，越界引用或输出失败自动退回抽取式答案。

人物模式只把发布人物档案作为表达和知识边界，并显示“角色化教学表达，不是史料原话”。“您是谁？”会读取同一发布中的姓名、角色、摘要和首条边界，引用仍只能来自该人物绑定的证据片段。40 题自然问法基准在纯 FTS 与真实 `BAAI/bge-small-zh-v1.5` 两种运行模式中均达到来源 Top 5 命中 40/40、支持判定 40/40；可用 `scripts/evaluate_rag_retrieval.py` 重跑。完整规则见[自然问答查询规划与多路检索](01-子文档/17-自然问答查询规划与多路检索.md)。

### 6.6 持久化、迁移与运行门禁

`services/persistence/` 提供 SQLite 与 PostgreSQL 同步 Engine、版本迁移、账号/审计、KV、进度、游戏会话、卷宗、备份和恢复。非空 `CHRONO_DATABASE_URL` 优先于 `CHRONO_SQLITE_PATH`。

- `apply-safe`：本地和测试可应用已登记安全迁移。
- `validate`：只复核 schema，版本不匹配即拒绝启动；production 必须使用此模式。
- SQLite 运维使用 `scripts/manage_database.py` 的 `status`、`migrate`、`backup`、`verify-backup`、`restore`。
- PostgreSQL 生产档要求 `postgresql+psycopg` 和 `sslmode=verify-full`；CI 的无 TLS PostgreSQL 只证明服务权限矩阵，不证明生产灾备。

当前 Saga 状态和部分限流仍为进程内实现，production 配置要求 `CHRONO_API_WORKER_COUNT=1`；不得横向扩为多副本。

所有设置以 `CHRONO_` 为前缀，定义在 `apps/api/settings.py`。`.env` 只供本地开发；发行和 CI 可设置 `CHRONO_DISABLE_DOTENV=true` 禁止隐式读取。

| 配置 | 默认值 | 用途 | 重要边界 |
| --- | --- | --- | --- |
| `CHRONO_RUNTIME_PROFILE` | `local` | `local` / `production` 配置档 | production 触发跨字段安全门禁 |

## 10. 开发与运行操作

所有命令从活动工作树根目录执行。

### 10.1 环境准备

前提：Python 3.11—3.13、Node.js 20.19+ 或 22.12+、npm。

```powershell
py -3.11 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r apps/api/requirements.txt
Push-Location apps/web
npm ci
Pop-Location
```

```powershell
& '.\.venv\Scripts\python.exe' -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8000 --reload
```

终端二：

```powershell

Pop-Location
```

正常结果：`http://127.0.0.1:5173` 打开 React 页面，API `/healthz` 返回存活，`/readyz` 返回 ready。停止使用各终端 `Ctrl+C`；不要用宽泛进程名终止无关 Node/Python 进程。

### 10.3 Windows 课堂包

发行包解压目录中执行：

```powershell
.\scripts\classroom.ps1
```

首次启动会安全询问管理员口令并默认只显示本机地址。局域网课堂需显式执行：

```powershell
.\scripts\classroom.ps1 -Lan
```

停止：

```powershell
.\scripts\stop-classroom.ps1
```

正常结果：单一端口同时提供 SPA、API 和视频，首次安装后断网仍能登录、播放、执行固定行动、使用 FTS/抽取式问答、生成卷宗并保存画板。

Pop-Location

构建产物写入 `apps/web/dist/`；它可以删除重建，不能提交或作为发行事实。后端测试失败先看具体测试模块与稳定错误码，不通过重复运行掩盖并发或生命周期缺陷。

在 PowerShell 7 宿主中经 Python 启动 Windows PowerShell 5.1 测试时，继承的 `PSModulePath` 可能优先指向 PowerShell 7 模块，表现为找不到 `Get-FileHash` 或 `ConvertTo-SecureString`。先让 Windows PowerShell 报告自己的模块路径，再运行测试：

```powershell
$windowsPSModulePath = & powershell.exe -NoProfile -NonInteractive -Command '$env:PSModulePath'
$env:PSModulePath = $windowsPSModulePath.Trim()
& '.\.venv\Scripts\python.exe' -m unittest discover -s tests
```

## 11. 修改与扩展指南

### 11.1 新增或修改正式课程

1. 先在[项目规划](02-项目规划.md)建立并认领内容任务。
2. 在 `services/content/flagships/` 修改可重复作者源，明确传说、文献、考古和教学解释边界。
3. 生成课程、证据、关卡和展示草稿；使用不同作者/审校身份完成校验、送审、批准和封存。
4. 通过 V3 发布动作选择精确四类制品版本和 checksum，不直接编辑 `content/runtime/v1/`。
5. 增加课程深度、边界、引用、结局可达、回滚和浏览器整链测试。
6. 同步本开发者文档、规划和开发历史。

反例：只在 React 中写课程文本、直接修改 sealed JSON、让模型补充未发布史实，都会破坏发布事实源。

### 11.2 新增 API

1. 在 `services/` 定义契约和业务行为，明确身份、输入上限、事务、幂等、错误和降级。
2. 在 `apps/api/routers/` 增加薄路由，并在 `apps/api/main.py` 注册或复用现有 router。
3. 在 `apps/web/src/utils/api.ts` 增加 DTO 与客户端调用；页面不得自行拼接服务端权威字段。
4. 增加正向、权限、损坏、并发和 OpenAPI 测试。
5. 更新本文件接口表和配置说明。

### 11.3 新增页面或课堂阶段能力

1. 确认功能属于踏勘、抉择、召见或卷宗中的哪一层。
2. 在 `App.tsx` 设置明确角色守卫；数据读取进入 `utils/api.ts`，课堂共性进入 `features/classroom/`。
3. 保留加载、空、错误、401、403、网络中断和刷新恢复状态。
4. 在 1366×768、1920×1080 和适用窄屏检查溢出、键盘、label 和控制台。

### 11.4 修改 RAG

检索阈值、tokenizer、融合算法、模型 revision、人物过滤或回答合同变化都属于算法/契约修改，必须：

1. 建立独立 AI/ARCH 任务。
2. 更新 40 题基准和不支持问题反例。
3. 证明所有引用属于本次召回与当前 release。
4. 证明模型、向量和网络缺失时 FTS/抽取路径仍可用。
5. 不通过放宽“依据不足”来改善人物身份问句；身份意图应使用发布人物档案的单独确定性路径。

### 11.5 修改核心文档

1. 先在 `doc/02-项目规划.md` 建立 DOC 或实际执行组任务。
2. 当前实现写 `01`，未来任务写 `02`，已发生提交写 `03`。
3. 旧 `docs/` 只保留专项或兼容入口，不建立第二份当前任务原件。
4. 运行 skill 校验、项目文档检查和 `git diff --check`。

### 13.1 工作区清理边界

可删除并重建：

- `__pycache__/`、`*.pyc`、`*.tsbuildinfo`。
- `apps/web/dist/`、`playwright-report/`、`test-results/`。
- `data/release-smoke-*`、`data/student-e2e-*`。
- 已确认哈希一致的重复 `data/release-artifacts/*-run*` 和旧候选包。
- 仓库根或 `data/` 直属、内容为空的 `tmp*` 目录。

必须保留：

- 活动工作树源码、`.git` 元数据和所有用户修改。
- `content/` 的作者源、封存件、运行制品、release 与媒体。
- `distribution/models/`、`media/hyperframes/` 和正式许可。
- 正式 V0.10.14 ZIP、`.sha256`、`licenses.json` 以及独立验收解压包。
- `.venv` 和 `node_modules`，除非用户明确要求重建依赖环境。
- 旧根工作树的 `docs/Map-Design.md` 用户修改。

清理前必须解析并验证目标位于项目根或已登记工作树内，并确认没有 Git 跟踪内容。Windows 优先移入系统回收站；只有运行环境允许且用户明确要求永久删除时，才在同一 PowerShell 进程内使用 `Remove-Item -LiteralPath`，不得把枚举结果拼接给另一 shell。

2026-08-23 的本轮清理及验证后复扫累计把 121 个可重建目标、26,321 个文件、合计 3,200,093,533 字节（2.980 GiB）移出工作区并放入 Windows 回收站。回收站清空前这些文件仍可恢复，磁盘可用空间也不保证立即增加；正式 V0.10.14 发行物与验收包不在回收范围内。

### 13.2 常见故障

| 表现 | 常见原因 | 诊断位置 | 恢复方式 |
| --- | --- | --- | --- |
| `/readyz` 非 ready | schema、配置、内容或服务初始化失败 | API stderr、`apps/api/main.py` lifespan | 先修复稳定错误，不删除数据库绕过 |
| 登录后回错页面 | 角色与原目标不兼容 | `authPolicy.test.ts`、`RouteGuards.tsx` | 使用 `principalLandingPath` 与兼容返回路径 |
| RAG 总是“依据不足” | 问题无课程信号、人物范围过窄、证据或索引异常 | `services/rag/retrieval.py`、回答中的 release/evidence checksum | 用建议追问验证；索引可重建，不能放宽证据边界补写 |
| 模型不可用 | provider/key/端点/超时或限流 | `/practice/llm/info`、脱敏日志 | 应自动退回确定性行动和抽取式回答 |
| 画板保存 409 | 另一页面写入了新 revision | Canvas API 与页面锁定提示 | 载入最新版本后再编辑，不覆盖胜者 |
| 课程能看但关卡/证据缺失 | V3 manifest 绑定不完整或制品损坏 | `content/releases/active/` 与 manifest | 回滚到上一不可变 release 或重新发布 |
| Windows 启动失败 | Python/Node 版本、端口、lock 或包不完整 | 启动器输出、`classroom-package-manifest.json` | 修正前置；不要删除或忽略 manifest 校验 |
| 教师启动器测试找不到 PowerShell cmdlet | PowerShell 7 的模块路径被 Python 原样传入 Windows PowerShell 5.1 | `PSModulePath`、`tests/test_teacher_launcher.py` | 按第 10.4 节取得 Windows PowerShell 自身模块路径后复跑 |
