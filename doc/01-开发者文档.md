## 1. 项目与系统定位

学生从课文进入情景，再追问依据，最后写出自己的判断。教师编写课文和资料，审校者审核，管理员发布；教师还可以批阅学生主动提交的笔记。

| 课堂阶段 | 用户看到的内容 | 本轮真实边界 |
| --- | --- | --- |
| 踏勘 / 看 | 教师正文、关键词批注、人物与地图点 | 46 课阅读已对齐；未与教师稿一致的旧短片不显示 |
| 抉择 / 练 | 有限回合、预设选择和自由输入 | 完整新引擎以旧双课为基线，其余仍有旧兼容内容 |
| 召见 / 问 | 学者或人物回复、可展开的依据 | 发布内 RAG 与人物包仅建设了旧双课 |
| 卷宗 / 创 | 正文、便签、手写、导图、轨迹与提交 | 工具已实现；自动材料仍取对应旧互动数据 |

“状态机拟合”不是训练一个语言模型，而是把已审校资料拆成可检索片段和答案槽，再用规则选择、组织回答。BGE 只把文本转换为用于搜索的向量。

## 2. 总体架构

下面是当前实现关系，箭头表示读取或调用：

```text
浏览器 React
  ├─ 学生：课程 / 练问创 / 学习书案
  ├─ 教师与审校：内容工作台 / 成果批阅
  └─ 管理员：账号 / 发布
                  │ HTTP + HttpOnly Cookie
                  ▼
FastAPI 路由：认证、输入校验、权限、错误响应
                  ▼
services 业务层
  ├─ courses ───────────→ textbooks 教师阅读 + 按教师名单选取的资料档案
  ├─ content ───────────→ 草稿、封存、审核、发布文件
  ├─ game_runtime ──────→ 确定性规则、回合、结局、卷宗
  ├─ rag / persona ─────→ 当前发布证据 → 本地回答或受限 API
  └─ learning_assets ───→ 学生提交版本、教师反馈
        │                  │
        ▼                  ▼
SQLite 学习与账号数据     JSON 内容事实 + 可重建 FTS/BGE 索引

浏览器本机：IndexedDB / localStorage 保存私人笔记
        └─ 学生明确提交后 → 后端学习成果；不是把笔记塞进 Cookie
```

路由只处理 HTTP 和身份；规则与存储由服务层负责。React 不决定用户归属、史实真值、回合变量或发布版本。课堂包由同一 FastAPI 端口提供网页与 API；开发环境用 Vite 代理 API。

### 2.1 三种容易混淆的数据

| 数据 | 权威位置 | 何时变化 |
| --- | --- | --- |
| 当前阅读目录与正文 | `content/textbooks/*.json` | 教师最新完整 PR 快照覆盖 |
| 互动课程、关卡、证据、人物与媒体 | `content/releases/active/` → manifest → `content/runtime/` | 走审校/封存/发布流程后切换指针 |
| 账号、进度、会话、已提交作品 | SQLite / PostgreSQL 数据库 | 用户在运行时操作 |

阅读目录只接受 textbooks；没有教师稿就返回不存在，不再回退旧正文。教师稿同时保存人物名单、地图点与来源。阅读人物从该名单按名称关联资产库，百科补充明确标注。独立的 interaction_people/interaction_figures、互动版本和规则引用仍用于练问创，前端进入这些功能时使用互动投影，不把新人物 ID 硬塞入旧人物包。

teacher_text_checksum 标识当前**单篇课文**及其教师标注，不包含 PR 元数据，也不因同分组其他课文改动而变化；既有 content_version/content_checksum 仍指互动课程制品，不能拿阅读指纹替代游戏 release pin。rag_available 独立表达证据问答能力，不再以有无短片判断 RAG 是否可用。旧制品只通过内部 get_interactive_lesson 读取，不作为学生阅读的兜底来源。

## 5. 入口与运行流程

### 5.1 第一次启动源码

在实际应用工作树根目录执行：

```powershell
py -3.11 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r apps/api/requirements.txt
npm --prefix apps/web ci
./scripts/classroom-review.ps1 -LexicalOnly
```

正常结果：网页 `http://127.0.0.1:5174`；API `http://127.0.0.1:8010`；`/healthz` 可读。已有环境不重复创建。脚本只启动服务，不承诺一个通用测试密码；账号创建规则见 5.3 和 `scripts/initialize_classroom.py --help`。

### 5.2 使用混合检索

```powershell
./.venv/Scripts/python.exe scripts/prepare_rag_model.py
./scripts/classroom-review.ps1
```

准备脚本下载固定模型并复核 SHA-256。默认启动先验证模型；仅检查课文或离线词法回退时使用 `-LexicalOnly`。开发启动器把 Web Origin 与 API 代理端口配对，避免 Cookie 写入被错误来源拒绝。不要随意另开端口然后关闭来源校验。

停止：`./scripts/stop-classroom-review.ps1`。自己的运行状态在 `.chronovita-review/`。

### 5.3 使用 Windows 课堂包

完整解压，安装 64 位 Python 3.11，双击“启动Chronovita课堂.cmd”。启动器从内置 wheelhouse 准备环境，空库安全提示创建管理员密码，再启动同源网页与 API。

默认 `127.0.0.1:8000`；显式执行 `./scripts/classroom.ps1 -Lan` 才监听 LAN。日常学生账号由管理员创建，不在包里预置。停止使用根目录关闭脚本。账号与学习数据保留在 `data/classroom/`，升级前先备份，不覆盖旧包数据目录。

### 5.4 一次请求怎样完成

登录写入 HttpOnly Cookie → 路由解析用户和角色 → 服务读取课文或互动发布 → 校验输入和版本 → 事务内保存 → 返回页面。失败时保留明确的 401、403、409 等错误，不以空成功结果吞掉问题。

## 6. 模块与功能实现

### 6.1 课文与独立档案同步

[课文同步脚本](../scripts/sync_teacher_course_snapshot.py)按课程读取 PR 的完整归档：检查 head、CI、课号集合和逐课 checksum；只提取目录与阅读字段；统一换行/空白，保留教师标注；写入 textbook 和教师草稿。

[读取层](../services/courses/textbooks.py)验证文件身份、重复课号与文本指纹；[课程服务](../services/courses/__init__.py)负责对外目录和正文覆盖。指纹不含 PR、commit、导出时间，因此相同文字不会被元数据变化误判为改稿。

历史内置正文已从课程模块删除；原有练问创的种子节点与兼容字段单独位于 legacy_interactions.json，不含旧正文，也不产生课程入口。旧视频仅当其发布课程的标题、摘要、正文与关键词均匹配教师稿时才允许作为阅读媒体返回。教师工作台的 source-lessons 入口也只列当前教师课文。

[档案脚本](../scripts/sync_named_assets.py)按规范化名称归并，而不是用可能复用的旧 ID。相同姓名采用最新稿并复用本地 ID；唯一别名可修正课时关联；不确定项保留待关联。它只写教师资产库，不自动生成 NPC 人物包。

用户本地 ZIP 使用同一脚本的 `--archives <ZIP路径...> --checkout <来源仓库>`；默认预检，添加 `--apply` 才写入。只读取 JSON，不解压或执行文件。重复附件合并关联与来源，正文冲突直接停止；真实但缺稿的课号保留并登记，不拿旧 ID 猜测身份。

### 6.2 审校与互动发布

教师草稿可修改；封存件不可改。互动发布的 `course-release/v5` 同时绑定课程包、关卡、证据、展示和人物包的精确版本与 checksum；V1—V4 继续可读。

当前活动发布事实在[活动指针](../content/releases/active/C-prequin-state.json)，不是手册里的复制哈希。教师不能自己批准自己的稿件，审校者不能发布。需要更新互动内容时走 `services/content/workflow.py` 及对应 evidence/persona 发布工具，不直接编辑 runtime JSON。

**课文覆盖是独立流程，不要求重新发布上述互动制品。**

### 6.3 情景推演

`services/game_runtime/` 以固定行动和确定性规则推进有限回合。自由输入先通过 `action_fit.py` 匹配当前允许的行动；明确命中走本地，含糊输入才可能交由 API 分类，离题或注入不推进。

规则先计算变量、事件和结局，`dialogue.py` 再生成具名 NPC 表达。模型不能更换人物、改变规则结果或伪造引用。保存通过 revision（并发版本）和请求 ID 保证单次推进，重复请求不多扣一个回合。最终卷宗由真实回合派生。

### 6.4 问答与人物会话

```text
学生原问
  → 识别意图与安全边界
  → 限定当前课时、发布、人物
  → FTS / 可选 BGE 检索 → RRF 合并候选
  → 检查答案槽与证据覆盖
      ├─ 简单且有依据：本地组织
      ├─ 充分命中的复杂问题：受限 API
      ├─ 课内但含糊或缺材料：澄清
      └─ 离题、注入或不支持：拒答
```

入口为 `services/rag/query.py`、`retrieval.py`、`local_reply.py`、`routing.py`、`service.py`。`EvidenceCorpusV2` 保存片段、来源、答案槽与知识边界；索引是缓存，不是史实库。

当前 V2 问答在 L101 已支持证据约束下的模型正文生成：模型只能选择召回片段并改写成短答，服务端校验 passage、人物边界和引用后才返回；模型不可引用召回范围外的材料。NPC 对话有独立受限润色适配器，练习分类、RAG 回答和 NPC 润色都可在在线模型不可用时退回确定性结果。

`PersonaPackV1` 是审校后的表达合同，与普通人物档案不同。`services/persona_conversation/` 把会话锁定到用户、课程、发布和人物；最多 24 轮、最近 6 轮用于连贯性。旧回答不能变成新证据。发布变化或版本冲突要求重读或新建会话。

### 6.5 学习书案与教师反馈

`learningLedger.ts` 记录阶段进入、关键词、抉择、回答和笔记事件；按用户、课程、课时隔离。本地书案支持受限 Markdown/富文本、便签、归一化笔迹和导图。

本机保存与提交给教师是两件事。提交时 `services/learning_assets/` 冻结作品及画板快照，产生不可变版本；网络重试使用同一幂等 ID。教师只看已提交版本并追加反馈，不能覆盖学生原稿。未提交笔记清理浏览器数据后可能丢失。

### 6.6 认证与持久化

`services/auth/` 管理四角色、会话到期、禁用、撤销和审计。浏览器不在 localStorage 存 token。Cookie 认证的写请求必须来自可信 Origin。

`services/persistence/` 提供数据库迁移和事务。当前 schema v6 包含人物会话与情景对话；版本以迁移代码为准。本地可 `apply-safe`，生产档只能 `validate`。部分旧 Saga/限流仍为进程内状态，不支持多副本；PostgreSQL 测试不等于已具备生产灾备。

### 6.7 个人中心与阅读进度

使用者：进入“个人中心”，编辑资料后点“保存修改”；“阅读偏好”可选标准或大字；“账号与数据”可改密、导出资料、退出所有设备。邮箱只是可选联系方式，未经验证，不用于找回密码。退出请求失败会留在当前页面并提示重试，不伪装退出成功。

资料入口为 [ProfilePage](../apps/web/src/pages/ProfilePage.tsx) → [profile 路由](../apps/api/routers/profile.py) → [资料服务](../services/auth/profile.py) → [AuthStore](../services/auth/store.py)。昵称仍以账号表为唯一来源；其余资料复用 KV 的 account_profile 命名空间，以服务端用户 ID 隔离。资料与昵称在同一事务保存，revision 拒绝陈旧覆盖；管理员改昵称也会推进该版本。头像校验后缩为最多 256 像素的 WebP，不保留上传元数据。改密验证当前密码，复用原密码策略、审计及会话撤销逻辑，无新认证路径。

阅读记录的语义如下，**不推断学习时长、分数或知识掌握程度**：

| 情况 | 页面表达 | 计入当前已读 |
| --- | --- | --- |
| 仅打开课文 | 已开始阅读 | 否 |
| 点击“我已读完这篇课文”，服务端确认当前指纹 | 已确认读完 | 是 |
| 课文更新，确认指纹不再匹配 | 课文已更新 | 否，需重新阅读确认 |
| 旧记录没有课文指纹 | 旧记录待核对 | 否，保留原记录 |
| 课号已撤下 | 课时已撤下 | 否，也不作为首页续学入口 |

实现入口：[learning 路由](../apps/api/routers/learning.py)、[readingProgress](../apps/web/src/features/classroom/readingProgress.ts)、[逐课指纹](../services/courses/textbooks.py)。首页、路线、课时页与“我的学习”共用同一语义；确认失败可重试，刷新后从后端回读。旧练问创完成标记保留为历史活动，不再换算成虚假的四阶段完成率。

课程搜索匹配教师题目、摘要、人物名和关键词；空格分词需全部命中。地图方向键只移动地图，时间轴获得焦点后才响应切换时代的方向键。Pages 不创建个人账号和学习进度。

### 6.8 管理员统一 API 配置与学习记录显示

管理员访问 `/admin/api-config`，配置提供方、API 地址、快速模型、高质量模型和思考模式；密钥写入 `runtime_config/llm` KV 记录，只返回是否配置和末四位。启动时由 [配置服务](../services/operations/api_config.py) 载入，保存后新建的 RAG、流式问答、练习分类和 NPC 润色适配器读取新配置；游戏运行时用配置指纹重建缓存适配器。Pages 没有此入口，也不承载密钥。

学习页将 `/learning/progress` 返回的 `unavailable` 记录从当前课号、标签数量和课程卡片中排除，另以历史课号提示展示；`total_lessons` 始终来自当前教师课表。当前课文的 `completed` 仍只由教师文本指纹和已读确认共同决定。

### 6.9 L101 大禹治水互动链路

“练”使用 `/practice/game/sessions/{id}/free-input`。固定行动不调用模型；自然语言先由 [action_fit](../services/game_runtime/action_fit.py) 处理，明确命中直接结算，涉及“召集百姓、商议方案”等自然表达时交给 [ActionClassifierV1](../services/ai/classifier.py)，模型只能从当前回合的 `available_actions` 中选择 action_id，规则引擎仍独占变量、事件与结局。分类器使用结构化 DeepSeek，超时或格式错误退回固定行动提示，不写入错误回合。

“问”和随行助教共用 `/practice/ask/rag`。查询先绑定 L101 的发布、人物和证据库，再以 FTS/BGE 召回；通过人物槽位、问题关系和证据置信度后，在线模型在召回片段中选择并生成不超过课堂需要的回答。`RagAnswerV1` 返回引用片段、证据 checksum、发布号和不确定性；没有足够材料时拒答。人物模式会再按 PersonaPack 的 `focus_answer_slot_ids` 和 `evidence_uses` 收窄，禹的“治水策略”只允许使用“鲧堵禹疏与组合治理”槽位。

课堂在线启动需使用 [start-online.ps1](../.chronovita-review/start-online.ps1)，不加 `-LexicalOnly`，并确保本机忽略配置中的 `CHRONO_LLM_PROVIDER=deepseek` 与 API key。无 API 或断网时，练的固定行动、问的抽取式回答、助教的确定性边界回答仍可用；在线 API 不改变规则和证据事实源。

## 9. 配置与环境

全部配置在 [settings.py](../apps/api/settings.py)，以 `CHRONO_` 开头。API key 只放本机环境变量或未跟踪的配置，严禁进入提交、日志、截图或 ZIP。

| 配置 | 用途 |
| --- | --- |

## 10. 开发与运行操作

### 10.1 定向和完整验证

```powershell
./.venv/Scripts/python.exe -m pytest tests/test_textbook_sync.py tests/test_named_asset_sync.py -q
npm --prefix apps/web test
npm --prefix apps/web run build
./.venv/Scripts/python.exe scripts/check_project_docs.py
git diff --check
```

阶段收束扩大到后端全量与发行验证。Windows PowerShell 测试若受 PowerShell 7 模块路径影响，按 13 节先隔离环境，不修改测试预期掩盖问题。

### 10.2 Windows 包的构建顺序

先测试并生成 `apps/web/dist`，准备固定模型与 `distribution/wheelhouse/windows-py311`，再提交源码。打包器**不自动执行前端构建**，它把已有 dist 和指定提交的源码封装。

```powershell
$releaseCommit = git rev-parse HEAD
$releaseVersion = (& ./.venv/Scripts/python.exe -c 'from services.version import APP_VERSION; print(APP_VERSION)').Trim()
./.venv/Scripts/python.exe scripts/build_classroom_release.py build --source-root . --output-dir "data/release-artifacts/v$releaseVersion" --version $releaseVersion --commit $releaseCommit
./.venv/Scripts/python.exe scripts/build_classroom_release.py verify --archive "data/release-artifacts/v$releaseVersion/Chronovita-Classroom-v$releaseVersion-windows.zip"
```

新解压目录做独立冷启动；不要用开发数据库证明包体成功。发布资产为 ZIP、SHA-256、许可清单；实际 commit 和文件哈希分别由包 manifest 与 sidecar 提供。GitHub Release 使用预发布标识，不把已知未适配课程写成完整课堂。

### 10.3 Pages 与课堂包不同

`scripts/build_pages_preview.py` 生成静态数据；`npm --prefix apps/web run build:pages` 生成只读 Hash 路由站点。它不提供真实账户、问答或保存。

Pages 构建会替换 dist，不得与依赖该目录的浏览器测试同时执行；打课堂包前必须重新执行普通 `npm run build`。V1.1.2 已按用户要求把 Pages 工作流接到 `codex/v1-agent-routing`，推送后部署教师阅读数据。工作流入口分别是 `pages-preview.yml` 和 `classroom-release.yml`。

## 11. 修改与扩展指南

### 11.1 只同步教师课文

先读[课文同步 Skill](../skills/ke-wen-tong-bu/SKILL.md)和[台账](04-课程同步台账.md)，取得 PR 精确 head，然后执行现有脚本。检查缺课是否明确，再 apply。教师草稿和学生正文一致、展示正常后更新台账并关闭 PR。人物、视频或练问创不同只登记，不自动开发。

### 11.2 修改真实互动内容

修改 `services/content/flagships/` 中相应作者源及契约，更新证据/答案槽/人物/关卡，走审校、封存和联合发布。先明确新旧课号迁移方案，不能仅换界面标题。旧学习记录和旧 release 保持可追溯。

### 11.3 修改 API 或页面

业务放 services，路由只做接线；前端统一经 `utils/api.ts` 调用，在 `App.tsx` 配置角色守卫。测试成功路径以及越权、冲突、网络失败和刷新恢复。不要添加重复权威状态。

### 11.4 修改 RAG

检索、路由或人物知识范围变化，要跑对应检索基准与不支持问题反例。每条引用必须属于当前发布和本轮召回；API 失败需保留本地回答。不能靠降低拒答门槛或模型常识填洞来“提高命中率”。

## 13. 维护与故障排查

| 现象 | 先检查 | 不要这样处理 |
| --- | --- | --- |
| 新课文没出现 | textbook 来源与指纹、实际服务工作树、Pages 是否重建 | 盲目新建 release |
| 课文与人物/游戏不同 | 同步台账的尚未适配项 | 宣称所有模块同步完成 |
| 401 / 403 | Cookie、账号角色、目标页面 | 改成全局免登录 |
| Cookie 写入被拒 | 启动端口、代理、可信 Origin | 关闭来源保护 |
| RAG 依据不足 | 问题所属课、活动证据、人物范围、索引 | 让模型编造证据 |
| 保存或推进 409 | revision 与幂等 ID | 覆盖服务器最新记录 |
| 包体启动失败 | Python 3.11、端口、manifest、日志 | 删除用户数据库重试 |
| PowerShell 测试找不到 cmdlet | 子进程 PSModulePath 是否串入 PS7 模块 | 把测试改成恒成功 |

必要时先取得 Windows PowerShell 自身模块路径：

```powershell
$winModulePath = & powershell.exe -NoProfile -NonInteractive -Command '$env:PSModulePath'
$env:PSModulePath = $winModulePath.Trim()
```

数据库维护入口为 `scripts/manage_database.py`。更新前先备份并验证，回滚代码用新提交，回滚内容移动活动指针。清理只处理明确的可重建产物，不碰封存件、发布媒体、数据库、用户修改和旧根工作树。
