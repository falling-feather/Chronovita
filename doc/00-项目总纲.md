## 0. 一句话定位

Chronovita 是面向七年级历史课堂、学期作品和比赛展示的学习平台：让学生读材料、作选择、问依据，再把学习过程整理为自己的笔记。V1.1.4 在真实阅读进度基础上，完成 **L101 大禹治水的在线练问与助教链路**；其他课程互动继续按发布状态区分。

## 1. 产品与角色

学生的课堂分成四步：

1. **踏勘（看）**：读课文、点开关键词解释、看地图与已有导读短片。
2. **抉择（练）**：在历史情景中选择预设行动或输入自己的方案。
3. **召见（问）**：与课程学者或人物交流，回答必须有本课资料支持。
4. **卷宗（创）**：整理选择和依据，打字、画图、记笔记，再按需提交给教师。

教师编辑内容、查看已提交成果并反馈；审校者审核内容；管理员管理账号和发布。四种角色共用登录入口，但权限不同。

“可观察、可干预、可反馈、可复盘”是产品目标，不代表目录中的每一课都已经完成四阶段内容。

## 3. 技术路线

系统分三层，而不是前端直接调用任意模型：

```text
浏览器：学生课堂 / 教师编辑器 / 管理界面
                    ↓ 受权限控制的 API
FastAPI：内容读取 / 游戏规则 / 问答路由 / 学习成果
                    ↓
JSON 内容文件 + SQLite 学习数据 + 可重建检索缓存
                    ↘ 可选在线模型 API
```

- **内容**：教师 PR 是新课文来源；课文快照与互动发布各有生命周期。
- **互动**：规则引擎决定回合、变量和结局；模型只能在允许范围内理解或表达。
- **问答**：本地状态机与资料匹配优先；充分命中且需要综合的问题才考虑 API；不支持的问题澄清或拒答。
- **保存**：私人笔记先存在浏览器；学生明确提交后才成为教师可见的版本。
- **离线**：基础课堂不强制依赖在线生成模型。向量模型缺失时可使用 FTS 词法检索。

具体架构、数据归属和修改入口见[开发者手册](01-开发者文档.md)。

## 4. 交付与边界

| 形态 | 用途 | 不包含的承诺 |
| --- | --- | --- |
| 源码仓库 | 开发、测试、内容维护 | 推送分支不等于合入 main |
| Windows 课堂 ZIP | 本机或可信 LAN，单端口，首次创建管理员 | 不含默认密码，不代表公网 TLS、多校租户或灾备 |
| GitHub Pages | 无后端的目录与课文展示 | 无登录、真实 RAG、游戏写入或笔记上传 |

V1.1.1 Windows 预发布包保持不变。本轮 V1.1.4 提交并推送源码，Pages 随分支部署但仍只读；L101 的在线练问和助教需使用本地课堂后端与有效 API 配置。实际提交、验证和远端状态见[开发历史](03-开发历史.md#0-当前版本与记录口径)。
