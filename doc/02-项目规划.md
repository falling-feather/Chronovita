# Chronovita — 项目规划

> **文档梗概**：记录 V1.0 当前目标、尚未完成的任务、依赖关系和验收门槛；当前稳定实现见[01-开发者文档](01-开发者文档.md)，已发生提交见[03-开发历史](03-开发历史.md)。
>
> **具体规划法则**：
>
> 1. 每项任务只写需要交付的结果和可复核验收，不在此复制详细技术手册。
> 2. 一次提交只对应一个任务编号和一个独立小版本；小版本由项目负责人明确安排后执行。
> 3. 模型和 API 都不得绕过当前发布证据、人物边界和确定性游戏规则。
>
> **最后一次更新时间**：2026-08-31
>
> **更新者**：项目统筹组

## 0. 当前结论

`V1.0.0` 已把 `V0.10.32 / 55d6eec` 收束为新阶段开发基线。V1.0 的首选路线是“本地状态机拟合 + 受证据约束 API”：高置信问题在本机按审校槽位组织，证据充分的复杂问题才调用 API，课内但证据不足时澄清，主题无关、伪前提、提示注入或极低命中时拒答。轻量生成模型 + API 是次优可插拔路线，不是核心课堂包依赖。

当前运行代码仍是发布内 FTS5/BGE/RRF 检索、可选 DeepSeek 生成和抽取式回退；上述新路由尚未实现，必须通过下列任务逐步接入。

此前 V0.10 规划中的 `ACCEPT-001` 未执行，随阶段切换由 `QA-006` 重新定义验收；待办 `REL-001` 未形成提交且与 V0.9.25 历史编号冲突，V1.0 的实际集成发行改用未占用的 `REL-003`。

## 2. 实施顺序

1. `AI-005` 先冻结路由状态、回答槽位和拒答边界。
2. `DATA-002` 与 `CONTENT-003` 按该合同扩充两课证据和人物表达。
3. `BE-010`、`GAME-003` 接通真实服务与模拟对话。
4. `QA-006` 完成正负样本和课堂验收；确有必要时才恢复 `AI-006`。
5. `REL-003` 最后执行集成与发行。

## 3. 发布门槛

- 高置信简单问题在本机完成，不依赖外部模型。
- API 只接收当前发布、当前召回、证据充分的问题；失败后仍能完成课堂。
- 主题无关、伪前提、注入和依据极低问题不得产生历史答案或伪造引用。
- NPC 语言与事实分离；模型不得写变量、事件、轮次或结局。
- L101/L103 证据、人物、路由、页面和发行包 checksum 一致。

## 4. 本阶段不做

- 不把约 8—10B 模型塞进基础课堂包；只有 `AI-006` 验证后才提供独立增强包。
- 不用 API 或模型常识弥补证据库缺口。
- 不扩展其余 46 课的正式语料，先证明双课管线可复用。
- 不建设公网、多学校、多副本、灾备、生产 TLS、PDF/OCR 或互联网实时检索。
