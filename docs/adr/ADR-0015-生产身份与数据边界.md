# ADR-0015 生产身份、角色权限与数据归属边界

- 状态：接受
- 日期：2026-07-16
- 目标版本：V0.9.x
- 决策人：核心开发组 / 系统架构组

## 背景

V0.8.x 已经打通内容生产、联合发布、学生关卡、史官卷宗和知识画板，但当前身份仍是开发期占位：管理员接口共享一个 `CHRONO_ADMIN_TOKEN`，游戏会话使用固定 `CHRONO_GAME_USER_ID`，学习进度固定为 `default`，画板只按 `lesson_id` 寻址。上述方式适合单机演示，不满足多人试用和生产部署：共享凭证无法区分操作者，学生资源存在横向读取风险，审校与发布日志也不能形成可信审计。

V0.9.x 的目标不是扩写正式课程、建设班级作业系统或补齐 RAG，而是先建立后续所有生产能力都必须依赖的身份与数据边界。

## 决策

### 1. 认证主体是唯一身份来源

后端建立统一 `Principal`，最低包含稳定 `user_id`、显示名、启用状态、角色集合、当前 `session_id` 和认证版本。业务路由只从认证依赖取得主体；请求体、查询参数、前端缓存和旧的 `actor/sealed_by/user_id` 字段均不得决定审计身份或资源归属。

账号密码使用带版本和参数的内存困难哈希，首版采用标准库 `scrypt`、随机盐和常量时间校验。登录成功签发至少 256 bit 的不透明随机会话令牌，数据库只保存令牌的 SHA-256 摘要、用户、创建时间、绝对过期时间、最后使用时间和撤销时间，不保存可重放明文。

浏览器默认使用 `HttpOnly`、`SameSite=Lax` 会话 Cookie；生产环境必须启用 `Secure`。非浏览器客户端可使用同一不透明令牌的 `Authorization: Bearer` 形式。登出、禁用用户、修改密码和管理员显式撤销都必须使相关会话失效。

### 2. 角色不代表隐式继承，权限按动作显式判断

首版固定四个角色：

| 角色 | 允许的核心动作 |
| --- | --- |
| `student` | 读取公开课程；读写自己的学习进度、游戏会话、卷宗和画板 |
| `teacher` | 读取内容工作区；创建、保存、校验和提交自己的课程/关卡草稿；读取获授权的学生摘要 |
| `reviewer` | 读取内容工作区；退回或批准待审草稿；读取审校相关审计 |
| `admin` | 用户与角色管理；封存、发布、回滚、运行制品登记；读取全量审计 |

管理员拥有的每项权限仍在策略表中显式列出，不通过“角色级别大于某值”推导。一个用户可以具有多个角色，接口依赖检查的是动作权限而非前端页面名称。

内容写入权限至少拆成以下边界：

| 动作 | 权限 |
| --- | --- |
| 内容模板、草稿、工作流和封存件只读 | `teacher`、`reviewer`、`admin` |
| 草稿保存、校验、提交审校、关卡作者草稿 | `teacher`、`admin` |
| 审校通过或退回 | `reviewer`、`admin` |
| 封存、运行制品登记、发布、回滚、旧版本迁移 | `admin` |
| 用户、角色和会话撤销管理 | `admin` |

### 3. 学生资源必须校验所有权

学习进度、游戏会话、卷宗和知识画板的存储键必须包含认证 `user_id`，所有读取和写入都在服务端核对所有者。学生接口不得接收可改变归属的 `user_id`；猜中其他人的 `session_id`、`lesson_id` 或 `dossier_id` 也不能越权读取。

跨用户精确资源访问统一返回不泄露存在性的 `404`。教师读取学生摘要必须走独立权限和后续课程分配边界，不能复用学生资源接口；在班级与分配模型尚未落地前，不开放学生全量列表。

旧单用户数据不得静默归给第一个登录用户。开发模式可以通过显式迁移命令映射到指定账号；生产模式发现未映射旧数据时失败关闭并报告迁移需求。

### 4. 审计记录不可由业务请求伪造

审校、封存、发布、回滚、账号与角色变更、会话撤销以及高价值学生摘要读取都写入结构化审计事件。事件最低包含：

- `event_id`、事件版本和 UTC 时间；
- 认证 `actor_user_id`、角色快照和认证会话 ID；
- 动作、资源类型、稳定资源 ID 和结果；
- 请求关联 ID、客户端地址摘要和允许列表内的业务元数据；
- 前一事件摘要与当前事件摘要，用于发现离线篡改。

审计事件只允许追加，不提供普通更新或删除接口。请求体中的旧 `actor` 和 `sealed_by` 仅作为兼容输入被忽略，并在合同升级后移除。

### 5. 本地兼容模式与生产模式严格分离

一键教师编辑器可以继续使用显式 `legacy-local` 模式和启动时随机 token，前提是 `debug=true`、只绑定回环地址且响应明确标注为开发身份。该模式不能创建可冒充真实用户的审计历史。

生产模式固定为 `accounts`：共享管理员 token、固定游戏用户、默认学习用户或未迁移画板任一存在时均不得宣称生产就绪。生产启动还必须校验非默认密钥、精确 CORS、Cookie 安全属性和数据库迁移版本。

### 6. 持久化和迁移先建立稳定边界

V0.9.x 保留 SQLite 作为离线教师编辑和自动化测试后端，同时引入显式 schema 版本与顺序迁移；账号、会话、审计和资源所有权使用可被 Postgres 实现的 SQLAlchemy Core 模型，不新增仅 SQLite 可表达的业务语义。

数据库升级、备份和恢复必须是显式命令并可在副本上验证。应用启动只允许执行已登记的安全迁移或拒绝启动，不能依靠 `create_all()` 静默猜测生产结构。

### 7. 稳定失败语义

- 未携带或失效认证返回 `401`，并使用稳定 `authentication_required` / `session_expired` 代码。
- 已认证但缺少动作权限返回 `403 permission_denied`。
- 跨用户资源、未知资源和不可见资源统一返回 `404 resource_not_found`。
- 认证存储、审计写入或迁移状态不可用时失败关闭，不降级为共享 token。
- 登录失败信息不区分账号不存在与密码错误；速率限制和锁定策略由 `OPS-001` 接续。

## 实施顺序

1. `BE-003` 建立账号、会话、权限策略与审计，并替换内容工作流的共享身份。
2. `BE-005` 将学习进度、游戏会话、卷宗和画板绑定认证主体，提供显式旧数据迁移。
3. `DATA-001` 建立 schema 版本、迁移、备份恢复和 Postgres 兼容路径。
4. `OPS-001` 收紧生产配置、健康检查、结构化日志、限流和部署检查。
5. `QA-001` 与 `SEC-001` 完成异常矩阵、CI 门禁、权限绕过和数据隔离 review。

## 验收反例

- 教师不能批准自己的待审内容，审校者不能发布，学生不能访问任何管理写接口。
- 请求体伪造 `actor`、`sealed_by` 或 `user_id` 不改变审计主体和资源所有者。
- 撤销、过期、禁用账号和密码变更后的旧会话全部失效。
- 学生 A 猜中学生 B 的会话、卷宗、课时和画板标识仍无法读取或覆盖。
- 审计写入失败时对应高价值写操作不提交；并发角色变更和发布不会产生身份漂移。
- `legacy-local` 配置在生产模式、非回环部署或关闭 debug 时拒绝启动。

## 后果

正面影响：内容审校和发布可以追溯到真实操作者；学生学习资产具备明确所有权；后续班级、作业、学情分析和 Postgres 迁移拥有稳定身份主键。

代价与限制：前端需要增加登录与会话失效处理；现有单用户数据必须显式迁移；认证和审计写入会增加数据库事务与测试矩阵；V0.9.x 仍不等于完整学校租户系统。
