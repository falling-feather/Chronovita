# ADR-0012 看练问创闭环与史实护栏

- 状态：接受
- 日期：2026-07-15
- 决策人：核心开发组
- 计划版本：V0.8.x（具体补丁版本待项目负责人收口确认）

## 背景

V1 历史局势引擎已经能够从 sealed 课程包和关卡模板确定性推进状态、事件、NPC 和结局，但当前游戏回合接口要求客户端同时提交 `action_id`、`action_source` 与归类置信度。若把自由文本和客户端声明的行动直接交给引擎，客户端或模型就可能绕过“当前可用行动”与史实边界。

现有 saga 和 ask 可以继续作为兼容体验，但其自由文本和 `[META]` 结果不属于 V1 规则权威来源，也不能作为 AI-001 的完成证据。AI-001 需要在不引入完整 RAG 或通用智能体的前提下，建立可离线验证、可回退、可重放的最小编排层。

## 决策

### 1. 服务端拥有行动归类权

- 固定行动接口继续只接受明确的 `client_action_id`、`action_id` 和 `expected_revision`，服务端请求模型拒绝客户端提交的 `raw_input`、`action_source` 和置信度声明。
- 自由输入使用独立解析入口，只接受 `client_action_id`、`raw_input` 和 `expected_revision`。客户端不能提交候选 `action_id`。
- 服务端先尝试稳定 ID、标题和 alias 的精确解析；只有无法精确解析时才调用结构化分类器。
- 分类器只能返回当前回合可用行动之一、澄清或拒绝。未知/不可用行动、低置信度、越时代、facts 冲突、提示注入、输出结构错误或供应商异常均不创建 Turn、不改变 revision。

### 2. 规则先结算，模型后叙事

- 分类成功后，`SituationEngineV1` 是状态差、事件、NPC 变化、节点迁移和结局的唯一生产者。
- 叙事器只读取不可变的规则结算投影、允许的 facts/source_refs 和人物 persona/boundaries。
- 叙事输出只包含有限长度文本及实际使用的 fact/source ID。模型输出中出现状态、效果、事件、NPC 数值、结局或下一行动即判为非法。
- 叙事器失败时使用 `render_rule_narrative()` 的确定性文本，已经合法结算的回合仍可提交。

### 3. 严格结构化适配

- 在 `services/llm/` 增加非流式结构化完成入口；业务层只依赖适配器，不直接拼 HTTP。
- 请求明确启用 JSON 对象输出，并在 prompt 中要求只返回 JSON；响应先执行字节、token 和超时限制，再用 `extra="forbid"` 的 Pydantic 模型校验。
- 供应商异常统一转换为稳定内部原因码，不向学生返回 HTTP body、网络异常文本、prompt、密钥或模型思维链。
- 无 key、超时、限流、空/截断 JSON 与 HTTP 失败都由可编程离线 fake 覆盖；CI 不调用真实供应商。

### 4. 固定发布快照与并发边界

- AI 上下文从会话已经固定的课程/关卡版本与 checksum 读取，不重新读取“当前最新”课程。
- 模型调用在数据库写锁和事务外执行。调用前固定 `session_id + expected_revision + ruleset_hash`，提交时继续使用既有 revision CAS。
- 模型返回期间 revision 已变化时返回冲突，不自动用新状态重新归类，也不重复扣除或推进回合。
- 同一幂等 ID 和相同的已提交输入返回既有回合结果；不同输入复用同一 ID 仍冲突。分类拒绝/澄清结果可短期返回，但不伪造 Turn，也不承诺跨重启保存零写入结果回执。
- CAS 保证同一 revision 只有一次状态提交，不保证竞争请求在提交前只发生一次供应商调用。避免重复计费需要后续增加持久化请求租约或结果缓存；AI-001 的正确性验收以“不重复推进状态”为边界。

### 5. 回放不依赖供应商

- Turn 保存归类来源、置信度、叙事来源、provider/model、prompt policy 版本、允许引用 ID、稳定回退原因和规范化输出 checksum；不保存思维链。
- `RuntimeBundleV1` 继续重新推导全部规则字段，并额外验证 AI 元数据结构、规则依据哈希、输出 checksum 与引用白名单。结构错误、局部篡改和跨字段不一致必须失败关闭。
- 重启恢复和 replay 只使用固定制品与持久化回合，不再次调用模型。
- 由于模型文本无法像规则结果一样离线重新生成，当前 checksum 不能防御拥有数据库写权限并能重算整个叙事信封的攻击者。生产环境若要求覆盖该威胁，必须另建安全任务并使用数据库之外的 HMAC/签名密钥；本 ADR 不把 checksum 描述成数字签名。

## API 结果语义

自由输入解析结果使用带 `kind` 的可判别结构：

| `kind` | 含义 | 状态变化 |
| --- | --- | --- |
| `advanced` | 已映射到可用行动并由规则引擎提交回合 | revision 增加 1 |
| `clarification_required` | 含义不清或置信度不足，返回简短澄清和可用行动 | 不变 |
| `rejected` | 越时代、facts 冲突、提示注入或明确越权请求 | 不变 |
| `provider_unavailable` | 分类服务不可用，提示改用固定行动 | 不变 |

固定行动仍直接返回 `AdvanceResultV1`。自由输入入口只有 `advanced` 分支包含该结果，其他分支不得伪造 session 或 turn。

截至 2026-07-15，固定/自由输入接口分离、分类前后 revision 校验、跨服务 CAS 单赢家、幂等恢复和零写入失败分支已经实现。规则结算后的受限叙事、严格分类/叙事持久元数据、旧信封兼容迁移和不调用供应商的离线回放仍在 `AI-001` 后续范围内。

## 后果

正面：

- 模型和客户端都不能越权修改局势，所有规则结果仍可确定性回放。
- 无网络、无 key 或供应商失败时固定行动仍可完整上课，叙事失败也有规则文本。
- facts、资料与人物边界成为显式白名单，能够被测试、审校和审计。

负面：

- 自由输入需要一次或两次模型调用，延迟高于固定按钮。
- 分类拒绝不形成 Turn，若后续需要分析学生误区，应另建非权威遥测任务，不能污染游戏会话。
- 当前不提供开放领域问答和 RAG；超出课程包的历史问题仍需走兼容 ask 或明确提示范围。
- 并发请求可能在 CAS 决出唯一提交前产生重复供应商调用；这影响成本但不影响状态唯一性，后续可由持久化请求租约治理。

## 被拒绝的方案

- **让模型直接生成 effects 或下一状态**：无法由规则重放，拒绝。
- **让前端先猜 action_id 再提交置信度**：客户端可绕过权威边界，拒绝。
- **模型失败时随机选择最接近行动**：会在不确定输入下推进不可逆状态，拒绝。
- **回放时重新调用模型以复现文本**：供应商和模型版本不可固定，拒绝。
- **本阶段引入向量库和全量 RAG**：超出 AI-001 范围，待资料审校与真实权限任务稳定后另行认领。
