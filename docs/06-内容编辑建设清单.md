## 2. 需要编辑的内容对象

内容编辑不只包括课文正文。当前应维护六类对象：

| 对象 | 目标 | 最低字段 |
| --- | --- | --- |
| 课程内容包 | 让一节课可读、可预览、可封存、可进入课程页 | `lesson_id`、`course_id`、`title`、`unit`、`era`、`body`、`keywords`、`people`、`facts`、`source_refs` |
| 人物档案 | 为人物卡片、AI 人物智能体、课堂问答提供统一资料 | `asset_id`、`name`、`role`、`summary`、`persona`、`boundaries`、`related_lessons` |
| 关键词档案 | 统一课程内外的概念解释，避免同一词多种说法 | `asset_id`、`word`、`gloss`、`category`、`examples`、`related_people`、`related_lessons` |
| 地图点与时空信息 | 支撑“看”层地图、路线、空间比较 | `label`、`region`、`note`、`kind`，坐标可后补 |
| 参考资料 | 支撑史实审校、RAG、教师复核 | `title`、`source`、`url_or_path`、`citation_note`、`reliability` |
| 历史局势关卡 | 把课程 facts、人物与资料编排成可执行抉择 | `scenario_id`、课程/课时、变量、行动、事件、结局、`fact_refs`、`source_ref_ids`、卷宗提示 |

| CE-02 | P0 | 打磨 9 节 P0 主线课程 | 每节至少 3 段正文、5 个关键词、2 个人物、5 条 facts、2 条 qa_points、1 条 level_goal |

## 4. 建议推进顺序

1. 先把样板课“洋务运动的探索”作为黄金样板复核一遍，确认字段、导出文件和预览效果都符合教师预期。
2. 用“已有课程初稿”导入 P0 主线课程，逐节补正文、关键词、人物、资料和 AI 预留字段。
3. 每完成 1 节课，同步补它的人物档案和关键词档案，避免课程正文先行、资料资产滞后。
4. 每完成 3 节课，做一次审校小批次：检查史实、导出文件名、封存版本和课程页展示。
5. P0 主线稳定后，再扩展到 48 节已实装课程。

## 5. 文件与命名规则

| 内容 | 保存位置 | 导出命名 |
| --- | --- | --- |
| 课程草稿 | `content/drafts/{lesson_id}.json` | `课程标题.json`、`课程标题-格式层.json`、`课程标题-预览.html`、`课程标题-教师稿.md` |
| 封存课程 | `content/sealed/{lesson_id}-vNNN.json` | 同课程标题导出 |
| 审校记录 | `content/workflows/{lesson_id}.json` | 不单独导出；随仓库或后续 CMS 审计保存 |
| V1 发布制品 | `content/packages/v1/{lesson_id}-vNNN.json` | 由发布动作生成，不手工改写 |
| V2 课程制品 | `content/runtime/v1/course-packages/{course_id}/{lesson_id}/vNNN-{checksum}.json` | 发布时按精确关卡引用生成，不手工改写 |
| 关卡作者草稿 | `content/scenario-drafts/{scenario_id}.json` | `关卡标题-关卡草稿.json` |
| sealed 关卡制品 | `content/runtime/v1/scenarios/{course_id}/{lesson_id}/{scenario_id}/vNNN-{checksum}.json` | `关卡标题-关卡封存-vNNN.json`；仅文件存在不表示 published |
| 课程发布清单 | `content/releases/manifests/{course_id}/{release_id}.json` | 由发布或回滚生成；active pointer 决定学生可见版本 |
| 人物档案 | `content/assets/people/{asset_id}.json` | `人物姓名-人物档案.json` |
| 关键词档案 | `content/assets/keywords/{asset_id}.json` | `关键词-关键词档案.json` |

`lesson_id` 和 `asset_id` 仍使用英文、数字、点、下划线或短横线，便于 Git 和接口稳定；导出文件给教师使用中文名，便于人工整理。

## 6. 最低审校清单

每节课提交审校前至少检查：

- 正文是否能在课程页完整展示。
- `【关键词】`、`**加粗**`、`==标红==`、`{{红色:文字}}`、`{{大字:文字}}` 与 `## 标题` 是否在预览中正确渲染。
- 关键词解释是否面向学生，而不是只给教师或开发者看。
- 关键词两列格式使用“词语 | 释义”，需要拼音时使用“词语 | 拼音 | 释义”。
- 人物 persona 是否有时代边界，不让人物“预知后世”。
- facts 是否是硬史实，不混入价值判断。
- source_refs 是否能让审校人追溯；在 CE-11 完成前，不得把课程级资料列表描述为逐条事实引证。
- 导出文件名是否保留课程或档案本身名称。
- 刷新页面后，草稿是否能从草稿库或档案库重新打开。
- 关卡变量、人物、行动、事件和结局引用是否都能从选择器建立，并能通过服务端逐字段校验。
- 刷新页面后，当前关卡的既有封存版本是否仍可按精确版本/checksum 读取和导出，且不会因导出生成新版本。
- 封存后学生课程页是否仍保持旧 release，发布后 `release_id/release_no/checksum` 是否更新。
- 回滚是否只影响目标课程，并生成新的 release 而不是改写历史文件。
- 历史 sealed 是否通过白名单迁移接口接管，未生成 active pointer 的文件是否始终对学生不可见。

## 7. 待决问题

| 问题 | 当前建议 |
| --- | --- |
| 人物档案是否需要封存版本 | P0 阶段先保存 draft，等人物智能体正式接入后再加封存版本 |
| 关键词是否需要全局去重 | 需要，但先靠人工命名和档案库检索，后续再做冲突检测 |
| 地图点是否必须有经纬度 | 当前不强制；优先保证 `label/region/note/kind` 可读 |
| 资料是否接入 RAG | 暂缓；先让 source_refs 结构稳定 |
| facts 如何绑定资料 | 新增 CE-11；必须由教师显式选择并经审校，不按顺序、标题或文本相似度自动推断 |
| 是否需要教师账号系统 | 暂缓；当前继续使用 admin token，避免权限系统拖慢内容生产 |

## 8. 一键启动脚本状态

一键启动脚本已经进入 `houduan` 分支并推送到 GitHub：

- `点我一键启动（部署）.cmd`
- `scripts/teacher-editor.cmd`
- `scripts/teacher-editor.ps1`

教师在 Windows 上可优先双击项目根目录的 `点我一键启动（部署）.cmd`。首次运行会自动创建 `.venv`、安装 `apps/api/requirements.txt`、安装 `apps/web` 的 npm 依赖，然后为当前进程生成随机 admin token，启动后端 API、前端 Vite 服务，并打开 `http://127.0.0.1:5173/admin/content`。后续运行会核对 `requirements.txt` 的 SHA-256，未变化且依赖可导入时直接复用，避免每次联网重装。根目录 `.cmd` 的命令行提示保持 ASCII，避免 Windows cmd 中文乱码；`scripts/teacher-editor.cmd` 与 `scripts/teacher-editor.ps1` 保留为开发组维护入口。
