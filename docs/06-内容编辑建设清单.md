## 2. 需要编辑的内容对象

内容编辑不只包括课文正文。当前应维护五类对象：

| 对象 | 目标 | 最低字段 |
| --- | --- | --- |
| 课程内容包 | 让一节课可读、可预览、可封存、可进入课程页 | `lesson_id`、`course_id`、`title`、`unit`、`era`、`body`、`keywords`、`people`、`facts`、`source_refs` |
| 人物档案 | 为人物卡片、AI 人物智能体、课堂问答提供统一资料 | `asset_id`、`name`、`role`、`summary`、`persona`、`boundaries`、`related_lessons` |
| 关键词档案 | 统一课程内外的概念解释，避免同一词多种说法 | `asset_id`、`word`、`gloss`、`category`、`examples`、`related_people`、`related_lessons` |
| 地图点与时空信息 | 支撑“看”层地图、路线、空间比较 | `label`、`region`、`note`、`kind`，坐标可后补 |
| 参考资料 | 支撑史实审校、RAG、教师复核 | `title`、`source`、`url_or_path`、`citation_note`、`reliability` |

## 3. 优先任务清单

| 编号 | 优先级 | 任务 | 验收标准 |
| --- | --- | --- | --- |
| CE-01 | P0 | 复核 48 节已实装课程初稿 | 每节课能从“已有课程初稿”导入；正文不乱码；关键词、人物、seed canvas 至少保留原始信息 |
| CE-02 | P0 | 打磨 9 节 P0 主线课程 | 每节至少 3 段正文、5 个关键词、2 个人物、5 条 facts、2 条 qa_points、1 条 level_goal |
| CE-03 | P0 | 建立 P0 人物档案池 | 每节主线课至少 2 个可复用人物档案；每个人物有 persona 与史实边界 |
| CE-04 | P0 | 建立 P0 关键词档案池 | 每节主线课至少 5 个关键词档案；解释面向学生，避免百科式堆砌 |
| CE-05 | P0 | 补齐 source_refs | 每节主线课至少 2 条可复核资料；资料状态标注为 `pending` 或更高可信级别 |
| CE-06 | P1 | 将已有内置课程分批转为草稿 | 每批导入、修订、保存后进入 `content/drafts`，文件名保留课程标题 |
| CE-07 | P1 | 地图点标准化 | 重点课程至少 2 个地图点；统一 `capital/site/route/battle` 等 kind |
| CE-08 | P1 | AI 预留字段标准化 | `facts`、`people.persona`、`qa_points`、`level_goals`、`saga_material`、`sandbox_material` 不再空缺 |
| CE-09 | P1 | 封存审校流程 | 草稿、预览、封存、课程页读取四步可复现；封存文件带版本、时间、操作者 |
| CE-10 | P2 | 批量编辑模板 | 形成教师批量写课模板，减少重复输入课程 ID、时代、单元 |

## 4. 建议推进顺序

1. 先把样板课“洋务运动的探索”作为黄金样板复核一遍，确认字段、导出文件和预览效果都符合教师预期。
2. 用“已有课程初稿”导入 P0 主线课程，逐节补正文、关键词、人物、资料和 AI 预留字段。
3. 每完成 1 节课，同步补它的人物档案和关键词档案，避免课程正文先行、资料资产滞后。
4. 每完成 3 节课，做一次审校小批次：检查史实、导出文件名、封存版本和课程页展示。
5. P0 主线稳定后，再扩展到 48 节已实装课程。

## 5. 文件与命名规则

| 内容 | 保存位置 | 导出命名 |
| --- | --- | --- |
| 课程草稿 | `content/drafts/{lesson_id}.json` | `课程标题.json`、`课程标题-格式层.json`、`课程标题-预览.html`、`课程标题-教师稿.md` |
| 封存课程 | `content/sealed/{lesson_id}-vNNN.json` | 同课程标题导出 |
| 人物档案 | `content/assets/people/{asset_id}.json` | `人物姓名-人物档案.json` |
| 关键词档案 | `content/assets/keywords/{asset_id}.json` | `关键词-关键词档案.json` |

`lesson_id` 和 `asset_id` 仍使用英文、数字、点、下划线或短横线，便于 Git 和接口稳定；导出文件给教师使用中文名，便于人工整理。

## 6. 最低审校清单

每节课进入封存前至少检查：

- 正文是否能在课程页完整展示。
- `【关键词】`、`**加粗**`、`==标红==`、`{{红色:文字}}`、`{{大字:文字}}` 与 `## 标题` 是否在预览中正确渲染。
- 关键词解释是否面向学生，而不是只给教师或开发者看。
- 人物 persona 是否有时代边界，不让人物“预知后世”。
- facts 是否是硬史实，不混入价值判断。
- source_refs 是否能让审校人追溯。
- 导出文件名是否保留课程或档案本身名称。
- 刷新页面后，草稿是否能从草稿库或档案库重新打开。

## 7. 待决问题

| 问题 | 当前建议 |
| --- | --- |
| 人物档案是否需要封存版本 | P0 阶段先保存 draft，等人物智能体正式接入后再加封存版本 |
| 关键词是否需要全局去重 | 需要，但先靠人工命名和档案库检索，后续再做冲突检测 |
| 地图点是否必须有经纬度 | 当前不强制；优先保证 `label/region/note/kind` 可读 |
| 资料是否接入 RAG | 暂缓；先让 source_refs 结构稳定 |
| 是否需要教师账号系统 | 暂缓；当前继续使用 admin token，避免权限系统拖慢内容生产 |
