## 1. 本文解决什么问题

Chronovita 的模型可以帮助理解学生输入和组织表达，但不能决定历史真值，也不能替代规则引擎改变局势。AI-001 只允许模型在服务端给出的白名单上下文中完成两件事：

1. 把学生自由输入归类到当前回合已经可用的行动，或要求澄清、拒绝越界输入。
2. 根据规则引擎已经结算的回合结果，生成受事实、人物和篇幅约束的叙事反馈。

AI-001 当时未包含 RAG。V0.10.4 已在运行层发布 L101/L103 两份 `EvidenceCorpusV1` 并与同一 `course-release/v3` 精确绑定，但检索索引、`/practice/ask/rag`、开放互联网检索、通用历史问答和多智能体自主决策仍未实现；模型始终不得生成状态效果、事件、NPC 数值或结局。

## 2. 依据对象与权威顺序

| 依据对象 | 课程包或关卡字段 | AI 用途 | 权威边界 |
| --- | --- | --- | --- |
| 不可违反事实 | `facts` | 判断行动是否违反史实，约束回合叙事 | 只能使用当前会话固定课程包与关卡中的条目 |
| 资料引用 | `source_refs`、事实的 `source_refs` | 解释事实来源，生成可追溯引用 ID | 模型只能引用服务端给出的 ID，不能自造书名、链接或路径 |
| 人物表达 | `people.persona`、`people.boundaries`、关卡 NPC persona/边界 | 约束口吻、立场与不可声称内容 | persona 只决定表达，不改变事实、规则或权限 |
| 问答知识点 | `qa_points` | 识别学生可能追问的课程内问题 | 不是开放知识库；超出范围时要求澄清或转到专家问答 |
| 学习目标 | `level_goals`、关卡 `objective` | 判断输入是否与当前任务相关 | 不能把“符合目标”当成行动可用性的替代条件 |
| 规则结果 | 当前可用行动、状态差、事件、NPC 变化、结局 | 生成本回合叙事 | 唯一来源是确定性规则引擎，模型不得重算或覆盖 |

依据优先级固定为：同一发布快照中的 sealed 课程/关卡字段 > 规则引擎结算结果 > 模型语言能力。发生冲突时必须保留前两者并舍弃模型输出。

## 3. 可进入 AI 上下文的白名单

### 3.1 自由输入归类

服务端只提供：

- 当前课程、课时、关卡标题和学生任务。
- 当前回合可用行动的稳定 `action_id`、教师标题、简短说明与别名。
- 与当前行动直接相关的已审 `facts` 及稳定资料引用 ID。
- 必要的时代边界和当前节点，不提供未公开教师备注。

模型输出只能是“匹配一个当前可用行动”“需要澄清”或“拒绝”。返回未知或不可用 `action_id`、低于服务端阈值、包含越时代建议、与 facts 冲突、结构不合法或服务异常时，不创建回合，也不增加 session revision。

固定按钮、稳定 ID、标题或 alias 能精确解析时直接走确定性路径，不调用模型。

当前实现入口为 `services/ai/ActionClassifierV1`，输出合同为 `ActionClassificationV1`。它只读取 `SituationEngineV1.available_actions()` 计算出的当次行动与相关已审 facts，不向模型发送教师备注、资料路径、规则效果或会话状态；返回对象不含状态变化字段，也不调用规则结算。带 `pending` 资料或“教师待审”标记的技术样板只能使用精确按钮，不能开启语义分类。`GameRuntimeService.apply_free_input()` 已在分类前后复核同一 revision；只有 matched 分支产生规则候选，澄清、拒绝或分类故障保持零写入。

### 3.2 回合叙事

服务端只提供：

- 已确定的行动与规则叙事。
- 规则引擎生成的状态差、触发事件、NPC 变化和结局投影。
- 与本回合相关的 facts、资料引用 ID，以及当前发言 NPC 的 persona/boundaries。
- 输出长度、语气、允许引用 ID 和禁止声称内容。

模型只返回有限长度的展示文本和实际使用的事实/资料 ID。任何状态、效果、事件、NPC 数值、结局或下一步行动字段都视为非法输出。叙事模型失败不会撤销已经由规则确定的行动，而是使用引擎的规则叙事作为稳定回退。

当前实现入口为 `services/ai/HistoricalNarratorV1`，严格输出合同为 `NarratorModelOutputV1`。服务端先用 `SituationEngineV1` 形成不可见的纯规则候选，再把固定课程/关卡身份、行动反馈、状态差、NPC 变化、事件/结局投影、已审 facts/source ID 和 persona/boundaries 交给叙事器；学生原文、教师备注、资料路径、规则 effects、密钥与既有模型历史不会进入该上下文。输出只允许 1—1200 字文本和白名单内引用；越界、重复、超长、未知字段或供应商异常原样回退规则文本并记录稳定原因。

固定行动 API 的 `submit_fixed_action()` 与自由输入 matched 分支都在状态锁和数据库事务外调用叙事器。返回后重新读取同一 revision；未漂移时才把规则状态、叙事、证据和可选完成态卷宗一次 CAS 提交，漂移时返回冲突且旧叙事不落库。离线 replay 只复用验真的持久文本，不调用叙事器。

## 4. 审校与发布边界

- AI 上下文必须从会话固定的课程版本、课程 checksum、关卡版本和关卡 checksum 读取，禁止从“当前最新”文件重新拼装。
- V0.10.2 的证据稿按 revision/CAS 保存，逐项校验来源、片段、fact/person 绑定，并要求不同认证账号审校；只有管理员能封存为不可变 `EvidenceCorpusV1`。
- `course-release/v3` 每课时必须同时精确绑定课程包、关卡、证据库和展示资源；活动指针切换前再次复验 checksum、事实/人物引用和本地媒体，失败不改变学生版本。
- 只有 active published release 可以作为正式学生课程的依据；development catalog 只用于开发验收。
- `C-prequin-state / L101` 与 `L103` 的 V0.10.4 active V3 制品已分别作为正式初稿走完独立审校；旧 `dayu-flood-control` 与 `scenario-shangyang-institutional-reform` 技术夹具中带 `【教师待审】`、`pending` 或 development 标记的内容仍只证明契约和引擎可运行。
- 旧内容缺少逐条事实与资料关系时不得猜测绑定；模型上下文可以缩减，但不能补造依据。
- 当前分类与叙事实现都不向模型提供 `source_refs.url_or_path`；只提供稳定 source ID 与叙事所需的标题、类型、出版方和审校状态。系统路径、管理备注、密钥、token、原始异常体和其他课程资料不得进入模型上下文或学生响应。

## 5. 结构校验与失败策略

| 失败场景 | 对学生的稳定结果 | 是否推进回合 |
| --- | --- | --- |
| 精确 ID/别名命中 | 直接进入规则结算 | 是 |
| 自由输入高置信度匹配当前可用行动 | 进入规则结算 | 是 |
| 含义不清或低置信度 | 返回澄清提示与当前可用行动 | 否 |
| 越时代、违反 facts、提示注入或要求模型改状态 | 返回边界说明 | 否 |
| 分类输出为空、截断、未知字段、未知行动或 JSON 错误 | 返回稳定回退提示 | 否 |
| 分类超时、限流、网络或供应商异常 | 返回稳定回退提示，仍可使用固定行动 | 否 |
| 叙事输出不合法或供应商异常 | 使用规则叙事 | 是，前提是规则结算已经成功 |
| revision 已变化 | 返回并发冲突，要求刷新会话 | 否，不自动重新归类 |

所有模型输出使用 Pydantic 严格对象校验并禁止未知字段，同时限制输入长度、输出长度、token、超时和可引用 ID。对外只返回稳定原因码，不返回供应商响应体、网络异常文本、prompt 或思维链。

## 6. 回放与审计最低信息

需要持久化的 AI 叙事元数据仅包括：

- `provider`、`model` 与 prompt policy 版本。
- 归类来源、置信度与最终 `action_id`。
- 实际使用的 fact/source 引用 ID。
- 规范化输出 checksum 和稳定回退原因。

禁止持久化思维链。回放只重放已经保存并验真的回合，不再次调用模型；规则状态、事件、NPC 变化和结局仍需由 `RuntimeBundleV1` 重新推导。叙事元数据结构错误、引用超出白名单、规则依据哈希漂移或输出 checksum 不一致时必须失败关闭。

当前 checksum 用于发现意外损坏、局部篡改和跨字段不一致，不是抵御拥有数据库写权限并能重算整个信封的攻击者的数字签名。若生产威胁模型需要覆盖该能力，必须另建安全任务，引入不与会话数据库同域保存的 HMAC/签名密钥和密钥轮换；AI-001 不虚构这项保证。

## 7. 开发与验收依据

AI-001 的离线测试使用可编程 fake provider，不在 CI 或仓库中保存真实 API key。最低反例包括：

- 未知行动、当前不可用行动、低置信度和越时代输入。
- 要求忽略 facts、泄露 prompt、修改资源数值或直接指定结局的提示注入。
- 空 JSON、截断 JSON、额外字段、超长文本、超时、限流和 HTTP 失败。
- 相同幂等 ID 重试、不同输入复用 ID、并发同 revision 和服务重启回放。
- 叙事引用未提供 fact/source、人物越界、模型元数据与输出 checksum 不一致，以及规则依据哈希漂移。

技术实现参考：

- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode)：JSON 模式仍需在 prompt 中明确要求 JSON，并处理空内容与截断。
- [DeepSeek Chat Completion API](https://api-docs.deepseek.com/api/create-chat-completion/)：结构化请求、模型和响应字段以官方接口为准。
- [OWASP LLM Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)：输出校验、最小权限与确定性外部控制是本项目的护栏依据。
- [Python asyncio timeout](https://docs.python.org/3.11/library/asyncio-task.html#timeouts)：模型调用使用明确超时边界，超时转换为稳定内部原因码。

## 8. 维护规则

1. 内容团队修改 facts、人物边界或资料关系后必须重新封存并发布，既有会话继续固定旧制品。
2. 人工智能组增加 prompt 或模型字段时，先更新 [ADR-0012](adr/ADR-0012-看练问创闭环与史实护栏.md) 和严格输出 Schema，再增加调用代码。
3. 后端组不得把模型返回直接传给 `SituationEngineV1` 的效果、事件或状态接口。
4. 前端组不得提交客户端声明的归类置信度、行动来源或权威 `action_id` 来绕过服务端归类。
5. RAG 检索实现由已登记的 AI-002 承担；在该任务完成前，只能宣称证据审校与精确发布已经可用，不能把发布语料描述成已完成检索回答。
