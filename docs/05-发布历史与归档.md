### V0.9.14 OPS test(postgres): 建立真实服务迁移与运行矩阵（OPS-001）

- PostgreSQL Engine 新增显式连接池容量、溢出、取连接等待、连接回收、建立连接超时和存活预检，Settings 与底层构造器使用同一组有界参数；production 数据库配置只接受 PostgreSQL/Psycopg 与 `sslmode=verify-full`，SQLite、其他驱动、仅加密不验证主机名及损坏 URL 均在打开数据库前以稳定代码失败，且不回显凭据。
- `scripts/manage_database.py status|migrate` 新增 `--database-url-env`，只从命名环境变量读取 PostgreSQL URL；空库初始化必须显式给出 `--initialize`，命令输出只记录环境变量名与 schema 状态。SQLite 文件参数及其 backup/verify/restore 保持原语义。修正 PostgreSQL Inspector 不在列字典携带主键信息时的合同反射，真实主键统一从主键约束读取。
- 新增 PostgreSQL 16.14 GitHub 服务工作流、固定 SHA 的官方 Actions、无持久卷且仅绑定回环地址的本地测试 Compose，以及端到端服务测试：双 Engine 并发迁移、连续账本、真实反射、环境变量式 CLI、accounts 启动、ready、管理员/学生账号、学习进度、游戏会话与认证审计基础链路。工作流把有界测试尾部写入任务摘要，并在失败时生成公开 Check API 可读的有界错误注释，无需下载完整日志也能定位失败。锁定虚拟环境下后端全量 252 项通过，1 项服务测试因本机没有 PostgreSQL 跳过；Python 编译、依赖与差异检查通过，[GitHub Actions 运行 29513892526](https://github.com/falling-feather/Chronovita/actions/runs/29513892526) 已在 PostgreSQL 16.14 服务上通过真实测试。该矩阵不验证真实 TLS 握手、多 worker 审计/最后管理员/KV 竞争、共享限流、故障转移或 Postgres 原生备份，OPS-001 和 QA-001 保持进行中；正式课程内容未改动。

### V0.9.13 OPS feat(security): 建立登录限流与可信运行边界（OPS-001）

- 新增 `LoginAttemptLimiter` 与纯 ASGI 登录中间件，只在 `POST /api/v1/auth/login` 密码校验前按连接端地址摘要消耗进程内令牌桶，不读取正文、用户名、密码或转发头。默认容量 10 次/60 秒、最多 10000 个客户端；耗尽后返回稳定 `429 auth_rate_limited`、`Retry-After`、`no-store` 与统一请求 ID，CORS 可读取重试头，其他接口不受影响。限流日志使用固定登录路由模板，不写原始 URL 或口令。
- 新增 `CHRONO_TRUSTED_HOSTS` 和 `TrustedHostMiddleware`。所有档位拒绝空值、重复、通配符、端口/协议/路径及非小写不精确 Host；production 进一步拒绝 localhost、testserver、回环和未指定地址，`local + legacy-local` 只接受本机测试 Host。请求遥测位于最外层，可信 Host、CORS 与限流拒绝仍有统一关联事件。
- 一键脚本先清除继承的 `CHRONO_*`，通过进程级 `CHRONO_DISABLE_DOTENV=true` 阻止根 `.env` 回填，再显式覆盖为回环 `local + debug + legacy-local + apply-safe + SQLite + mock`，生成新 admin token 并重置 Vite API 代理；修复 Windows 父进程同时含 `PATH/Path` 时 `Start-Process` 崩溃，识别完整已运行编辑器、拒绝单端口半套服务，并在后续启动失败时回收本次进程树。根 CMD 与提示继续使用 ASCII。新增 6 项专项，锁定虚拟环境下后端全量 247 项；PowerShell 解析、沙箱外 API/Vite 启动、`readyz=ready`、编辑器 HTTP 200 以及故障后双端口清理通过。OPS-001 继续真实 Postgres 服务矩阵与跨实例共享限流；正式课程内容未改动。

### V0.9.12 OPS feat(observability): 接通请求追踪与脱敏结构化日志（OPS-001）

- 新增纯 ASGI 请求遥测中间件：校验或生成 `X-Request-ID`，写入 request state 与 ContextVar，覆盖响应关联头并供现有认证/内容授权审计复用；CORS 显式暴露该头。非法 ID 不反射，未匹配 URL 只记 `<unmatched>`，下游不能覆盖服务端最终关联值。
- lifespan 关闭 Uvicorn 重复 access log，每次请求只生成一条 JSON 消息，字段限于 UTC 时间、请求 ID、方法、路由模板、状态、耗时和客户端摘要，不读取资源 path、query、Authorization、Cookie、请求/响应正文、账号或学生文本。production 未开始响应的未知异常返回固定 `internal_server_error`，日志只记异常类名；local debug 保留抛出边界。
- 数据库 URL 之外，admin token、bootstrap 密码与 DeepSeek key 也改为 `SecretStr`，消费点显式取值，Settings repr 不暴露明文。新增 5 项专项，覆盖三类秘密遮蔽、请求关联、非法 ID、响应头覆盖、路由模板、404 高基数路径隐藏、敏感字段缺席与异常消息脱敏；锁定虚拟环境下后端全量 241 项通过。OPS-001 继续认证限流、可信 Host、一键模式复验和真实 Postgres 服务；正式课程内容未改动。

### V0.9.8 DATA feat(backup): 建立可验证数据库备份恢复（DATA-001）

- 新增 `services/persistence/backup.py` 与 `scripts/manage_database.py`，提供结构化 JSON 的 `status/migrate/backup/verify-backup/restore`。备份通过 SQLite 官方 backup API 读取包含活动 WAL 已提交内容的一致视图，规范为独立文件后执行 `quick_check` 与 V0.9.7 schema 复验，再写入 `chronovita-backup-manifest/v1` 的 backup ID、UTC 时间、版本、文件名、字节数和 SHA-256；清单不保存源路径、URL、凭证或业务正文。
- 备份文件和 manifest 使用同目录临时文件与只创建硬链接发布，既有目标不覆盖，第二文件发布失败会清理第一文件。恢复先复验 manifest/checksum/SQLite/schema 并拒绝同文件或硬链接别名；默认只恢复到新目标，`--replace` 会先生成可验证安全副本，目标存在 WAL/SHM/journal 时拒绝，原子替换后的末次复验失败会自动恢复旧库。Postgres 不伪装成文件复制，仍由 DATA/OPS 后续接入原生工具。
- 新增 10 项专项测试，覆盖当前库与 V0.8.x 旧库往返、活动 WAL、篡改/重复键/未来 schema、目标与 sidecar 冲突、双文件发布故障、覆盖前安全副本、末次验证失败回滚和 CLI 整链；相关 34 项与锁定虚拟环境下后端全量 216 项通过。DATA-001 继续处理数据库 URL/Postgres 边界和 Store 兼容 `create_all()` 清理；正式课程内容未改动。

### Persist game sessions with optimistic CAS (BE-002)

- 新增 `game_sessions` SQLAlchemy Core JSON 镜像表；带 checksum 的规范 envelope 保存完整 `GameSessionV1`，Turns、状态快照、NPC 和结局不拆成第二套状态模型，单记录上限为 4 MiB。
- 会话创建、读取与行动推进全部改为 SQLite 权威存储；写回要求 revision 恰好增加一，并以“会话 ID + 原始整段 data”原子 compare-and-swap。不同连接的陈旧写不能覆盖已提交回合，同一动作跨实例重试仍幂等。
- 每次读取按会话固定的 scenario 版本/checksum 从显式 catalog 重新加载 sealed 课程与关卡，再组成 `RuntimeBundleV1` 完整回放；损坏 JSON、身份或 envelope checksum 漂移、重算 checksum 后伪造规则叙事、固定场景版本缺失均失败关闭；SQLAlchemy 运行错误统一收口为结构化 `503 game_storage_unavailable`。
- FastAPI lifespan 复用共享 Engine 并在退出时只释放连接，不删除会话；测试已实际关闭并重建应用后读取原会话并继续下一回合。API 明示 `session_storage=sqlite-json`。
- 后端全量 77 项测试、编译和 OpenAPI 契约检查通过。本提交完成持久会话基础，回放读取、完成态 `DossierV1`、持久卷宗和教师可读摘要由后续 `Generate durable replay dossiers (BE-002)` 提交接续。

### Harden historical situation replay integrity (GAME-001)

- `GameSessionV1` 强制 `revision = current_turn + 1`；同一 `client_action_id` 只有在动作、输入、分类结果和产生原回合时的 `expected_revision` 全部一致时才作为幂等重试返回，迟到复用稳定拒绝。
- `RuntimeBundleV1` 在完整规则重放中逐项核对 `state_changes`、`fact_refs`、`ruleset_hash` 与 `narrative_source=rules` 的确定性叙事；运行时经 JSON 投影深度重建输入，嵌套列表或字典原位篡改不能绕过校验。
- sealed 文件加载改为单句柄 `fstat`、2 MiB 有界读取、`lstat` 符号链接拒绝与路径身份核对，避免检查和读取分离；重复 JSON key、非法编码、非普通文件及中途替换继续失败关闭。
- 商鞅技术样板新增阻力超限与评估自循环动作，使成功、待复核、阻力失败和六回合兜底四类结局都有确定可达路径；大禹样板回合改由共享 reducer 生成完整规则来源与叙事。
- 当前核心后端基线 63 项测试通过；`GAME-001` 仍待显式场景目录和 API 接线后完成。
