### V0.9.17 OPS fix(kv): 建立原子 upsert 与值语义 CAS（OPS-001）

- 学习进度和知识画板把读取到的 presence 位传入 CAS。SQLite 专项覆盖 16 路首次 upsert、双写唯一 CAS、旧格式、null 与类型边界；相关 10 项与锁定虚拟环境下后端全量 255 项通过，1 项服务测试因本机无 PostgreSQL 跳过。[GitHub Actions 运行 29517646885](https://github.com/falling-feather/Chronovita/actions/runs/29517646885) 已在 PostgreSQL 16 服务上通过 16 路 upsert、16 路 CAS 及兼容数据复验；正式课程内容未改动。

### V0.9.15 OPS fix(audit): 串行化多实例审计并固定复验快照（OPS-001）

- 审计追加不再依赖单个 `AuthStore` 的 Python `RLock` 保证生产顺序；每个事务先以 `SELECT ... FOR UPDATE` 锁定唯一审计头，读取提交后的最新 sequence/hash，再原子更新头并插入事件。不同进程、worker、Engine 和 Store 的正常并发由数据库串行化，不再因为同时读取旧头而把合法业务写回滚为 `audit_head_busy`。
- PostgreSQL 的 `AuthStore.verify_audit_chain()`、schema/审计不变量只读复验和迁移事务统一使用 `REPEATABLE READ`。同一次复验中的 head、events、表合同和迁移账本来自一个一致快照，避免并发审计提交恰好发生在两条 SELECT 之间时误报链损坏；SQLite 原有事务语义保持不变。
- PostgreSQL 并发迁移先取得会话级 advisory lock 并提交锁获取事务，再开启新的 `REPEATABLE READ` 迁移事务；提交或回滚后显式解锁，解锁失败会使连接失效并失败关闭。该顺序避免等待事务在前一迁移提交前固定旧快照后重复建表，同时保留迁移内的一致视图。
- PostgreSQL 16 服务矩阵新增 8 个独立 AuthStore、32 次并发审计追加，并在写入期间由另一 Engine 循环执行链复验和完整 schema 复验；最终要求 sequence 无缺口、hash 链有效且 schema 当前。相关 35 项与锁定虚拟环境下后端全量 252 项通过，1 项服务测试因本机无 PostgreSQL 跳过；[GitHub Actions 运行 29515058702](https://github.com/falling-feather/Chronovita/actions/runs/29515058702) 已在 PostgreSQL 16 服务上通过跨实例迁移、审计追加和一致快照复验。最后管理员/bootstrap、KV 竞争、迁移锁超时等仍继续修复，正式课程内容未改动。

### Persist game sessions with optimistic CAS (BE-002)
