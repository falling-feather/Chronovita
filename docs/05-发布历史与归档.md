## 3. 版本记录

### AI feat(classifier): 建立服务端行动归类与史实前置护栏（AI-001）

- 新增严格 `ClassifierModelOutputV1` 与 `ActionClassificationV1`：模型只能在服务端当次计算的可用行动中返回一个稳定 ID，或返回澄清/拒绝；LLM 来源必须携带 provider、model 与规范输出 checksum，归类合同不包含任何状态、效果、事件、NPC 或结局写入字段。
- 新增纯 `ActionClassifierV1`：先按 `PlayerInput` 校验，再由规则引擎精确解析 ID、教师标题与 alias；仅在未精确命中且存在相关已审 facts 时调用结构化模型。模型上下文排除教师备注、资料路径、规则效果、完整状态与密钥，待审技术样板保持固定按钮可用但关闭语义分类。
- 提示注入、当前不可用/未知行动、低置信、越时代、事实冲突、非法输入、无已审依据和供应商异常全部失败关闭，不修改会话；归类器不调用 `apply_action()`，确定性规则引擎仍是唯一状态权威。自由输入 API、revision CAS、规则结算后叙事与回放元数据仍由 `AI-001` 后续提交接续。
- 新增 9 项纯离线归类反例；项目锁定 `.venv` 下后端全量 134 项、Python 编译通过，不访问真实模型或读取真实 API key。

### AI feat(llm): 建立严格结构化模型适配与稳定回退（AI-001）

- 新增 `LLMMessage`、`StructuredLLMAdapter`、类型化 `LLMFailureCode`/`StructuredLLMError` 与规范输出 checksum；结构化调用自动携带目标 Pydantic JSON Schema 和 `response_format=json_object`，模型额外字段不能进入业务层。
- DeepSeek 响应执行超时、token、字节、finish reason、UTF-8、重复 key、非有限数、JSON 对象和输出 Schema 校验；响应按流分块读取，超过上限立即中止。429、超时、4xx、5xx、截断与供应商异常转换为稳定原因码，不包含响应体或网络异常原文。
- legacy `stream_chat()` 保持 saga/ask 兼容，但 HTTP 错误、网络异常或空响应统一使用稳定离线提示和 mock 回答，不再把供应商调试文本展示给学生。
- 新增 9 项纯离线适配器反例；后端全量 125 项、Python 编译与 `git diff --check` 通过，不读取真实 API key。

### AI docs(guardrails): 冻结交互编排与史实护栏边界（AI-001）

- 核心开发组认领 `AI-001` 并归入 V0.8.x；精确补丁版本继续由项目负责人在阶段收口时确认。
- 新增资料依据库，明确 published 且同一固定运行快照中的 `facts`、`source_refs`、人物 `persona/boundaries`、行动与规则结果是 AI 上下文白名单；带“教师待审”或 development 标记的样板不得被描述成正式史实依据。
- ADR-0012 冻结两段式编排：服务端先把自由输入严格归类到当前可用行动，再由确定性规则引擎结算；模型只生成受限叙事。低置信度、越时代、事实冲突、输出结构错误和分类服务异常不推进回合，叙事服务异常则使用规则文本完成已确定的回合。
- 归类和叙事均使用禁止未知字段的结构校验、长度/超时限制与稳定错误码；模型不得返回状态效果、事件、NPC 数值或结局，回放不得再次调用模型，也不保存思维链。

### Generate durable replay dossiers (BE-002)

- 新增 `game_dossiers` SQLAlchemy Core JSON 镜像和确定性卷宗生成器；最终回合、完成态会话与 `DossierV1` 在同一事务中提交，卷宗插入失败会回滚整次末回合。旧完成态会话只能通过显式 POST 幂等补建，GET 不产生写入。
- 卷宗选择、轨迹、代价、历史解释、facts、资料、反思问题与允许的知识节点只取自固定 sealed 制品和真实回合；没有关系契约时不编造知识边，也不代写学生或教师反思。读取时重新派生并逐字段核对，修改文本后重算 checksum 仍会失败关闭。
- 新增精确回放、卷宗读取/补建和教师摘要 API；回放从持久回合重建命令并核对完整 `GameSessionV1`。会话启动要求 `client_request_id`，同用户同请求重试返回原会话，改用其他场景稳定冲突。
- 测试覆盖双技术模板、应用重启、跨服务末回合幂等、事务回滚、旧会话补建、checksum 与重签名篡改、固定场景缺失和存储故障；后端全量 86 项、编译及 OpenAPI 契约检查通过，窄范围独立只读 review 无剩余 P0-P2。
- `BE-002` 至此完成。这里的 final 卷宗只表示不可变技术制品，并不代表历史内容通过审校；两份 catalog 样板仍是 `audience=development`，正式教学需后续 published 课程/关卡联合发布。

### Claim BE-002 durable game sessions and dossiers

- 核心开发组认领 `BE-002`，目标版本为 V0.8.x；前置 `ARCH-001` 与 `GAME-001` 均已完成。
- 实现遵循 ADR-0007：复用 SQLAlchemy Core + SQLite，不引入 ORM Session、Alembic 或新基础设施；以业务表保存完整 Pydantic JSON 镜像。
- `GameSessionV1` 是唯一会话状态真相，完整 Turns、状态快照和结局随会话事务保存，写入以 revision 做 compare-and-swap；恢复时必须从 catalog 加载精确场景版本/checksum，并经 `RuntimeBundleV1` 完整重放验真。
- `DossierV1` 只从已完成且验真的会话幂等派生，引用真实回合、状态轨迹、facts 与资料。历史解释、反思问题和知识图谱仅使用已封存模板/课程字段或明确技术占位，不由开发组自行补写史实。
- 任务验收包括 API 重启续玩、完整回放、卷宗读取、并发冲突、损坏 JSON、规则制品漂移和事务失败反例；实现与测试按独立 Git 提交持续同步。

### Persist game sessions with optimistic CAS (BE-002)

- 新增 `game_sessions` SQLAlchemy Core JSON 镜像表；带 checksum 的规范 envelope 保存完整 `GameSessionV1`，Turns、状态快照、NPC 和结局不拆成第二套状态模型，单记录上限为 4 MiB。
- 会话创建、读取与行动推进全部改为 SQLite 权威存储；写回要求 revision 恰好增加一，并以“会话 ID + 原始整段 data”原子 compare-and-swap。不同连接的陈旧写不能覆盖已提交回合，同一动作跨实例重试仍幂等。
- 每次读取按会话固定的 scenario 版本/checksum 从显式 catalog 重新加载 sealed 课程与关卡，再组成 `RuntimeBundleV1` 完整回放；损坏 JSON、身份或 envelope checksum 漂移、重算 checksum 后伪造规则叙事、固定场景版本缺失均失败关闭；SQLAlchemy 运行错误统一收口为结构化 `503 game_storage_unavailable`。
- FastAPI lifespan 复用共享 Engine 并在退出时只释放连接，不删除会话；测试已实际关闭并重建应用后读取原会话并继续下一回合。API 明示 `session_storage=sqlite-json`。
- 后端全量 77 项测试、编译和 OpenAPI 契约检查通过。本提交完成持久会话基础，回放读取、完成态 `DossierV1`、持久卷宗和教师可读摘要由后续 `Generate durable replay dossiers (BE-002)` 提交接续。

### Expose pinned historical situation game API (GAME-001)

- 新增 `ScenarioCatalogV1` 显式 allowlist；每个 active 关卡固定场景/课程 ID、版本、checksum、规范 POSIX 路径和 `development|published` audience，不扫描目录猜测最新文件。课程包允许被多个关卡共享，但同一路径的课程身份必须完全一致。
- 新增 `/api/v1/practice/game/scenarios`、`/sessions`、`/sessions/{session_id}` 和 `/sessions/{session_id}/turns` 四条 OpenAPI 响应明确的接口；回合请求禁止携带客户端 state 等权威字段，404/409/422/503 使用稳定错误码。
- 新增线程安全的单进程临时会话协调器；同 revision 并发动作恰有一个成功，幂等重试保留原结果，存储会话与返回对象深度分离。lifespan 退出或初始化失败会清空临时会话并释放 SQLite 文件句柄。
- 场景目录和制品使用根目录约束、规范路径、符号链接拒绝、有界读取与制品身份复验；catalog 损坏、路径逃逸、未列出文件和 checksum 漂移均失败关闭。两份技术样板通过 API 明示为 `audience=development`。
- legacy saga/sandbox 路由保持兼容；后端全量 70 项测试、编译、OpenAPI 路径检查、敏感信息扫描和文档校验通过。本地逐行 review 修复课程包复用、解析异常映射、会话浅引用与并发覆盖测试后，无剩余 P0-P2。
- `GAME-001` 至此完成。当前 `session_storage=ephemeral`、开发期单用户和 development 样板是明确边界；跨重启恢复、卷宗生成及 published 课程/关卡联合发布由 `BE-002` 接续。

### Harden historical situation replay integrity (GAME-001)

- `GameSessionV1` 强制 `revision = current_turn + 1`；同一 `client_action_id` 只有在动作、输入、分类结果和产生原回合时的 `expected_revision` 全部一致时才作为幂等重试返回，迟到复用稳定拒绝。
- `RuntimeBundleV1` 在完整规则重放中逐项核对 `state_changes`、`fact_refs`、`ruleset_hash` 与 `narrative_source=rules` 的确定性叙事；运行时经 JSON 投影深度重建输入，嵌套列表或字典原位篡改不能绕过校验。
- sealed 文件加载改为单句柄 `fstat`、2 MiB 有界读取、`lstat` 符号链接拒绝与路径身份核对，避免检查和读取分离；重复 JSON key、非法编码、非普通文件及中途替换继续失败关闭。
- 商鞅技术样板新增阻力超限与评估自循环动作，使成功、待复核、阻力失败和六回合兜底四类结局都有确定可达路径；大禹样板回合改由共享 reducer 生成完整规则来源与叙事。
- 当前核心后端基线 63 项测试通过；`GAME-001` 仍待显式场景目录和 API 接线后完成。

### Build deterministic historical situation engine core (GAME-001)

- 新增唯一 `rules_v1` 纯规则 reducer，由会话生成和 `RuntimeBundleV1` 回放验真共同调用；顺序固定为行动效果、事件一次性筛选与稳定执行、节点迁移、结局裁定。
- 新增 `SituationEngineV1`，从 sealed 课程包/关卡 JSON 加载，复制式启动和推进 `GameSessionV1`，生成规范 `TurnV1`，支持固定 alias、`client_action_id` 幂等、`revision` 乐观并发与完整确定性重放。
- 状态和 NPC 效果逐条限幅；节点结局优先于条件结局；命中结局后禁止继续行动或伪装为失败/放弃；无可用行动、到上限仍无结局、checksum/重复 JSON key/跨引用/会话快照篡改均失败关闭。
- 增加大禹治水无节点危机治理与商鞅变法节点式制度改革两类 sealed 技术样板；全部史实、人物、数值和结论均标明教师待审，不作为正式教学内容。
- 完整后端 61 项测试通过；双模板固定输入重复运行、在线逐步与批量重放逐字段一致。当前提交只收口核心层，游戏 API 和正式场景仓库仍在 `GAME-001` 后续范围内。

### Implement content review and release workflow (BE-001)

- 新增独立内容工作流，覆盖保存、最低校验、提交审校、退回、通过、封存、发布和回滚；实质内容变化会使旧批准失效，相同内容重复保存不会误撤销状态。
- 每门课程使用不可变 release manifest 与原子 active pointer；发布或回滚先复验全部制品与跨课程课时 ID，再写后台工作流投影，最后才把 active pointer 作为学生端提交点。短生命周期事务日志支持进程中断后的启动恢复，可重入全局工作流文件锁串行化本机多 worker 的保存、审校与发布。
- 发布时把旧教师内容包规范化为 `CoursePackageV1`，同时固定源 sealed checksum、V1 checksum 和 release checksum；学生课时响应带 release 身份，损坏发布返回稳定 `503`。
- 学生端取消旧 sealed 目录的隐式 fallback；历史内容必须由管理员显式列出 `lesson_id + content_version`，经最低校验后生成 bootstrap release。
- admin token 移除通用默认值，一键启动进程生成随机 token；审计身份取认证后的服务端 actor，不信任请求体署名；单文件写入采用同目录临时文件、`fsync`、原子替换或只创建硬链接。
- 后端全量 50 项测试通过，新增 API 全链路、封存不可见、显式迁移与不合格迁移拒绝、V1/V2 发布、同课程多课时投影、跨课程 ID 冲突、按课程回滚与历史制品复验、服务重载、并发保存与审批封存并发、严格 ID 路径校验、重复保存、路径/制品篡改、源文件缺失、孤立 manifest 隔离及首发/工作流/指针/进程中断故障注入反例。
- 本次编辑器改动已在 `houduan` 干净分支独立通过生产构建；浏览器在桌面与移动视口完成“保存—校验—审校—封存—发布—学生课程页—回滚”验收。课程页第三方视频播放器在受限网络中仍会产生其自身请求告警，不影响课程内容读取。

### Freeze runtime contracts V1 (ARCH-001)

- 新增 `CoursePackageV1`、`ScenarioTemplateV1`、`GameSessionV1`、`TurnV1`、`NpcStateV1` 与 `DossierV1` 不可变 Pydantic 契约和跨对象引用校验。
