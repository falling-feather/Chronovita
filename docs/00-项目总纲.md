## 1. 项目定位

Chronovita 是面向中小学历史学习与国家级创新训练成果展示的历史仿真学习平台，不是普通课程网页或自由问答站点。项目用“看、练、问、创”组织一节课，并把历史事实、人物立场、局势变量、行动约束、事件、证据和学习成果连接成可执行、可回放、可审校的学习链路。

核心创新方向：

| 方向 | 项目表达 |
| --- | --- |
| 可执行历史局势 | 教师用低代码规则描述变量、人物、行动、事件与结局，规则引擎负责权威状态和结局裁定 |
| 证据约束的 AI | 模型只承担行动理解和受 facts/source_refs/persona 约束的表达，不直接决定史实真值 |
| 可复盘学习证据 | 每次行动、状态变化、依据和结局形成可验证回放与史官卷宗，并进入知识画板 |
| 教师可持续生产 | 课程、人物、关键词和关卡从草稿、审校、封存到发布均由结构化制品驱动，不写死在页面代码中 |

## 3. 当前开发主线

当前激活的是 `class` 分支上的“课程内容历史库与教师发布”目标：

```text
已审校并封存的课程版本
  -> 生成稳定命名、带校验和的课程包
  -> 发布到独立私有 GitHub 内容历史库
  -> 默认创建 Pull Request，保留审校与追踪入口
  -> 教师只看到“发布到课程历史库”和结果状态
```

该 Git 仓库承担不可变课程版本、审校差异和历史追踪，不替代运行数据库。草稿、会话状态、发布任务状态和账号数据继续由应用数据库管理；密钥只保存在后端环境或秘密管理系统中。

正式课文、人物史实、关键词释义和资料审校继续由教师团队维护，开发组本轮不代写或批量改写。

## 6. 版本与任务规则

1. 当前中版本为 `V0.9.x`，核心开发组可在 [02-项目规划与设计总纲](02-项目规划与设计总纲.md) 中登记并分配未占用补丁版本。
2. 每个开发任务使用唯一三位流水号，例如 `DOC-002`、`ARCH-004`；只有“已完成”任务使用 `[x]`。
3. 一次 Git 提交只对应一个任务编号；实际改动、任务状态、开发历史和稳定实现说明在同一提交同步。
4. 提交标题采用 `V大.中.小 GROUP type(scope): 描述（TASK-ID）`，开发历史标题与 Git 提交标题一致。
5. 计划目标与当前实现不混写；未经过代码、测试或运行结果验证的能力不得写成“已完成”。
