## 2. 项目设计路线速读

Chronovita 不是普通 AI 问答网站，也不是只放视频和地图的资料库。它的设计路线是把一节历史课拆成四个可交互学习动作：

```text
看：地图、课文、视频、关键词，建立历史图景
练：saga / sandbox，把历史情境变成可推演的抉择局
问：专家 / 历史人物双模态智能体，解释疑惑与时代视角
创：知识画板和智能笔记，把学习结果沉淀为个人知识谱系
```

开发时要始终保留这个闭环。新增功能如果无法归入“看、练、问、创”中的某一层，通常应先回到产品规划讨论，而不是直接加页面。

## 3. 技术路径

        |
FastAPI + Pydantic 后端
        |
services 业务服务层
        |
SQLite KV 持久化 + 文件化课程素材 + LLM 适配层

## 4. 管理员内容编辑器可行路径

后端依托管理员账号进入内容编辑器，快速编写课文式内容，并将成品封存为文件，这件事是现实的，而且很适合当前项目。建议把它定义为“内容生产后台”，而不是复杂 CMS。

推荐落地方式：

| 层 | 设计 |
| --- | --- |
| 权限 | 增加管理员登录态或轻量 token，所有写入接口挂在 `/api/v1/admin/content` 下 |
| 前端 | 新增 `/admin/content` 页面，提供课文、关键词、人物、地图点、关卡素材的结构化编辑 |
| 后端 | 用 Pydantic schema 校验内容包，保存草稿、预览、审校状态和封存快照 |
| 文件 | 草稿写入 `content/drafts/`，封存版本写入 `content/sealed/` 或 `content/courses/` |
| 封存 | 生成不可直接覆盖的版本文件，包含 `sealed_at`、`sealed_by`、`checksum`、`source_refs` |
| 汇总 | 通过 manifest 汇总课程包，再由脚本或接口同步到 `services/courses/` |

建议的文件格式是 Markdown + YAML frontmatter，原因是内容团队容易编辑，后续也方便汇总、审校、导出和进入 Git 版本管理：

```markdown
---
lesson_id: xia-yu-flood
title: 大禹治水
unit: 文明起源与早期国家
status: sealed
version: 1
sealed_at: 2026-07-06T00:00:00+08:00
sealed_by: admin
source_refs:
  - 教材页码或资料编号
checksum: 待生成
---

# 课文正文

这里写学生可阅读的课文内容。
```

需要注意：开发期可以让后端直接写入仓库文件；如果进入生产部署，容器内文件系统可能不可持久化，届时应改成数据库/对象存储/Git 提交流程。当前阶段先做“管理员编辑 -> 文件封存 -> manifest 汇总 -> 课程服务读取”是成本最低、最符合项目需要的路线。

当前 A1 已落地第一版轻量链路：

| 能力 | 当前实现 |
| --- | --- |
| 管理入口 | `/admin/content` 提供低代码表单编辑、正文重点解析、草稿库、预览、保存草稿、封存和 JSON 导出 |
| 鉴权 | `/api/v1/admin/content` 使用临时 token，支持 `Authorization: Bearer <token>` 与 `X-Admin-Token` |
| Schema | `services/content/LessonContentPackage` 校验课文、标题、单元、时代、关键词、人物、地图点、资料来源、facts、问答点、关卡目标、saga/sandbox 占位 |
| 草稿 | `POST /api/v1/admin/content/drafts` 写入 `content/drafts/{lesson_id}.json`，允许反复覆盖；前端同时保留浏览器本地暂存，刷新可恢复未保存内容 |
| 预览 | `POST /api/v1/admin/content/preview` 返回后端规范化后的内容包，不写文件 |
| 封存 | `POST /api/v1/admin/content/drafts/{lesson_id}/seal` 生成 `content/sealed/{lesson_id}-vNNN.json`，记录 `status/version/sealed_at/sealed_by/source_refs/checksum` |
| 课程读取 | `services/courses` 动态读取最新 sealed 文件；若 `course_id` 命中旧课程则覆盖或追加课时，否则生成文件化内容课程 |
| 前端展示 | 课时“看”层展示 sealed 正文、关键词、人物卡、地图点、参考资料和 AI 预留素材摘要 |

### 4.1 V1 课程运行契约

`ARCH-001` 已在不改变现有内容接口、saga 和 sandbox 行为的前提下建立规范 V1 对象：

| 对象 | Python 模型 | 主要职责 |
| --- | --- | --- |
| 课程包 | `services.contracts.CoursePackageV1` | 表示一节可封存课时，保留现有课程字段并为人物、关键词、facts、资料和关卡建立稳定 ID |
| 关卡模板 | `services.contracts.ScenarioTemplateV1` | 描述变量、NPC、行动、条件事件、结局规则和卷宗模板；条件与效果使用带 `kind` 的可判别结构，不允许任意代码表达式 |
| 游戏会话 | `services.contracts.GameSessionV1` | 固定课程包/关卡版本与 checksum，保存完整回合、状态快照、NPC 状态、节点、摘要、叙事观察和恢复信息 |
| 史官卷宗 | `services.contracts.DossierV1` | 保存关键回合、状态轨迹、主要代价、史实解释、知识节点与关系边，并引用原始 facts 和资料 |

`TurnV1`、`NpcStateV1` 是 `GameSessionV1` 的规范嵌套对象。四个顶层对象都使用固定 `schema_version`，禁止未知字段，时间字段要求带时区；ID 保持现有 2-64 位 ASCII 规则并区分大小写。契约对象为不可变值对象，更新时必须通过 `model_copy` 后重新校验，不能靠字段赋值留下半合法状态。课程包和关卡的 `status` 只表达 `draft|sealed` 制品状态，校验、审校、发布和回滚由后续 `BE-001` 的独立发布记录管理，避免破坏旧读取器只识别 sealed 文件的行为。

`RuntimeBundleV1` 是跨对象语义校验入口：除版本、ID 与 checksum 绑定外，还会从场景初始值按回合重算行动可用性、状态效果、自动事件、NPC 变化、节点迁移与结局优先级，并核对卷宗结局、完整状态轨迹、会话时间线和关键选择原始输入。它用于拒绝“快照结构正确但不可能由规则产生”的伪造记录；接收玩家输入并实际推进游戏的通用执行器仍由 `GAME-001` 实现。

V1 回放顺序固定为：校验当前节点与行动前置条件，先应用行动效果，再基于“行动后、事件前”的状态筛选事件；事件按 `priority + event_id` 稳定排序后依次应用，`once=true` 的事件只触发一次。数值效果逐条限制在变量或 NPC 的声明范围内，`rejected|failed` 回合不得产生状态、NPC 或事件效果。首次满足结局后不得继续追加回合，节点显式结局优先，否则选择满足条件且优先级最高的结局；会话不得超过 `max_turns`，active 恢复态的可用行动清单也必须能从当前状态复算。`GAME-001` 必须复用同一语义，不能另设一套隐式顺序。

契约文件与样板位于：

```text
services/contracts/                 Pydantic V1 模型、跨对象校验和 legacy 适配器
content/schemas/v1/                 可交给其他服务使用的 JSON Schema 2020-12 文件
content/examples/v1/                大禹治水课程、关卡、会话、卷宗和完整 bundle 技术夹具
scripts/export_runtime_contracts.py 可重复生成 schema 与样板文件
tests/test_runtime_contracts.py     schema 漂移、规则回放、引用、checksum、兼容与篡改测试
```

在仓库根目录重新生成并验证：

```powershell
& ".\.venv\Scripts\python.exe" scripts\export_runtime_contracts.py
& ".\.venv\Scripts\python.exe" -m unittest discover -s tests -v
```

正常结果为导出两个 `content/*/v1` 目录，且当前 24 项后端测试全部通过。生成器会清理这两个目录中不再属于清单的旧 JSON，防止废弃 schema 或样板继续被下游误读。对外 JSON Schema 要求显式提供 `status`，防止省略默认值绕过生命周期分支。V1 draft 允许正文或关卡规则暂未写完，但不能携带封存元数据；sealed 才强制正文、变量、行动、结局、版本和 checksum 完整。checksum 只能对已经通过 Pydantic 校验的模型计算，不能直接签名未经规范化的原始字典。

`course_package_from_legacy()` 会保留旧 `LessonContentPackage` 的课程元数据、`draft|sealed`、版本、时间、saga/sandbox 素材和暂未解析引用；合法的旧画布 ID 原样保留，必须替换的 ID 写入 `compatibility.legacy_id_map`。旧 sealed 内容必须先通过源 checksum 校验，源 checksum 写入 `compatibility.source_checksum`，转换后的 V1 制品再生成自己的可复算 checksum，避免把被修改的旧文件重新签成可信制品。旧格式缺少逐条事实来源绑定时不会自行推测关系。大禹治水样板中的历史正文、facts、人物 persona 和解释均标有“教师待审”，只用于开发验收。

当前边界：V1 契约尚未接管现有课程读取、saga 或 sandbox。接入发布清单属于 `BE-001`，文件驱动规则引擎属于 `GAME-001`，会话持久化与回放属于 `BE-002`。

## 10. 核心数据流

### 10.1 课程读取

```text
前端课程页
  -> GET /api/v1/courses
  -> courses.list_courses()
  -> 内置课程 + content/sealed 最新内容包合并后的 CourseSummary 列表

课时页
  -> GET /api/v1/courses/{course_id}/lessons/{lesson_id}
  -> courses.get_lesson(lesson_id)
  -> 若存在 sealed lesson_id，优先返回封存正文、关键词、人物、地图点、资料来源、AI 预留字段
  -> 否则返回内置课程正文、关键词、人物、seed canvas、sandbox_id
```

### 10.2 saga 推演

```text
LessonPractice
  -> POST /practice/saga/start {lesson_id}
  -> saga.start(lesson_id)
  -> 开场、候选行动、persona、keywords

学生行动
  -> POST /practice/saga/{saga_id}/act {action}
  -> saga.act_stream()
  -> llm.stream_chat()
  -> text/plain 流式正文 + [META] JSON
```

saga 模板包含 `facts`、`era`、`setting`、`persona`、`opening`、`initial_choices`、`keywords`。`step >= 5` 倾向收束，`step >= 7` 必须收束。

### 10.3 sandbox 决策沙盘

```text
GET /practice/sandbox/{sid}
  -> scenario、start node、init_state

POST /practice/sandbox/{sid}/step
  -> sandbox.step()
  -> 下一节点、feedback、新 state
```

未来「历史抉择局」优先在 `sandbox` 扩展状态机，再由 saga/LLM 做叙事包装。

### 10.4 ask 双模态问答

```text
POST /practice/ask
  -> practice._system_prompt(persona)
  -> llm.stream_chat(model=deepseek_model_pro)
  -> text/plain 流式返回
```

| persona | 角色 | 约束 |
| --- | --- | --- |
| `expert` | 历史专家/教师 | 教材共识、争议标注、不编造、250 字内 |
| `peer` | 历史人物同伴 | 第一人称、时代边界、不预言后世、200 字内 |

### 10.5 canvas 画板

```text
GET /practice/canvas/{lesson_id}
PUT /practice/canvas/{lesson_id}
POST /practice/canvas/generate
```

画板保存在 SQLite KV：namespace=`canvas`，key=`lesson_id`。

### 10.6 学习进度

```text
POST /learning/progress/touch
namespace="lesson_progress"
key="default:{lesson_id}"
```

当前单用户 `default`，多用户接入后需要真实用户 ID、鉴权和数据隔离。

## 12. LLM 适配层

统一入口：

```python
stream_chat(messages, provider=None, model=None)
```

| provider | 说明 |
| --- | --- |
| `mock` | 离线兜底，保障课堂主流程不中断 |
| `deepseek` | OpenAI 兼容协议，支持 `deepseek-v4-flash` 与 `deepseek-v4-pro` |

模型分工：

- saga：速度优先，默认 `deepseek-v4-flash`。
- ask：准确度优先，显式 `deepseek-v4-pro`。
- 异常或无 API Key：回落 mock。

规则：

- 业务层不得直接拼 LLM HTTP。
- LLM 不决定史实真值；史实边界来自课程 facts、RAG 和教师审校。
- mock 回退是课堂可靠性设计，不是临时调试残留。
