## 2. 项目设计路线速读

Chronovita 不是普通 AI 问答网站，也不是只放视频和地图的资料库。它的设计路线是把一节历史课拆成四个可交互学习动作：

```text
看：地图、课文、视频、关键词，建立历史图景
练：saga / sandbox，把历史情境变成可推演的抉择局
问：专家 / 历史人物双模态智能体，解释疑惑与时代视角
创：知识画板和智能笔记，把学习结果沉淀为个人知识谱系
```

开发时要始终保留这个闭环。新增功能如果无法归入“看、练、问、创”中的某一层，通常应先回到产品规划讨论，而不是直接加页面。

## 3. 技术路径

当前项目采用开发期单体架构，优先保证本地可演示、可快速迭代、可逐步迁移：

```text
React + Vite + TypeScript + Ant Design 前端
        |
FastAPI + Pydantic 后端
        |
services 业务服务层
        |
SQLite KV 持久化 + 文件化课程素材 + LLM 适配层
```

中长期演进路径：

| 阶段 | 技术方向 |
| --- | --- |
| 当前 | SQLite、mock/DeepSeek/OpenAI 兼容 LLM、本地课程数据、单用户或轻量演示 |
| 近期 | 管理员内容编辑器、课程文件封存、内容审校状态、关键路径测试 |
| 中期 | Postgres、对象存储或 Git 化内容仓库、教师后台、班级与作业 |
| 长期 | 向量库/RAG、内容版本审计、多模型路由、生产部署与权限治理 |

## 4. 管理员内容生产与发布

当前实现是单管理员、文件驱动的内容生产后台，不是生产级多用户 CMS。`LessonContentPackage.status` 只描述 `draft|sealed` 制品状态；审校和学生可见性由独立工作流与课程发布清单决定。**封存不等于发布**。

```text
保存草稿 -> 最低字段校验 -> 提交审校 -> 退回或通过 -> 封存不可变制品 -> 发布整课快照
                                                                    |
学生课程 API <- V1 课程投影 <- 活动指针 <- 课程发布清单 <-----------+
                                      ^
                                      └------------ 回滚生成新快照
```

| 层 | 当前实现 |
| --- | --- |
| 鉴权 | `/api/v1/admin/content` 使用临时 admin token，支持 Bearer 与 `X-Admin-Token`；配置无默认通用口令，一键启动脚本为本次进程生成随机 token；审计操作者固定取认证后的 `CHRONO_ADMIN_ACTOR`，请求体中的显示名称不能伪造审计身份 |
| 编辑制品 | `LessonContentPackage` 禁止未知字段，保存到 `content/drafts/{lesson_id}.json`；重复保存相同正文不会撤销已有审校状态，实质内容变化会清除旧校验与批准 |
| 最低校验 | `validate_package()` 阻止空正文、无关键词释义、无人物摘要、无 facts 或无可追溯资料的内容进入审校；AI persona、问答点、地图点和互动目标当前为警告 |
| 审校记录 | `content/workflows/{lesson_id}.json` 保存状态、revision、校验报告和连续事件历史；保存、校验、提交、退回、通过、封存、发布和回滚均留操作者与时间 |
| 封存制品 | `content/sealed/{lesson_id}-vNNN.json` 不可覆盖，记录版本、时间、操作者和 SHA-256；只有 `approved` 的当前草稿可以封存 |
| V1 制品 | 发布时通过 `course_package_from_legacy()` 生成 `content/packages/v1/{lesson_id}-vNNN.json`，同时固定旧 sealed checksum 与 V1 checksum |
| 发布清单 | `content/releases/manifests/{course_id}/{release_id}.json` 是不可变整课快照；`content/releases/active/{course_id}.json` 是原子替换的活动指针，也是学生可见性的唯一提交点 |
| 发布事务 | `content/releases/transactions/{course_id}.json` 在指针切换前记录旧/新工作流投影；API 启动时依据活动指针自动完成或回滚，成功后立即删除 |
| 学生读取 | `services/courses` 只读取活动清单指定的 V1 制品，并返回 `release_id`、`release_no`、`release_checksum`；校验失败时课程 API 返回稳定 `503`，不回退到未发布内容 |
| 回滚 | 回滚不改写历史文件，而是先复验目标快照全部制品，再复制为新的 release 并移动活动指针；不同课程互不连带回滚 |

关键管理接口：

| 方法与路径 | 前置状态 | 结果 |
| --- | --- | --- |
| `POST /api/v1/admin/content/drafts` | 任意可校验草稿 | 原子保存草稿，建立或刷新工作流 |
| `POST /drafts/{lesson_id}/validate` | 已保存草稿 | 只写入最低内容校验报告，不改变任何学生可见内容或 release |
| `POST /drafts/{lesson_id}/submit-review` | `validated|changes_requested` | 进入 `in_review` |
| `POST /drafts/{lesson_id}/review` | `in_review` | `approve` 进入 `approved`；`changes_requested` 必须附退回说明 |
| `POST /drafts/{lesson_id}/seal` | `approved` | 生成不可变 sealed 版本，学生端仍保持原发布内容 |
| `POST /sealed/{lesson_id}/versions/{version}/publish` | 当前工作流的 sealed 版本 | 生成整课 release 并切换活动指针 |
| `POST /releases/{course_id}/bootstrap-legacy` | 无活动 release；显式列出 `lesson_id + content_version` | 对白名单旧 sealed 逐份校验后建立首个受管 release；不允许目录扫描自动发布 |
| `POST /releases/{course_id}/rollback` | 已有活动 release | 以历史 release 为目标生成新的回滚快照 |

所有 signed metadata、sealed 和 V1 制品在读取时都会复算 checksum，并校验文件路径、文件名、课程 ID、课时 ID 和版本身份。单文件写入使用同目录临时文件、`flush + fsync` 和原子替换；不可变文件使用原子硬链接实现“只创建、不覆盖”。发布与回滚先复验快照内全部 sealed/V1 制品和跨课程 `lesson_id` 唯一性，再完成 manifest 和整门课程的工作流投影，最后才原子替换 active pointer；接口返回失败时学生仍读取原 release。`content/releases/transactions/` 保存短生命周期恢复日志，API 重启时按活动指针完成或回滚中断事务；可重入的全局工作流文件锁串行化本机多 worker 的保存、审校、封存和发布操作。生产集群跨主机部署时仍应迁移到支持事务/CAS 的数据库或对象存储。

兼容规则：学生课程服务不扫描 `content/sealed` 猜测最新版本。历史 sealed 只有通过管理员 `bootstrap-legacy` 接口显式列出课时与版本、通过最低发布校验并生成 active pointer 后才可见；普通草稿校验和封存都不会触发迁移。内置 Python 课程继续作为没有发布覆盖时的回退。

### 4.1 V1 课程运行契约

`ARCH-001` 已在不改变现有内容接口、saga 和 sandbox 行为的前提下建立规范 V1 对象：

| 对象 | Python 模型 | 主要职责 |
| --- | --- | --- |
| 课程包 | `services.contracts.CoursePackageV1` | 表示一节可封存课时，保留现有课程字段并为人物、关键词、facts、资料和关卡建立稳定 ID |
| 关卡模板 | `services.contracts.ScenarioTemplateV1` | 描述变量、NPC、行动、条件事件、结局规则和卷宗模板；条件与效果使用带 `kind` 的可判别结构，不允许任意代码表达式 |
| 游戏会话 | `services.contracts.GameSessionV1` | 固定课程包/关卡版本与 checksum，保存完整回合、状态快照、NPC 状态、节点、摘要、叙事观察和恢复信息 |
| 史官卷宗 | `services.contracts.DossierV1` | 保存关键回合、状态轨迹、主要代价、史实解释、知识节点与关系边，并引用原始 facts 和资料 |

`TurnV1`、`NpcStateV1` 是 `GameSessionV1` 的规范嵌套对象。四个顶层对象都使用固定 `schema_version`，禁止未知字段，拒绝 `NaN`/无穷数，时间字段要求带时区；ID 保持现有 2-64 位 ASCII 规则并区分大小写。Pydantic 的 `frozen` 只阻止顶层字段重新赋值，不能深冻结嵌套列表与字典；规则运行时必须复制输入、构造并重新校验新模型，禁止原位修改 sealed 制品或会话。课程包和关卡的 `status` 只表达 `draft|sealed` 制品状态，校验、审校、发布和回滚由 `BE-001` 的独立发布记录管理。

`RuntimeBundleV1` 是跨对象语义校验入口：除版本、ID 与 checksum 绑定外，还会从场景初始值按回合重算行动可用性、状态效果、自动事件、NPC 变化、节点迁移与结局优先级，并逐项核对 `state_changes`、`fact_refs`、`ruleset_hash` 和规则叙事，再核对卷宗结局、完整状态轨迹、会话时间线和关键选择原始输入。它用于拒绝“快照结构正确但不可能由规则产生”的伪造记录。`services/game_runtime/SituationEngineV1` 已能从 sealed 课程包和关卡文件启动、推进与重放会话；每次输入先通过 JSON 投影重建并深度校验，防止嵌套列表或字典被原位改写后绕过 Pydantic 验真。

V1 回放顺序固定为：校验当前节点与行动前置条件，先应用行动效果，再基于“行动后、事件前”的状态一次性筛选事件；事件按 `priority + event_id` 稳定排序后依次应用，`once=true` 的事件只触发一次，同回合事件之间不级联选取。数值效果逐条限制在变量或 NPC 的声明范围内，`rejected|failed` 回合不得产生状态、NPC 或事件效果。首次满足结局后不得继续追加回合，节点显式结局优先，否则选择满足条件且优先级最高的结局；命中结局的会话不能伪装成 `failed|abandoned`。会话不得超过 `max_turns`，`revision` 必须恒等于 `current_turn + 1`，active 恢复态的可用行动清单也必须能从当前状态复算。`client_action_id` 重试还必须携带产生原回合时的 `expected_revision`，不能在后续修订号上把旧动作误认成新重试。生成和验真共同调用 `services/contracts/rules_v1.py`，不得另设一套隐式顺序。

sealed 契约文件使用单一二进制句柄读取：先以 `fstat` 确认为普通文件并限制为 2 MiB，再做上限加一的有界读取，最后用 `lstat` 拒绝符号链接并核对打开对象与路径对象身份。JSON 仍拒绝重复 key、非法 UTF-8、未知字段和 checksum 篡改；不能恢复为“先检查路径、再按路径另读一次”的两阶段实现。

契约文件与样板位于：

```text
services/contracts/                 Pydantic V1 模型、共享 rules_v1 reducer、跨对象校验和 legacy 适配器
services/game_runtime/              sealed 文件加载、显式场景目录、会话协调、行动推进、幂等与确定性重放
content/schemas/v1/                 可交给其他服务使用的 JSON Schema 2020-12 文件
content/examples/v1/                大禹状态式与商鞅节点式课程/关卡技术夹具，教学内容均待教师审校
content/scenarios/catalog.v1.json   显式 allowlist，固定课程/关卡版本、checksum、路径与 audience
scripts/export_runtime_contracts.py 可重复生成 schema 与样板文件
tests/test_runtime_contracts.py     schema 漂移、规则回放、引用、checksum、兼容与篡改测试
tests/test_game_runtime.py          双模板加载、在线推进、重放、节点、NPC、终态、幂等与篡改测试
tests/test_game_api.py              目录边界、API 全链路、并发、错误映射、会话隔离与 legacy 兼容测试
```

在仓库根目录重新生成并验证：

```powershell
& ".\.venv\Scripts\python.exe" scripts\export_runtime_contracts.py
& ".\.venv\Scripts\python.exe" -m unittest discover -s tests -v
```

正常结果为导出两个 `content/*/v1` 目录，且当前后端全量 70 项测试全部通过。生成器会清理这两个目录中不再属于清单的旧 JSON，防止废弃 schema 或样板继续被下游误读。对外 JSON Schema 要求显式提供 `status`，防止省略默认值绕过生命周期分支。V1 draft 允许正文或关卡规则暂未写完，但不能携带封存元数据；sealed 才强制正文、变量、行动、结局、版本和 checksum 完整。checksum 只能对已经通过 Pydantic 校验的模型计算，不能直接签名未经规范化的原始字典。

`course_package_from_legacy()` 会保留旧 `LessonContentPackage` 的课程元数据、`draft|sealed`、版本、时间、saga/sandbox 素材和暂未解析引用；合法的旧画布 ID 原样保留，必须替换的 ID 写入 `compatibility.legacy_id_map`。旧 sealed 内容必须先通过源 checksum 校验，源 checksum 写入 `compatibility.source_checksum`，转换后的 V1 制品再生成自己的可复算 checksum，避免把被修改的旧文件重新签成可信制品。旧格式缺少逐条事实来源绑定时不会自行推测关系。大禹治水样板中的历史正文、facts、人物 persona 和解释均标有“教师待审”，只用于开发验收。

当前边界：`GAME-001` 已完成纯规则内核、显式 checksum 固定场景目录、临时会话协调与 V1 游戏 API。目录中的两份样板均为 `audience=development`，不会伪装成正式教学内容；课程发布流程尚未物化 `audience=published` 的关卡制品。游戏会话当前只保存在单进程内存，API 重启后的恢复、卷宗生成和正式课程/关卡联合发布属于 `BE-002`；真实用户鉴权与隔离沿用后续身份任务。

## 9. 服务层职责

| 服务 | 当前职责 | 后续演进 |
| --- | --- | --- |
| `services/courses/` | 内置课程与已发布 `CoursePackageV1` 的学生读取投影；附带 release 身份并对损坏发布失败关闭 | 接入 `GAME-001` 时固定课程与关卡 release |

| `services/contracts/` | V1 课程运行契约、跨对象引用校验、checksum 和旧内容包适配 | 供发布、局势引擎、会话持久化与 AI 编排共同使用 |
| `services/game_runtime/` | 从显式 allowlist 加载 checksum 固定的 sealed 课程包与关卡，构造 `SituationEngineV1`；复制式推进并隔离存储 `GameSessionV1`，处理别名、行动条件、状态/NPC/事件/节点/结局、幂等 `client_action_id`、`revision` 冲突与确定性重放 | 单进程临时协调已由 `GAME-001` 完成；数据库恢复、卷宗和 published 联合发布由 `BE-002` 接续 |

## 10. 核心数据流

### 10.1 课程读取

```text
前端课程页
  -> GET /api/v1/courses
  -> courses.list_courses()
  -> 内置课程 + 每门课程 active release 指定的 V1 内容包

课时页
  -> GET /api/v1/courses/{course_id}/lessons/{lesson_id}
  -> courses.get_lesson(lesson_id)
  -> load_published_snapshots() 严格校验 pointer、manifest、旧 sealed 与 V1 checksum
  -> 若存在已发布 lesson_id，返回正文、关键词、人物、地图点、资料与 release 身份
  -> 否则返回内置课程正文、关键词、人物、seed canvas、sandbox_id
  -> 任一已发布制品损坏时返回 503，不扫描目录猜测“最新版本”
```

### 10.2 saga 推演

```text
LessonPractice
  -> POST /practice/saga/start {lesson_id}
  -> saga.start(lesson_id)
  -> 开场、候选行动、persona、keywords

学生行动
  -> POST /practice/saga/{saga_id}/act {action}
  -> saga.act_stream()
  -> llm.stream_chat()
  -> text/plain 流式正文 + [META] JSON
```

saga 模板包含 `facts`、`era`、`setting`、`persona`、`opening`、`initial_choices`、`keywords`。`step >= 5` 倾向收束，`step >= 7` 必须收束。

### 10.3 sandbox 决策沙盘与 V1 局势核心

legacy 接口保持兼容：

```text
GET /practice/sandbox/{sid}
  -> scenario、start node、init_state

POST /practice/sandbox/{sid}/step
  -> sandbox.step()
  -> 下一节点、feedback、新 state
```

legacy `sandbox.step()` 信任客户端传入 state，只供旧页面兼容，禁止用于 V1 会话。V1 核心调用链为：

```text
SituationEngineV1.from_files(course_path, scenario_path)
  -> UTF-8 JSON、重复 key、sealed 状态、checksum 与 RuntimeBundle 跨引用校验
  -> start_session(...)
  -> 初始变量、NPC、节点、可用行动与精确制品身份

apply_action(session, RuntimeCommandV1)
  -> 复验完整历史和 expected_revision
  -> rules_v1.evaluate_rule_action()
  -> 行动效果 -> 事件筛选/执行 -> 节点迁移 -> 结局裁定
  -> 生成 TurnV1 与新 GameSessionV1
  -> RuntimeBundleV1 再次确定性回放验真
```

固定按钮文本可按 `action_id`、label 或 alias 确定性解析；`free_input|fallback` 必须由上游显式给出 `action_id`，当前核心不会用模糊字符串或 LLM 猜测行动。相同 `client_action_id` 和相同输入返回原结果，不同输入复用该 ID 会冲突；`expected_revision` 防止并发覆盖。引擎不在原模型上修改嵌套字典或列表。达到 `max_turns` 却没有模板结局、或未到上限但没有可用行动时，关闭为可解释的 `failed` 状态。

V1 API 调用链：

```text
GET  /api/v1/practice/game/scenarios
  -> 只读取 catalog.v1.json 明确列出的 active 条目
  -> 返回固定版本/checksum、课程身份、audience 与关卡摘要

POST /api/v1/practice/game/sessions {scenario_id}
  -> 服务端生成 session_id 和初始权威状态

GET  /api/v1/practice/game/sessions/{session_id}
  -> 返回服务端保存的会话副本

POST /api/v1/practice/game/sessions/{session_id}/turns
  -> 只接收 client_action_id、action_id、raw_input、expected_revision 与分类元数据
  -> 客户端 state/current_turn/ending 等权威字段因 extra=forbid 被拒绝
```

场景路径相对 `CHRONO_CONTENT_ROOT`，必须是规范 POSIX JSON 路径；仓库不扫描目录猜测关卡。catalog 和制品都使用有界单句柄读取，拒绝逃逸、符号链接、重复 key、路径身份或 checksum 漂移。同一课程包可供多个关卡复用，但路径对应的课程 ID、课时 ID、版本与 checksum 必须完全一致。API 的 `session_storage=ephemeral` 是显式契约：当前 `RLock` 串行化同一进程中的权威更新，存储与返回对象深度分离；进程退出会清空会话并释放 SQLite，不能承诺跨重启续玩。

### 10.4 ask 双模态问答

```text
POST /practice/ask
  -> practice._system_prompt(persona)
  -> llm.stream_chat(model=deepseek_model_pro)
  -> text/plain 流式返回
```

| persona | 角色 | 约束 |
| --- | --- | --- |
| `expert` | 历史专家/教师 | 教材共识、争议标注、不编造、250 字内 |
| `peer` | 历史人物同伴 | 第一人称、时代边界、不预言后世、200 字内 |

### 10.5 canvas 画板

```text
GET /practice/canvas/{lesson_id}
PUT /practice/canvas/{lesson_id}
POST /practice/canvas/generate
```

画板保存在 SQLite KV：namespace=`canvas`，key=`lesson_id`。

### 10.6 学习进度

```text
POST /learning/progress/touch
namespace="lesson_progress"
key="default:{lesson_id}"
```

当前单用户 `default`，多用户接入后需要真实用户 ID、鉴权和数据隔离。

## 12. LLM 适配层

统一入口：

```python
stream_chat(messages, provider=None, model=None)
```

| provider | 说明 |
| --- | --- |
| `mock` | 离线兜底，保障课堂主流程不中断 |
| `deepseek` | OpenAI 兼容协议，支持 `deepseek-v4-flash` 与 `deepseek-v4-pro` |

模型分工：

- saga：速度优先，默认 `deepseek-v4-flash`。
- ask：准确度优先，显式 `deepseek-v4-pro`。
- 异常或无 API Key：回落 mock。

规则：

- 业务层不得直接拼 LLM HTTP。
- LLM 不决定史实真值；史实边界来自课程 facts、RAG 和教师审校。
- mock 回退是课堂可靠性设计，不是临时调试残留。

## 13. 本地开发

后端：

```powershell
python -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install -r apps/api/requirements.txt
& ".\.venv\Scripts\python.exe" -m uvicorn apps.api.main:app --reload --host 127.0.0.1 --port 8000
```

后端请从仓库根目录启动。SQLite 与内容封存目录都按仓库根解析；在 Windows 中文路径下从 `apps/api` 子目录启动，可能触发 SQLite 写入失败。

前端：

```powershell
cd apps/web
npm ci
npm run dev
```

Windows 教师编辑器可在仓库根目录双击 `点我一键启动（部署）.cmd`。脚本首次运行创建 `.venv`、安装锁定依赖、为当前进程生成随机 `CHRONO_ADMIN_TOKEN`，再启动 API 与 Vite；API 依赖按 `requirements.txt` SHA-256 复用，文件未变化时不会重复联网安装。根 `.cmd` 保持 ASCII 输出以规避 cmd 中文编码差异。手动启动时必须显式设置 `CHRONO_ADMIN_TOKEN`，未配置时所有管理员接口返回 `503`。
