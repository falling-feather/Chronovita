## 1. 内容团队的工作目标

内容团队不是只写课文，而是为每节课制作一个可进入、可推演、可追问、可沉淀的学习包：

```text
课程背景 -> 地图与时空 -> 正文课文 -> 关键词 -> 人物池
-> 历史抉择局 -> 问答边界 -> 史官卷宗 -> 知识图谱种子
```

所有史实内容进入代码或正式发布前必须审校。

## 2. 课程制作包结构

每节课建议按以下模板制作：

| 模块 | 产物 | 说明 |
| --- | --- | --- |
| 基础信息 | 课程标题、时代、地点、适用年级、核心问题 | 决定课程定位 |
| 课文正文 | 3-6 段教材级正文 | 可直接供「看」层阅读 |
| 时空信息 | 地图点位、路线、区域、时间轴节点 | 供地图和关卡使用 |
| 关键词卡 | 5-8 个关键词 | 包含解释、拼音、史实边界 |
| 人物池 | 2-5 个课程人物 + 可选观察者 | 供「问」和议事厅使用 |
| facts | 5-8 条不可违反史实 | 供 saga/ask/sandbox 约束 |
| 情境任务 | 学生身份、任务书、胜败条件 | 供历史抉择局入局 |
| 状态变量 | 3-6 个变量 | 如民心、财政、军力、信任、风险 |
| 回合事件 | 5-7 个事件卡 | 供练习过程推进 |
| 结局复盘 | 成功、代价型成功、失败、纠偏解释 | 供史官卷宗 |
| 知识图谱种子 | 5-8 个节点和关系 | 供「创」层初始画板 |
| 资料来源 | 教材、史料、参考书、链接 | 供审校与 RAG |

当前管理员内容编辑器由低代码表单、正文格式工具栏和预览页承载教师写作，底层仍以 JSON 内容包作为草稿、封存和可复刻导出格式；教师不需要直接编辑 JSON。教师团队写作时优先填写这些字段：

| 字段 | 写法 |
| --- | --- |
| `lesson_id` | 稳定课时 ID，只用英文、数字、点、下划线或短横线，例如 `xia-yu-flood` |
| `course_id` / `course_title` | 所属课程 ID 与课程名；新课程可先用 `C-content-studio` |
| `title` / `unit` / `era` | 课时标题、课程单元、历史时代 |
| `body` | 3-6 段学生可读正文，数组中每一项是一段 |
| `keywords` | `word/pinyin/gloss` 三列，解释要面向学生 |
| `people` | `name/role/summary/persona/boundaries`，其中 `persona` 供后续人物智能体使用 |
| `map_points` | `label/region/note/lat/lng/kind`，坐标可暂缺 |
| `source_refs` | `title/source/url_or_path/citation_note/reliability`，必须能追溯来源 |
| `facts` | 5-8 条不可违反史实，后续约束 AI 助教、saga 与 sandbox |
| `qa_points` | 学生可能追问、教师希望 AI 能回答的问题 |
| `level_goals` | 历史抉择局或关卡目标 |
| `saga_material` / `sandbox_material` | 当前只写标题、目标、备注和素材占位，不要求完整剧本 |
| `seed_canvas` | 「创」层初始知识节点，暂不要求完整关系图 |

## 3. 课文正文写法

课文正文要承担三件事：

- 给学生足够背景，不直接把所有结论塞满。
- 提供后续推演需要的事实和约束。
- 为专家问答和知识图谱留下清晰概念。

建议结构：

```text
第一段：时空与问题引入
第二段：关键人物/制度/事件
第三段：冲突与选择的困难
第四段：历史结果与影响
第五段：可讨论的解释问题
```

避免：

- 把申报书式宏大叙事直接写成课文。
- 为了戏剧性编造人物台词或事件。
- 让课文只剩考点罗列。

## 4. 目标课程蓝图

目标版本建议扩展为：

```text
10 个时代单元 -> 32 门课程 -> 87 节课
```

原则：

- 按通史建立骨架：文明起源、早期国家、大一统帝国、近现代转型、当代中国。
- 按空间打开差异：春秋战国、魏晋南北朝、宋辽夏金元、明清海疆边疆不能只按朝代顺序讲。
- 按看练问创落地：每节课都要能进入地图、推演、问答和知识谱系，而不是只列知识点。

### 5.1 L101 大禹治水正式旗舰课

V0.10.3 的 L101 不再使用旧“大禹治水技术样板”作为学生内容。人工可审校源位于 `services/content/flagships/dayu_l101.py`，通过正常课程、证据、关卡与 V3 发布流程生成正式制品。制作包包括：

| 内容层 | 已交付规模 | 课堂用途 |
| --- | --- | --- |
| 叙事正文 | 15 段、2872 字（2540 个汉字） | 从洪水风险进入传说、文献、考古与国家形成问题 |
| 史实边界 | 16 条 | 区分可观察材料、研究判断、争议和教学模型 |
| 来源与证据 | 12 项来源、30 个稳定片段 | 为后续 RAG 与卷宗引用提供当前 release 内的事实源 |
| 人物与空间 | 5 个人物/群体、4 个地图点 | 呈现首领、协作者、聚落与劳动者的不同立场，并区分遗址、自然案例和记忆地图 |
| 概念与追问 | 8 个关键词、8 个问题、4 项学习目标 | 支撑踏勘、召见和复盘 |
| 抉择与成果 | 六回合危机治理、四类结局、卷宗模板、6 个画板种子 | 保存选择、变量轨迹、事件、代价、历史解释与来源 |

内容标注规则固定为五层：`【传说】` 说明后世流传的故事细节；`【传世文献】` 说明后世文本及其成书语境；`【考古观察】` 只写遗址、器物和布局可直接支持的描述；`【考古判断/解释边界】` 说明从材料到“夏史/早期国家”的论证强度；`【教学解释】` 明示为课堂因果模型。积石峡局地洪水、二里头与夏的关系、“鲧堵禹疏”和“三过家门”均按此规则保留边界。

正式关卡仍可按钮确定性完成，不依赖模型。平衡成功、代价成功、协商折中和治理失败都有经过 reducer 验证的六回合路径；结局评价同时观察水患、粮食、劳作者处境、公共信任、地形知识和跨聚落协作，避免只按“治水成功”给出单一英雄结论。

### 5.2 L103 商鞅变法正式旗舰课

V0.10.4 的 L103 不再以旧 `scenario-shangyang-institutional-reform` 技术夹具作为学生正式内容。人工可审校源位于 `services/content/flagships/shangyang_l103.py`，通过正常课程、证据、关卡和 V3 发布流程生成：

| 内容层 | 已交付规模 | 课堂用途 |
| --- | --- | --- |
| 叙事正文 | 16 段、2952 字符 | 从“秦国变强是否等于人人获益”进入制度因果与评价 |
| 史实边界 | 19 条 | 区分战国背景、后世叙事、同时代实物、较晚秦简、文本分层和教学解释 |
| 来源与证据 | 10 项来源、30 个稳定片段 | 为 L103 后续 RAG、人物回答与卷宗提供精确发布事实源 |
| 人物与空间 | 6 个人物/群体、4 个地图点 | 呈现改革者、支持者、旧特权、农户、士卒和基层执行者 |
| 概念与追问 | 8 个关键词、8 个问题、4 项学习目标 | 支撑证据踏勘、人物召见和多因复盘 |
| 抉择与成果 | 六回合节点式制度改革、四类结局、卷宗模板、6 个画板种子 | 保存制度节点、变量轨迹、执行代价、解释和来源 |

内容按四个时间层组织：公元前四世纪中叶的方升铭文可以直接支持标准量器；《商君书》按累积文本而非单一作者手稿使用；战国晚期至秦始皇时期的睡虎地秦简只观察成熟秦制；西汉《史记》说明后世怎样组织改革人物和故事。徙木立信、廷议对白、土地制度和“商鞅一人使秦统一”都必须保留叙事或解释边界。

六回合依次经过改革启动、法令信用、耕战与身份、地方执行、纠错强度和阶段评估。国家能力、军事准备、粮食供给、制度信用、社会压力和旧贵族阻力共同变化；平衡成功、强国高压、协商折中和改革失败均有 reducer 验证路径。关卡不是秦国统计复刻，也不把现代宪政法治概念倒置到战国秦法。

## 6. 制作优先级

| 优先级 | 含义 |
| --- | --- |
| P0 | 支撑平台演示和课堂主干，优先做可互动、可推演、可问答的样板课 |
| P1 | 补齐通史骨架和关键时代转换 |
| P2 | 加强思想、经济、民族、制度等结构厚度 |
| P3-P5 | 专题深化、素材型课程、当代复杂议题和高素材成本课程 |

推进顺序：

1. 先做一节黄金样板课，把四层闭环、史实护栏、回放和创作沉淀全部打通。
2. 再做 9 节 P0 演示主线，使平台有连续可展示路线。
3. 再扩展到 18 节全量 P0。
4. 最后扩展到 87 节完整课程蓝图。

## 7. 历史抉择局内容模板

每一局关卡至少包含：

```text
关卡名
学生身份
任务书
胜利条件
失败条件
核心变量
人物与群体
回合事件
可选策略
自由输入归类规则
结局类型
史官卷宗模板
```

当前关卡交接流程：教师在 `/admin/content` 选择“关卡规则”，通过基础、指标与人物、行动、事件、结局、卷宗六个页签完成规则稿；保存服务器草稿后可反复打开修改，校验通过再封存为严格 `ScenarioTemplateV1`。封存只表示暂存；回到“课程内容”的“审校与发布”区后，选择“更新绑定”、勾选精确关卡版本并指定唯一主关卡，随课程 sealed 版本一起发布后才正式上线。“保留现状”不改线上关卡，“清空绑定”会移除该课时全部正式关卡。教师无需手写底层 JSON；“导出封存件”直接下载服务器不可变文件的原始字节，也禁止通过扫描目录猜测“最新关卡”。

### 大禹治水历史设计草图（已由 5.1 节正式稿取代）

以下内容保留用于解释早期设计如何演进，不是 V0.10.3 学生事实源；正式变量、行动、事件、结局和人物边界以活动 `dayu-crisis-governance` 及第 5.1 节为准。

关卡名：

```text
大禹治水：洪水、部族与早期国家
```

学生身份：

```text
你是受命治水的行动者，需要协助禹在多方压力下组织治水。
```

核心变量：

| 变量 | 含义 |
| --- | --- |
| 水患 | 洪水危险程度，过高会触发坏结局 |
| 民心 | 百姓对治水动员的承受和支持 |
| 粮食 | 工程和民众维持所需资源 |
| 劳力 | 可调动的人手 |
| 部族信任 | 不同部族是否愿意配合 |
| 工程认知 | 学生是否逐渐理解堵与疏的差异 |

人物与群体：

| 人物/群体 | 作用 |
| --- | --- |
| 禹 | 治水主导者，强调实地勘察、长期坚持和方法调整 |
| 百姓代表 | 体现劳役压力、疲惫和民心风险 |
| 部族首领 | 体现协作、资源分配和政治信任 |
| 工匠/水利助手 | 解释地势、河道和工程方法 |
| 历史专家 | 区分传说、文献记载和历史解释 |

回合示例：

| 回合 | 事件 | 学生选择方向 | 可能反馈 |
| --- | --- | --- | --- |
| 1 | 洪水未退，百姓疲惫 | 继续堵水 / 勘察地势 / 安抚民众 | 堵水短期见效但下游风险上升；勘察消耗时间但提升工程认知 |
| 2 | 部族首领犹豫是否出人 | 强令出工 / 解释计划 / 分配粮食 | 强令提高劳力但民心下降；解释提高信任但进度较慢 |
| 3 | 暴雨将至 | 抢修堤坝 / 开挖疏导线 / 转移聚落 | 不同选择改变水患、粮食和民心 |
| 4 | 百姓质疑工程无效 | 惩罚逃役 / 公开说明 / 调整劳力 | 体现公共动员和信任建设 |
| 5 | 疏导路线初见成效 | 扩大工程 / 保守维护 / 请求支援 | 检验前期积累 |
| 6 | 洪水退势或失控 | 收束结局 | 生成治水卷宗 |
