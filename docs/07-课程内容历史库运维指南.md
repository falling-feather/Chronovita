## 2. 职责边界

内容历史库只保存已封存课程的不可变归档和 Git 审校历史：

```text
Chronovita 数据库
  草稿、账号、审校流、发布任务状态
        |
        | 精确 sealed/published release
        v
Chronovita 归档器
  内容层 + 格式层 + 教师稿 + 预览 + 仿真素材 + 清单
        |
        | 默认 Pull Request
        v
私有内容历史库
  不可变版本、差异审校、人工批准、异地留痕
```

它不是运行时数据库，不保存浏览器临时状态，不决定学生当前看到哪个版本。学生读取仍由 Chronovita 应用侧 active release pointer 控制。

## 3. 教师操作边界

V0.9.30 已可由管理员 API 预览归档、下载 ZIP、提交 PR、读取状态和重试，但教师发布按钮尚未接通。FE-004 完成后，教师流程固定为：

1. 在编辑器选择一份已经封存或发布的课程版本。
2. 预览系统生成的中文文件名、课程包清单和更新说明。
3. 点击“提交审核”，无需填写仓库、分支、路径或 token。
4. 刷新页面后继续查看任务状态；成功时获得审核链接。
5. 只有管理员在二次确认后才能使用直接提交。

普通教师不需要安装 Git、GitHub CLI，也不需要理解 branch、commit、remote 等术语。当前在 `/admin/content` 下载文件仍只是本地导出，不代表已经发布到历史库。

## 4. 归档目录

每个归档使用不可覆盖的内容寻址目录：

```text
courses/<course_id>/releases/<release_id>/<archive_id>/
├── 课程归档清单.json
├── 课程发布清单.json
└── lessons/<lesson_id>/
    ├── <课程标题>.json
    ├── <课程标题>-运行包.json
    ├── <课程标题>-格式层.json
    ├── <课程标题>-教师稿.md
    ├── <课程标题>-预览.html
    └── scenarios/<scenario_id>-vNNN.json
```

同一目录进入 `main` 后不得原位修改。课程内容、渲染器或任一文件字节变化时，系统必须生成新的归档身份。

## 5. 自动校验

内容库的 `Validate Chronovita content` 工作流在 push、Pull Request 和手工触发时运行：

- 复核仓库策略文件及 vendored `course-archive/v1` Schema 哈希；
- 验证归档清单 Schema、归档 checksum、清单 checksum 与派生目录；
- 拒绝父级逃逸、非 NFKC、Windows 保留名、大小写或 Unicode 碰撞；
- 逐文件核对字节数、SHA-256、UTF-8 和 JSON 可解析性；
- 拒绝清单未登记文件、符号链接、超大文件或超大归档；
- 运行正常归档、字节篡改、游离文件和凭据字段四类单元测试。

维护者可在内容库根目录运行：

```powershell
python -m pip install -r .chronovita/validation-requirements.txt
python -m unittest discover -s tests -v
python scripts/validate_content_archive.py --repository .
```

## 6. 凭据策略

生产优先使用仅安装到内容历史库的 GitHub App；过渡期可使用最小权限 fine-grained token。无论采用哪种方式：

- 凭据只能由后端环境或秘密管理系统提供；
- 浏览器请求只发送 `binding_id` 和精确归档身份；
- 仓库、课程包、教师下载包、日志和审计正文不得包含凭据；
- installation token 按需生成和刷新，不写入数据库；
- GitHub App 尚未注册或安装，不能把“仓库已创建”描述成“生产认证已完成”。

V0.9.30 配置项：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CHRONO_CONTENT_HISTORY_TARGET_PATH` | `infra/content-history-target.json` | 只含公开目标元数据，不含凭据 |
| `CHRONO_GITHUB_PUBLICATION_ENABLED` | `false` | 未完成配置时保持关闭，不影响本地编辑和 ZIP 下载 |
| `CHRONO_GITHUB_PUBLICATION_TOKEN` | 空 | 仅由服务端环境注入的细粒度 token，Settings 中使用 `SecretStr` |
| `CHRONO_GITHUB_API_BASE_URL` | `https://api.github.com` | 启用后必须是可信非本地 HTTPS 地址 |
| `CHRONO_GITHUB_TIMEOUT_SECONDS` | `20` | 单次 GitHub 请求上限 |
| `CHRONO_GITHUB_PUBLICATION_STALE_SECONDS` | `600` | 后续状态机判断中断任务可恢复的时间窗 |

checked-in [目标配置](../infra/content-history-target.json) 中的 `runtime_publication_enabled=true` 只表示后端适配器已通过验收；环境变量默认仍为 `false`。启用前应为后端进程注入仅授权该私有内容库的 token，并重启 API。教师浏览器、课程 ZIP 和一键分发包都不得获得该 token。

V0.9.30 的真实验收记录为 [内容 PR #2](https://github.com/falling-feather/Chronovita-Course-Content/pull/2)、源 Commit `57dfb20`、合并提交 `8c4b203`、[PR 校验 30147300184](https://github.com/falling-feather/Chronovita-Course-Content/actions/runs/30147300184) 和 [main 校验 30147312831](https://github.com/falling-feather/Chronovita-Course-Content/actions/runs/30147312831)。首条归档是大禹技术夹具，用于证明完整链路，不代表教师正式内容审校结论。

## 7. 维护与故障恢复

- 内容 PR 校验失败时先修复生成器或源内容，再生成新归档；不要手改清单哈希。
- Git Commit 已创建而 PR 创建超时时，后端应保留 Commit SHA 并协调恢复，不能重复造包。
- 基准分支推进产生冲突时重新读取基准 Tree；禁止 force push 覆盖历史。
- 删除或移动既有归档必须经过单独的数据治理决策，普通发布流程只新增。
- 仓库改名或转移所有者后，必须通过数字仓库 ID 复核绑定并更新文档，不能静默跟随名称。
