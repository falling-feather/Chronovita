## 1. 一句话定位

Chronovita 是一个面向中小学历史学习的 AI 历史学科学习平台。它把传统历史课中的「看材料、背结论」重构为：

```text
看见历史图景 -> 进入历史抉择 -> 追问历史解释 -> 生成个人知识谱系
```

对外展示时可以压缩成：

```text
Chronovita 把历史事件转化为可观察、可干预、可反馈、可复盘的历史局势。
```

## 2. 项目要解决的问题

- 知识点散：人物、制度、地理、事件、因果关系被拆成孤立考点。
- 时空感弱：学生知道事件结论，却不理解时代、地区和结构压力。
- 行动体验缺失：学生能背「大禹治水」「商鞅变法」「贞观之治」，但难体会历史选择的代价。
- 追问不足：课堂时间有限，普通搜索又缺少适龄、可靠、与课程相关的解释。
- 复盘不足：学习后只剩笔记或作业，很少沉淀成可修改、可分享、可回看推演路径的知识资产。

## 3. 四层学习闭环

| 层 | 学习动作 | 解决的问题 | 平台表达 |
| --- | --- | --- | --- |
| 看 | 建立图景 | 我在什么时间、空间、制度和人物关系中？ | 历史地图、课程正文、主题视频、关键词卡 |
| 练 | 行动推演 | 如果我是历史行动者，选择为什么困难？ | saga 动态叙事、sandbox 参数沙盘、失败结局复盘 |
| 问 | 对话澄清 | 我为什么不理解？不同人物如何解释？ | 历史人物同伴、历史专家双模态智能体 |
| 创 | 知识建构 | 我如何把所学组织成自己的结构？ | 智能笔记本、知识画板、节点关系、分享与复盘 |

学生侧不必直白展示「看练问创」，可转译为：

```text
踏勘遗址 -> 进入抉择 -> 召见人物 -> 整理卷宗
```

## 4. 核心创意：历史局势关卡化学习

Chronovita 的创新点不是「AI 会讲历史」，而是：

```text
历史局势关卡化学习
```

即把教材中的历史事件从静态文本升级为**史实约束的状态驱动推演系统**。学生在同一教材边界内做决策、看到局势变化、与历史人物或专家对话，并最终生成可复盘的知识结构。

### 4.1 历史抉择局

一局重点课时的基本结构：

```text
学生身份：历史行动者
当前局势：地图 + 人物 + 资源 + 危机
学生行动：选择策略 / 输入方案 / 说服人物 / 调配资源
系统反馈：局势变化 / 人物态度变化 / 状态变量变化 / 新事件触发
最终复盘：为什么这样会成功或失败，它对应什么历史逻辑
```

### 4.2 史实约束的历史局势引擎

| 架构层 | 学生体验 | 系统能力 | 创新点 |
| --- | --- | --- | --- |
| 局势地图 | 水患、路线、军队、势力、城邑随选择变化 | 时空坐标、状态可视化、局势演化 | 地图不是导航，而是棋盘 |
| 角色议事厅 | 历史人物、群体代表、专家提出冲突意见 | 多智能体观点、身份立场、时代约束 | 智能体不是陪聊，而是决策阻力与信息来源 |
| 因果沙盘 | 选择改变民心、粮食、军力、信任等变量 | 状态机、事件卡、LLM 叙事反馈 | 不是固定剧情树，而是可计算的历史因果推演 |
| 史官卷宗 | 结局后生成复盘、关键转折和知识图谱节点 | 过程摘要、历史解释、创作沉淀 | 创作不是课后作业，而是通关后的历史解释成果 |

技术表达：

```text
LLM 不直接决定历史真值，只负责生成可理解叙事层；
事实真值由课程 facts、状态机、RAG 与教师审校共同约束。
```

## 5. 一局历史关卡流程

| 阶段 | 体验 | 关键设计 |
| --- | --- | --- |
| 入局 | 历史任务书 | 身份、危机、目标、失败风险 |
| 看局势 | 动态地图 | 水患、路线、城邑、势力、资源 |
| 听议事 | 多角色发言 | 百姓、官员、工匠、君主、专家给出冲突意见 |
| 做抉择 | 固定选项 + 自由输入 | 固定选项保教学边界，自由输入体现 AI |
| 局势反馈 | 状态条和叙事变化 | 地图、指标、人物态度同时变化 |
| 史官复盘 | 生成卷宗 | 关键选择、状态轨迹、历史解释、知识图谱 |

三类可复用关卡模板：

| 类型 | 适合课程 | 常用变量 |
| --- | --- | --- |
| 危机治理型 | 大禹治水、秦末危机、安史之乱、明末危机、鸦片战争 | 民心、财政、军力、灾害、中央控制、外部压力 |
| 制度改革型 | 商鞅变法、孝文帝改革、王安石变法、洋务运动、改革开放 | 国力、民生、旧势力支持、改革信用、财政、风险 |
| 人物议政型 | 周公分封、汉武帝大一统、贞观之治、宋辽关系 | 君臣信任、制度稳定、边疆压力、百姓负担、声望 |

## 10. 后端开发推进计划

本节是当前后端任务、认领关系与验收标准的唯一权威原件。实现路径和现有接口以 [01-开发者文档](01-开发者文档.md) 为准；教师内容生产安排见 [06-内容编辑建设清单](06-内容编辑建设清单.md)。

### 10.1 本轮范围

本轮后端建设聚焦“每一次写入有真实身份、每一份学生资产有明确所有者、每一次发布可审计、每一次上线可重复验证”，不介入教师团队正在推进的正式课程内容。

| 纳入本轮 | 暂不纳入本轮 |
| --- | --- |
| 账号、会话、角色权限和操作审计 | 正式课文、人物、关键词和资料撰写 |
| 学习进度、游戏会话、卷宗和画板的真实用户隔离 | 完整班级、作业、成绩和学情大盘 |
| 数据库 schema 版本、迁移、备份恢复和 Postgres 兼容边界 | Redis、向量库和完整 RAG |
| 生产配置检查、结构化日志、健康检查和基础限流 | 面向多学校的完整租户与计费系统 |
| CI 发布门禁、权限反例、并发和重启异常矩阵 | 视觉重绘和沉浸叙事内容制作 |

V0.8.x 的运行链继续作为回归基线；V0.9.x 不以接口数量验收，而以上述身份、所有权、迁移和发布门禁能否在自动化中失败关闭为准。

### 10.2 目标运行链路

```text
教师创建 CoursePackage
  -> 系统校验 facts、source_refs、人物边界和关卡字段
  -> 审校与发布
  -> 学生进入课程并启动 ScenarioTemplate
  -> GameSession 保存行动、状态、人物态度和事件
  -> 规则引擎计算结果，LLM 生成受约束叙事
  -> 生成 Dossier 史官卷宗
  -> 学生继续整理知识谱系，教师查看过程记录
```

规则引擎必须拥有状态变化、事件触发和结局裁定权；LLM 不得直接决定史实真值和最终数值。

### 10.3 V1 数据对象

| 对象 | 最低职责 | 关键字段方向 |
| --- | --- | --- |
| `CoursePackage` | 承载一节可发布课程 | 课文、人物引用、关键词引用、地图点、facts、source_refs、教学目标 |
| `ScenarioTemplate` | 描述一局可执行历史关卡 | 学生身份、目标、变量、NPC、事件、行动规则、结局规则、卷宗模板 |
| `GameSession` | 表示学生的一次完整游玩 | 用户、课程、关卡、当前回合、当前状态、开始与结束时间 |
| `Turn` | 记录一次学生行动与系统反馈 | 原始输入、归类行动、规则结果、叙事、状态前后快照 |
| `NpcState` | 记录人物在局内的立场变化 | 人物 ID、态度、信任、已知信息、发言依据 |
| `Dossier` | 形成可复盘学习成果 | 关键选择、状态轨迹、主要代价、史实解释、知识图谱节点 |

V1 冻结规则：

- `CoursePackageV1` 表示一节课时，不表示包含多课时的整门课程；现有学生端 `Course/Lesson` 继续作为读取投影。
- `schema_version`、课程内容版本、关卡版本、会话 revision 和后续发布版本分别管理，不互相替代。
- 课程包与关卡的 `status` 只保留 `draft|sealed` 制品状态；校验、待审、退回、通过、发布和回滚由 `BE-001` 的独立发布记录与 manifest 管理。
- 课程、课时、关卡、人物、关键词、facts、资料、变量、事件和结局使用 2-64 位 ASCII 稳定 ID，引用必须通过跨对象校验。
- 旧 `LessonContentPackage`、saga 与 sandbox 文件和接口不原地重写。课程包通过 adapter 复制为 V1；旧格式没有逐条资料关系时不得自行推测来源绑定。
- `GameSessionV1` 固定课程包与关卡的版本及 checksum，完整回合快照必须连续可重放；published 启动来源的 release 身份保存在会话 envelope 中约束幂等，不进入规则状态；LLM 叙事元数据与规则状态分开保存，不能越权修改数值。
- `DossierV1` 必须引用真实回合、首尾状态、facts、资料和知识图谱边；final 卷宗与 sealed 制品均使用可复算 SHA-256 检查完整性。

#### 10.7.3 生产收口后的创新深化

生产基线完成后，后端创新不以增加普通课程页面为目标，而沿三条能力线推进：

1. **可执行历史模型**：把地点、路线、资源、人物立场、知识边界、事件队列和行动成本纳入统一 `Actor / State / Event / Constraint / Evidence` 合同；教师关卡在发布前自动检查不可达结局、死循环、无依据状态变化和数值失衡。
2. **证据约束的 AI 协作**：建设逐条 claim/source 关系、可引用 RAG、受控多人物议事和模型评测；规则引擎继续拥有状态与结局裁定权，LLM 只负责行动理解和受证据约束的表达。
3. **教学研究闭环**：支持路径对比、因果轨迹、误解诊断、核心素养量表、教师摘要和匿名研究数据导出，使仿真过程成为可复盘、可评价、可研究的学习证据。

#### 10.8.3 阶段完成条件

1. 管理员能选择一份精确 sealed/published 课程版本并预览归档包清单、自动文件名与 checksum。

#### 10.9.3 版本分配与发布门槛

1. 上述补丁版本由用户授权的核心开发组按顺序分配；若同一任务需要修复提交，则从下一个未占用补丁版本继续，仍使用原任务编号并在本节追加关联版本。
2. 任何 V0.10 规划项只有在代码、自动化和可观察运行结果完成后才能标记“已完成”；历史文档只记录已经发生的提交。
3. 双课必须先形成可审校初稿，再由不同作者/审校账号完成校验、送审、批准、封存和发布，最终由用户决定是否通过内容验收。
4. 最终 prerelease 只在 `class -> main` 与 V0.10 功能 PR 全部通过、`student-classroom-e2e` 稳定成为必需检查、Windows 包与全部 checksum 一致后创建。

## 11. 北极星与评价

北极星指标：**一节课内学生主动产出的有效次数**。

教学评价维度：

| 维度 | 可观察信号 |
| --- | --- |
| 时空观念 | 能在地图和时间轴上定位事件 |
| 史料实证 | 能区分传说、史料、解释和推测 |
| 历史解释 | 能说明因果关系和多因素作用 |
| 唯物史观 | 能理解制度、生产、地理、阶层、战争等因素的相互作用 |
| 家国情怀 | 能在具体历史过程中理解文明连续性、多民族交融与现代转型 |
| 创造表达 | 能形成自己的知识谱系和复盘总结 |

## 12. 风险与边界

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| LLM 编造史料 | 教学事故 | facts 约束、RAG 引证、教师审校、错误反馈 |
| 角色扮演越界 | 学生误解人物和时代 | 同窗时代边界、专家纠偏、回答长度限制 |
| 剧情自由度过高 | 偏离课程目标 | 收束条件、状态变量、结局触发器 |
| 内容生产跟不上 | 课程空心化 | P0 优先、模板化生产、管理员内容编辑器、后续教师 CMS |
| 申报叙事过度 | 文档误导开发 | 所有文档标注能力状态 |
